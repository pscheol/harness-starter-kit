1개요

1.1 목적과 범위

요구사항 접수에서 운영 기록까지를 한 리포 안의 문서와 사람 승인, scripts/verify.sh 판정으로 잇는다. 같은 흐름이 Claude Code · Codex · Cursor · Kiro 어느 하네스에서 열어도 같은 원본과 같은 게이트를 쓴다.

넣는 것넣지 않는 것
킷 저장소(템플릿 층 · 플러그인 스킬 · CLI · 어댑터 · 모듈), 회사 팩 형식제품 코드, 외부 도구(AI-DLC · Entire) 내부 동작
설치된 리포의 원본 · 하네스 배치 · 검증 · 훅 · 문서 · 상태운영 배포 명령 자체, 환경 만들기, 모니터링 도구 연결(14 §1)
로컬 관리 페이지, worktree, 세션 등록과 작업 요청화면 디자인(screens), 네트워크에 공개하는 서버, 화면에서 셸 명령 실행
리포 밖 시스템과의 경계(GitLab · CI · Jira · Notion · 분석기)사용자 전역 설정 · 자격 증명 쓰기

1.3 원칙 10개

README §1의 원칙을 시스템의 어느 자리가 지키는지로 다시 적는다. 원칙 10(토큰)이 다른 원칙과 부딪히면 원칙 10을 먼저 지킨다.

번호원칙지키는 자리
10최우선킷을 도입해도 토큰 소모량이 늘지 않는다. CLI · 관리 페이지 · 훅 · 스크립트는 모델을 부르지 않고, 모델 작업은 사람이 시킨 작업 안에서만 돈다세션에 덧붙이는 양의 상한과 릴리스 전후 측정(9.1), 모델을 부를 수 있는 구성요소 표(9.2)
1원본은 .agents/ 한 곳하네스 폴더는 mirror · render · merge 결과(실제 파일, 링크·포인터 없음)만 두고 lock에 적는다. doctor와 fast 검증이 어긋남을 잡는다(4.2)
2완료 판정은 scripts/verify.sh 한 곳훅 · git 훅 · CI · CLI는 부르기만 한다. MR 파이프라인은 base 브랜치의 판으로 판정한다(09 VQ-R11)
3사람이 고친 파일과 다른 도구의 파일은 덮지 않는다update 3방향 비교와 .new, 주인 user · external:*(4.3)
4외부 도구 원본 파일은 고치지 않는다외부 파일은 op: none으로 기록만 하고, 킷 명령 전후 sha256이 같아야 한다(10 MD-R7)
5AI-DLC · Entire 없이도 전 흐름이 돈다두 모듈은 기본 꺼짐. 릴리스마다 킷만 구성으로 운영 기록까지 도는 e2e 시험(11 §3.4)
6AI-DLC 원칙 다섯 가지는 모듈과 상관없이 지킨다/hx-intent, Unit = 이슈 = 브랜치, 게이트 하한, approvals.md(13: 142항목 중 충족 117)
7프로젝트 밖에는 쓰지 않는다사용자 폴더는 스킬 목록과, 사람이 켰을 때의 사용량 보고에서만 읽는다(07, 12 §3.9)
8사람이 연 세션의 모델 · effort는 바꾸지 않는다등급은 위임 역할에만. implement · design · review는 inherit로 잠근다(12 §3.2 · §3.10)
9화면 없이도 모든 기능이 돈다서버와 CLI가 packages/cli/src/core/를 같이 부르고 --json 출력이 같다(06 §3.15)

4계층과 배치

설치할 파일은 층을 차례로 쌓아 정하고(resolve), 그 결과가 .agents/ 원본이 된다. 하네스 폴더는 그 원본에서 다시 만든다. 두 단계 모두 lock에 남는다.

4.1 층과 우선순위

순서는 common → domains → stacks → arch → optional(모듈, 메타 순서) → packs(배열 순서) → project이고, 같은 경로는 뒤가 이긴다. 팩 둘이 같은 경로나 같은 훅 id를 내면 충돌이고, 그때는 아무것도 쓰지 않고 exit 4로 끝낸다(04 §3.5).

층lock owner원본 자리커밋update 때

2 회사 팩pack:<이름>팩 리포 · 패키지 → .agents/ 등예(배치 결과)update --packs일 때만 같은 규칙
3 프로젝트user.agents/ 안 팀 파일예건드리지 않는다

하한은 킷 코드 상수(packages/cli/src/core/floor.ts, sdd_layout.py의 GATE_FLOOR)라 설정으로 바꾸지 못한다: 게이트 requirements · design · mr · done, floor 훅 harness-protect-sources · harness-block-full-verify · harness-verify-gate, 보호 경로 deny. 개인 층이 이 값을 약하게 하는 키(flow.gates · approvers · verify · risk · codebase)는 무시하고 doctor가 경고한다(README §5).
