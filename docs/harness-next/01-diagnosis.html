무엇이 맞았고 무엇이 낡았나

이 장은 판단 근거만 모은다. 지금 킷의 구조, 2026년에 바깥에서 바뀐 표준과 도구, 킷을 실제로 쓴 두 프로젝트에서 생긴 일을 차례로 보고 마지막 절에서 맞았던 것·낡은 것·빈 것으로 나눈다.

AI-DLC v2

개념과 단계는 AI-DLC 핸드북 02장에 있다. 설치 관점에서 볼 것은 셋이다.

  • v2는 엔진 설치형이다. 네이티브 바이너리 aidlc를 설치하고 프로젝트에서 aidlc config --harness claude|kiro|codex|cursor|opencode|copilot, aidlc doctor를 돌린다. update·uninstall이 있다.
  • 자기 파일의 소유 기준선을 갖고, 고친 파일은 충돌로 보고 --force를 요구한다. 킷과 같은 폴더(.claude/)에 쓰면 두 설치기가 서로의 파일을 모른다.
  • knots에서는 Claude 하네스로만 설치됐다. 같은 리포를 Codex·Kiro로 열면 AI-DLC 흐름이 없다(아래).

Entire

전 GitHub CEO Thomas Dohmke가 2026-02에 세운 회사의 도구다. CLI(entireio/cli)는 MIT, Go, 최신 0.13.4(2026-11-13)이다. 방법론이 아니고, 에이전트 세션 기록을 커밋에 묶어 남기는 기록 도구다.

설치계정 없이
brew install --cask entireio/tap/entire → 저장소에서 entire enable. 에이전트 훅과 git 훅(prepare-commit-msg · post-commit · pre-push)을 깐다. Claude Code에는 .claude/settings.json에 훅 7개를 넣는다.
하네스내장 · 외부
내장: Claude Code, Codex, Cursor(재개 없음), Copilot CLI, OpenCode, Antigravity, Factory, Pi. Kiro는 외부 에이전트(entire-agent-kiro)로만 붙는다. Gemini CLI 지원은 0.11.3에서 빠졌다.
기록무엇을
프롬프트와 응답, 도구 호출, 바뀐 파일, 모델, 토큰, 줄 단위 AI 귀속. 서브에이전트 기록은 부모 체크포인트 안에 들어간다.
저장어디에
커밋할 때 체크포인트가 생기고 커밋 메시지에 Entire-Checkpoint 트레일러가 붙는다. 기록은 refs/entire/checkpoints/… ref에 두고 작업 브랜치에는 커밋을 더하지 않는다. pre-push 때 함께 올라간다.
주의공개 저장소
문서 원문: "If that repository is public, anyone can read them." 대화 원문이 원격에 올라간다. 별도 원격(--checkpoint-remote)이나 올리지 않기(--skip-push-sessions)를 고를 수 있다.
동시 세션알려진 한계
같은 폴더에서 여러 세션이 돌다 하나가 커밋하면 모든 세션이 그 체크포인트에 묶인다. 문서의 해법은 세션마다 worktree를 나누는 것이다.
GitLab부분 지원
체크포인트는 일반 git ref라 gitlab.com 원격에도 코드와 함께 올라간다. 기록을 별도 리포에 두는 --checkpoint-remote gitlab:<그룹>/<리포>는 v0.11.0부터 gitlab.com만 된다(자체 설치형 GitLab은 미지원, 이슈 #2033). entire.io 웹 보기·Trails·미러·이슈 연결은 GitHub 전용이다. GitLab의 squash 병합은 커밋 본문을 버려 Entire-Checkpoint 트레일러가 사라지므로 squash 커밋 메시지 템플릿에 %{all_commits}를 넣어야 한다.
GUI 클라이언트Sourcetree 등
훅이 entire를 절대 경로로 부르게 바뀌어(v0.4.9) 셸 설정을 읽지 않는 GUI 클라이언트에서도 돈다. Xcode에서 entire: command not found로 실패하던 문제가 이것으로 해결됐다. Sourcetree를 따로 다룬 문서·이슈는 없고, 체크포인트를 보여 주는 화면도 없다.
변화 속도0.x
0.10.0에서 저장 방식이 브랜치에서 ref로 바뀌고 rewind가 삭제됐다. 0.11.5에서 섀도 브랜치가 없어졌다. 버전을 고정해서 써야 한다.

이 저장소의 Entire와 AI-DLC 함께 쓰기는 둘을 층으로 나눈다. AI-DLC는 "무엇을 왜, 누가 승인하나", Entire는 "변경을 어디에 남기고 병합해도 되나"를 맡는다. 그 문서는 Kiro를 "지원 목록에 없음"으로 적었는데, 외부 에이전트로는 붙는다.

채널톡 사례

「백엔드 개발자 한 명이 팀처럼 일하는 법」(2026-11-19). 별도 SDD 절차 없이 이슈 단위 흐름 하나로 일한다.

  • 흐름: 이슈 → 코드 읽기와 계획(사람이 확정) → 구현 → 빌드·테스트 → 여러 관점 리뷰 → PR → CI 대응 → 회고. 처음에는 단계마다 승인했고, 지금은 요구사항이 모호할 때와 머지 직전에만 멈춘다.
  • 세션: 이슈마다 워커 세션, 프로젝트마다 PM 세션(상태 파일만 보고 병합·리뷰 요청·보류를 판정), 그 위에 오케스트레이터. 세션마다 git worktree를 쓴다.
  • 리뷰: 스펙·백엔드·보안·도메인·설계 관점 에이전트를 동시에 돌리고, 코드는 Claude가 쓰고 리뷰는 Codex가 한다.
  • 머지 뒤: 검증 환경 자동 배포 → E2E. 같은 시나리오가 두 번 실패하면 멈추고 사람에게 알린다. 운영 배포는 사람이 누른다.
  • 한계: PM·오케스트레이터를 들인 뒤 사람 개입 횟수가 두 배 넘게 늘었다고 스스로 적었다.

브랜치와 worktree

도구사실
Claude Codeclaude -w <name>은 .claude/worktrees/<name>/에 worktree-<name> 브랜치를 만든다. 서브에이전트에 isolation: worktree를 주면 자기 worktree에서 돈다. WorktreeCreate·WorktreeRemove 훅으로 생성 방식을 바꿀 수 있다
Codex 앱$CODEX_HOME/worktrees에 detached worktree를 만든다. 브랜치 기본 접두사는 codex/
Copilot 클라우드copilot/ 브랜치 하나에만 push하고, 시작하자마자 draft PR을 연다
GitHub스택 PR(gh stack)이 2026-07-30 공개 프리뷰. merge queue는 merge_group 이벤트에 required check가 걸려야 한다. 둘 다 GitHub 전용이다
DORA 2025AI를 기존 관행의 "amplifier"로 보고, 강한 버전 관리 관행과 작은 배치를 AI 효과를 키우는 역량으로 꼽는다

벤더 기본값은 모두 "기준 브랜치에서 짧게 딴 브랜치, 세션마다 분리된 작업 폴더"다. 킷은 같은 체크아웃에서 파일 점유로 동시 작업을 조율하고 worktree 규칙이 없다.

판정

맞았던 것 유지

  • 원본을 .agents/ 한 곳에 둔 것. 표준 스킬 위치와 같아졌다.
  • 검증 게이트 한 곳 + 여러 트리거. 하네스가 바뀌어도 완료 판정 기준은 그대로다.
  • 고친 파일을 덮지 않는 업데이트. 조사한 설치기 중 이보다 보수적인 것은 없다.
  • 에이전트·모듈 선택 설치. aidlc도 대상 하네스를 골라 깐다.

낡은 것 바꿈

  • 손으로 쓴 포인터·요약 62개와 역할 파일 16개. 원본과 요약이 갈라질 수 있고, 스킬 하나를 더하면 다섯 곳을 고친다.
  • 에이전트 세션 안에서만 시작되는 설치. CI·스크립트·새 장비에서 바로 돌릴 진입점이 없다.
  • .claude/commands/. Claude Code가 예전 형식으로 분류했다.
  • 설정 파일 통째 복사. 다른 도구의 훅이 있는 리포에서는 덮거나 배포에서 빼야 한다.

빈 것 새로

  • 점검·복구·제거(doctor · repair · uninstall)와 외부 도구 파일 인식.
  • 다층 단위(units) 배포. knots가 sync.py로 따로 만들었다.
  • 세션별 worktree 규칙과 정리 도구, base 브랜치 설정, GitLab·GoCD 템플릿.
  • AI-DLC 없이 킷만으로 하는 Intent·Unit 분해, AI-DLC·Entire를 선택 모듈로 켜고 끄는 방법, Unit을 SDD 이슈로 잇는 자리, 운영 피드백(핸드북 05장).
  • 하네스별 역할 분리, 자체 리뷰 에이전트, 보안·품질 스캔, 승인의 기계 강제.
  • 진행 상황과 문서를 한 곳에서 보는 화면, 흩어진 스킬을 단계별로 찾는 목록.
  • 상시 컨텍스트 크기 기준, 기록 파일 보존 기한.
