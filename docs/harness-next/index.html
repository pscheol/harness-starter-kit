킷만으로 끝까지, 켜면 AI-DLC와 Entire까지

harness-starter-kit v2는 요구사항 하나를 설계 → 구현 → 검증 → 반영 → 운영까지 킷만으로 끌고 간다. AI-DLC와 Entire는 기본 꺼짐인 선택 모듈로, 켜면 설계 단계와 대화 기록을 맡는다. 하네스마다 역할을 나누고, 진행 상황·문서·이 컴퓨터의 스킬은 대시보드 한 곳에서 본다. 이 문서 묶음은 그 진단과 방향, 단계 계획, 쓰는 법을 적는다.

상태 제안. 아직 구현하지 않았다기준일 2026-11-23대상 버전 v1.0.8 → v2.6

한 장 요약

흐름바깥과 안
요구사항 → 설계(킷 /hx-intent 또는 AI-DLC, 기획물) → 구현(Unit마다 SDD) → 검증(자체 리뷰·보안·품질) → 승인·병합 → 반영(문서) → 운영 기록 → 다음 요구사항.
역할하네스마다
설계·구현 Claude Code, 리뷰 Codex, 반영·운영 기록 Kiro, 진행 판정은 사람이 대시보드에서. 팀이 바꿀 수 있는 기본값이다.
외부 도구선택 모듈
AI-DLC·Entire는 기본 꺼짐이다. 켜면 각자의 설치기로 원본 그대로 깔고 그때그때 올린다. 원본 파일은 고치지 않고 우리 개선은 킷 층에 둔다. 꺼도 빠지는 단계가 없고, 릴리스마다 두 구성(킷만 / 모두 켬)을 시험한다. 리뷰 에이전트는 자체로 만든다.
동시 작업worktree
같은 리포에서 동시에 쓰는 세션이 둘 이상일 때 둘째부터 리포 옆 <리포>.worktrees/에 만든다. 리포당 3개까지, 끝나면 바로 지운다. 문서만 쓰는 세션은 문서 폴더만 받는다.
검증바꾼 기능만
작업마다 바꾼 기능만(changed), MR 전에 영향 모듈까지(affected) 검증한다. 전체 검증은 CI에서만 돌고 에이전트 세션에서는 막는다. 지금 1~2시간 걸리는 원인이 에이전트의 전체 검증이다.
SDD이슈 단위
이슈 하나 = issues/<키>-<이름>/ 폴더 하나 = 브랜치·worktree·MR 하나. 키는 Jira 키 그대로, Jira가 없으면 킷이 같은 모양(KNOTS-17)으로 만든다.
관리 페이지한 화면
npx harness-kit dashboard. 처리할 일, 진행, 문서, 검증, 작업 공간, 운영, 스킬, 하네스 상태를 보고, 문서를 고쳐 저장하고 승인하고, 켜 둔 Claude 세션에 작업을 요청한다.
원칙·확장05장
AI-DLC 원칙 다섯 가지를 킷이 지킨다(도구를 켜든 끄든). 회사 팩·프로젝트·개인 층으로 각자 고쳐 쓴다. Jira도 같은 단위와 승인 게이트에 맞춘다.
스킬 목록내 장비
이 컴퓨터의 스킬(Claude 사용자 221 · ~/.agents 156 · Kiro 143 · 플러그인)을 하네스·단계별로 보여 주고, 킷 명령이 깔린 스킬을 찾아 쓴다.
기반설치와 배치
npx CLI 하나가 설치·업데이트·점검·제거를 맡는다. 손으로 쓰던 하네스 포인터 78개를 복사·생성으로 바꾸고(링크·포인터 없음), 다른 도구의 파일과 훅은 덮지 않는다.
순서P17 → P24
CLI 엔진 → 배치 전환(v2.0) → worktree · 대시보드 · 킷 설계 단계 · 검증 확장 → 선택 모듈(AI-DLC·Entire) · 반영·운영·역수입(v2.6).

결정 상태

번호정할 것상태
D1로드맵 불변식(외부 이름 금지)정함: 선택 모듈과 연동 문서에서만 허용
D2AI-DLC와의 관계정함: 선택 모듈로 공존. 기본은 킷 설계 단계, 켜면 AI-DLC
D5동시 작업 방식정함: 둘째 쓰는 세션부터 리포 옆 worktree
D9이슈 키정함: Jira 키 그대로, 없으면 킷이 <프로젝트키>-<번호>로 만든다
D10전체 검증 위치정함: CI만. 에이전트 세션은 changed·affected
D3배포 경로추천: GitHub 직접(npx github:)으로 시작 → npm
D4base 브랜치 기본값추천: 설정값, 기본 develop
D6Entire 기록 push추천: 비공개 원격이면 같은 원격, 공개면 올리지 않음
D7역할 배정 기본값추천: 설계·구현 Claude, 리뷰 Codex, 반영 Kiro
D8정적 분석 도구정함: 오픈소스 조합(Semgrep/Opengrep · gitleaks · OSV · jscpd · lizard + 스택별), SonarQube 쓰지 않음

초록은 정한 것, 빨강은 정할 것. 각 선택지의 비용은 02장 결정 목록에 있다.

읽는 순서

  1. 01 진단지금 킷이 하는 일, 바깥에서 바뀐 것(표준 · 설치기 4종 · AI-DLC · Entire · 채널톡 · 브랜치), knots·hdr에서 본 것.
  2. 02 방향흐름, 킷만 · 모듈을 켰을 때, 하네스별 역할, AI-DLC·Entire 선택 모듈, 기획물, 검증, worktree, 대시보드, 스킬 목록, 설치 엔진, 결정 목록.
  3. 03 계획P17~P24의 산출물·완료 기준·착수 전 확인, 기존 프로젝트 이전, 위험, 릴리스 규칙.
  4. 04 활용요구사항 하나를 운영까지, 세션 배치, 대시보드·내 스킬 쓰는 법, 팀 도입 순서. 지금 되는 것과 v2 뒤에 되는 것을 나눴다.
  5. 05 원칙·확장AI-DLC 원칙 대응, 채널톡 사례에서 가져올 것과 버릴 것, 사람 역할, 폴더와 주인, 이슈 키, Jira 대응, 하네스를 고쳐 쓰는 네 층.
