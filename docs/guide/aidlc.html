AI-DLC 모듈

AI-DLC(awslabs 의 aidlc-workflows)는 요구사항을 대화로 정리해 Intent · Unit 으로 나누는 외부 설계 도구다. aidlc 모듈을 켜면 설계 단계를 AI-DLC 가 맡고, knots-sync 는 그 산출물을 자기 Intent · Unit 형식으로 가져와 이슈 단계부터 이어 간다. 기본은 꺼져 있다.

무엇이 바뀌나

모듈 없음 — 킷 설계 단계(flow.design = "kit")

  • /kns-intent 가 intent.md · questions.md · units.json 을 쓴다.
  • 질문은 관리 페이지 · knots-sync answer 로 답한다.
  • intent 승인은 관리 페이지 · knots-sync approve · Jira.
  • 세션에 더 실리는 것 없음(킷 몫 약 10KB).

모듈 켬 — AI-DLC 설계 단계(flow.design = "aidlc")

  • AI-DLC 가 터미널 대화로 질문 · 스토리 · Unit 분해를 받는다. 산출물은 aidlc/spaces/<space>/intents/<YYMMDD>-<label>/.
  • knots-sync sync aidlc 가 Intent 폴더에 intent.json(AI-DLC 산출물 링크)과 units.json 을 만든다.
  • /kns-intent 는 "설계 단계는 /aidlc 가 맡는다. 끝나면 sync aidlc"만 알린다.
  • AI-DLC 사람 입력 확인 훅이 받은 승인은 경로: aidlc 로 옮겨진다(승인자가 기록에 있을 때).
  • 세션마다 약 73KB 와 훅 17개가 더 실린다.

이후 단계 — 기획물(/kns-plans), /kns-specify --from-unit, 이슈 세 문서, 게이트 검사, 관리 페이지 — 는 두 경우 같다. 명령과 출력 형식도 같고, 입력만 intent.md 대신 intent.json 이 가리키는 AI-DLC 문서다. 구현은 늘 킷 SDD 가 맡는다. AI-DLC 쪽 구현 산출물이 생기면 doctor 가 "두 곳에서 구현하지 않는다"를 경고한다.

언제 쓰나

상황권장이유
팀이 이미 AI-DLC 로 Intent 를 만들어 왔고 그 방식(단계 · 대화 · 승인 훅)을 계속 쓰고 싶다켠다산출물을 다시 쓰지 않고 이슈 단계로 이어진다. 사람이 두 번 승인하지 않는다
AI-DLC 로 만든 Intent 가 0건이다켜지 않는다(flow.design = "kit")킷 설계 단계만으로 전 흐름이 돈다. 세션 적재량 약 73KB · 훅 17개를 아낀다(이전 안내서의 선택 B)
설계는 Kiro 에서 하고 싶은데 AI-DLC 는 Claude Code 에만 깔았다맞춘다설계 역할 하네스(roles.design.harness)와 AI-DLC 가 깔린 하네스가 다르면 doctor 가 경고한다
Codex · Cursor · Kiro 리포켜기 전에 확인AI-DLC 가 AGENTS.md(Codex 는 .agents/skills/ 도)에 쓴다. 킷 소유 파일과 겹치니 add 뒤 doctor 와 diff 로 본다

AI-DLC 방법론 자체(Intent · Unit · Bolt, 세 단계, 대화 방향 역전)는 AI-DLC 핸드북에 있다. 모듈을 켜지 않아도 이 원칙 다섯 가지는 킷 흐름이 지킨다.

켜기 — add aidlc

외부 도구 설치는 사람이 한다

킷은 외부 도구를 몰래 깔지 않는다. 도구가 없으면 add 가 exit 5 와 설치 안내를 낸다. --install-tools 는 사람 터미널에서만 공식 설치기(curl -fsSL https://github.com/awslabs/aidlc-workflows/releases/latest/download/install.sh | sh)를 부른다. 처음에는 일회용 HOME 에서 시험해 보길 권한다.

$ aidlc --version                       # 검증 범위: >=2.11 <3 (versions.aidlc)
$ knots-sync add aidlc --dry-run
$ knots-sync add aidlc                  # 범위 밖 판이면 exit 4 — 그래도 쓰려면 --allow-unverified

add aidlc 가 하는 일(module.json 의 steps.add 순서).

  1. aidlc config --harness <설계 하네스> --yes — 확인을 받고 실행한다.
  2. aidlc doctor — 결과를 함께 보인다(실패해도 계속).
  3. AI-DLC 가 만든 파일 · 훅을 lock 에 owner: external:aidlc(op: none)로 등록한다. 대상은 aidlc/**, .claude/aidlc-common/** · .claude/agents/aidlc-* · .claude/skills/aidlc*/** · .claude/hooks/** 등 하네스별 AI-DLC 경로다.
  4. 킷 몫을 깐다: hooks.d/aidlc.json 과 Stop 훅 harness-aidlc-freshness(Claude Code 에만) — AI-DLC 산출물이 units.json 보다 새로우면 "sync aidlc 하라"를 알린다.
  5. flow.design = "aidlc" 로 바꾼다.
  6. doctor 의 aidlc 점검(도구 판 · 설계 하네스 · 구현 산출물 · 신선도)을 돈다.

새로 깔 때 함께 켜려면 knots-sync init … --modules aidlc. 외부 도구 모듈은 이름을 직접 줄 때만 켜진다(--modules all 로는 켜지지 않는다). 도구 판을 올릴 때는 knots-sync update --tools — 지금 · 최신 판을 보이고 사람이 고른 것만 올린다.

가져오기 — sync aidlc

--helpknots-sync sync(aidlc 부분) 
knots-sync sync aidlc [--intent <AI-DLC Intent 폴더>] [--key <Intent 키>] [--check] [--json] — AI-DLC 산출물을 intent.json · units.json 으로 옮긴다. 같은 입력이면 쓰지 않는다. --check 는 쓰지 않고 차이가 있으면 exit 1.
  1. 입력 = AI-DLC Intent 폴더의 파일 목록과 내용 → inputSha256. 이미 같은 입력으로 가져왔으면 아무것도 쓰지 않는다(exit 0).
  2. 판별 모듈이 알려진 파일만 읽는다. 알려진 파일이나 필수 항목(Intent 제목 · Unit 목록)이 없으면 exit 2 와 빠진 항목을 낸다. 추측해서 채우지 않는다.
  3. AI-DLC Intent → intent.json, Unit → units[](sourceId 에 AI-DLC 쪽 식별자), 스토리 → stories, 의존 → dependsOn, 계약 성격 Unit → kind: contract.
  4. 다시 가져올 때: sourceId 가 같은 Unit 은 id · issue · planned 를 지킨다. 새 Unit 은 다음 U 번호, 사라진 Unit 은 planned: false.
  5. AI-DLC 승인 기록에 승인자가 있으면 승인자 · 시각 · 문구를 Intent 의 approvals.md 에 경로: aidlc · source: aidlc · 근거 파일과 함께 옮긴다. 승인자가 없으면 옮기지 않는다 — 그 게이트는 관리 페이지 · knots-sync approve · Jira 로 승인한다.

설계서 08 §3.10 의 intent.json 예시. 실제 값은 sync aidlc 가 쓴다.

CI 에서는 knots-sync sync aidlc --check 를 두면 "AI-DLC 는 바뀌었는데 가져오지 않음"을 잡는다.

AI-DLC Intent 의 승인

  • AI-DLC 가 사람 입력을 훅으로 확인한 승인은 채팅과 다르다. 그래서 킷은 그 승인을 intent 게이트 승인으로 인정한다. 사람이 두 번 승인하지 않는다.
  • AI-DLC 세션의 그 밖의 대화는 승인이 아니다. 채팅에서 "좋아"라고 한 것은 어디서든 승인이 아니다.
  • intent 게이트는 intent.json 을 대상으로 읽는다. 두 구성 e2e 가 "AI-DLC Intent 의 intent 게이트 승인"에서 버그를 찾아 고쳤다(HK-22 T6).
  • plans 이후 게이트는 킷 경로(관리 페이지 · approve · Jira)로만 생긴다.

세션 적재량 — 약 73KB

켜기 전에 숫자를 본다

두 구성 e2e(실제 도구 aidlc 2.11.4 · entire 0.13.4, 하네스 Claude Code, doctor --json 의 load)의 값이다.

구성kitexternal:aidlcexternal:entire합계
A 킷만10,189 B · 훅 13——10,189 B
B 킷 + AI-DLC + Entire10,189 B · 훅 1473,333 B · 훅 170 B · 훅 1083,522 B(추정 약 27,800 토큰)
  • AI-DLC 몫 73,333 B 의 내역: 규칙 1 · 스킬 설명 43 · 에이전트 설명 14 · 진입 파일 9.
  • 킷 쪽은 harness-aidlc-freshness Stop 훅 하나가 늘고, 새 산출물이 있을 때만 최대 512바이트를 낸다.
  • 사람 터미널의 마지막 실행(real)에서도 킷만 10,202 B · AI-DLC +73,333 B · Entire +0 B, 합계 83,535 B 로 같은 크기였다. 설치 순서(킷 → aidlc → entire, 그 반대)와 무관하다. Codex 는 두 도구를 Claude Code 에만 켜서 킷만(약 8.4KB)이다.
  • 이 숫자는 킷이 아니라 외부 도구가 더하는 양이다. 킷의 토큰 원칙에 따라 켜기 전 · 후 값을 MR 설명에 적고 사람이 받아들인다.

끄기 — remove aidlc

$ knots-sync remove aidlc --dry-run
$ knots-sync remove aidlc

킷 몫(훅 · 등록)만 빼고 flow.design = "kit" 으로 돌린다. 끝에 이렇게 알린다: "AI-DLC 가 하네스 설정에 넣은 자기 훅 · 파일은 남는다. 빼려면 사람이 aidlc uninstall 또는 그 도구의 안내를 따른다(킷은 실행하지 않는다). AI-DLC 산출물 · intent.json · units.json · SDD 이슈는 그대로 남는다." 남은 Intent 는 intent.json 을 그대로 읽어 관리 페이지에 보인다.

e2e 의 E5 · E6 판정이 이 약속을 지킨다: update · repair · uninstall 과 remove entire → remove aidlc 뒤에 외부 파일 · 훅 항목의 sha256 이 그대로였다(real: 파일 405 · 훅 27).

확인 범위

e2e(stub · real)에서 설치 순서 두 가지, intent.py check, Unit 목록 키 비교(E1), 외부 파일 불변(E5 · E6)을 확인했다. 사람 터미널 실행에서는 승인 단계(S3~S9)까지 통과했다. 팀의 실제 AI-DLC Intent 로 한 바퀴 도는 것은 각 팀이 처음 쓸 때 확인한다.
