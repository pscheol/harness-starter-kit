Entire 모듈

Entire(entireio 의 entire CLI)는 에이전트 대화를 커밋마다 체크포인트로 남긴다. entire 모듈은 그 기록을 구현 하네스 하나에만 켜고, 커밋 트레일러 · push 정책 · 비밀값 가림을 킷 규칙에 맞춘다. 기본은 꺼져 있다.

이 장에서

  1. 무엇이 남나
  2. 켜기 — add entire
  3. push 정책(결정 D6)
  4. 커밋 트레일러와 MR 플랫폼
  5. 체크포인트 보기 — checkpoints
  6. 끄기 — remove entire
  7. doctor 점검

무엇이 남나

  • 구현 세션이 커밋할 때 커밋 메시지에 Entire-Checkpoint: <id> 트레일러가 붙고, 대화 기록은 refs/entire/checkpoints/ 아래 ref 로 남는다.
  • 리뷰어는 "이 코드가 어떤 대화에서 나왔나"를 이슈 브랜치의 커밋별로 따라갈 수 있다.
  • 설정 flow.record = "entire". 규칙 파일 .agents/rules/entire-usage.md 하나가 킷 몫이다.
  • 세션에 실리는 글은 0바이트, 훅은 구현 하네스에만 10개(e2e real 실측)다.

켜기 — add entire

처음은 일회용 HOME 에서

entire enable 이 전역 git 설정에 손댄 일이 있었다. 처음 켤 때는 일회용 HOME 에서 시험하고, 실제 홈에서는 사람 터미널에서 한다. doctor 의 global-hooks-path 점검이 전역 core.hooksPath 를 본다.

$ entire --version                     # 검증 범위: >=0.13 <0.14 (0.x 라 좁게)
$ knots-sync add entire --dry-run
$ knots-sync add entire
  1. entire enable --agent <구현 하네스> --project — 확인을 받고 실행한다. 하네스 이름은 claude → claude-code, codex → codex, cursor → cursor(Kiro 는 대상이 아니다). 리뷰 하네스가 같은 하네스여도 하나만 더한다.
  2. push 정책을 정한다(아래).
  3. Entire 파일(.entire/**)과 훅을 external:entire 로 등록한다.
  4. 규칙 entire-usage.md 를 깔고 flow.record = "entire".
  5. doctor 의 entire 점검을 돈다.

도구가 없으면 exit 5 와 설치 안내(macOS brew install --cask entireio/tap/entire, Linux curl -fsSL https://entire.com/install.sh | bash). --install-tools 는 사람 터미널에서만이다.

push 정책(결정 D6)

원격 공개 여부기본 정책
private · internal(gh repo view --json visibility · glab repo view -F json)같은 원격에 체크포인트 ref 를 올린다
public올리지 않는다. 별도 비공개 원격이 있으면 entire configure --checkpoint-remote gitlab:<그룹>/<리포>(gitlab.com)를 안내한다
확인 실패(CLI 없음 · 인증 없음 · 자체 호스팅)public 으로 보고 올리지 않는다

대화 기록에는 코드 밖의 맥락이 들어가므로, 공개 저장소에는 기본으로 올리지 않는다. 비밀값 가림은 킷 비밀값 가드와 같은 목록(*_KEY · *_SECRET · *_TOKEN · *_PASSWORD 대입, AWS 키, 개인 키 블록, JWT, .env 내용)을 쓴다.

커밋 트레일러와 MR 플랫폼

  • 킷의 커밋 메시지 검사(git 훅 · 가드)는 Entire-Checkpoint: 트레일러를 지우거나 거부하지 않는다(trailer-allowed 점검).
  • GitLab 의 squash 병합 기본 메시지는 커밋 본문을 버려 트레일러가 사라진다. doctor 가 "Settings → Merge requests → Squash commit message template 을 %{title} (%{reference}) 다음 줄에 %{all_commits} 로"를 알린다(gitlab-squash-template).
  • entire.io 의 웹 보기는 GitHub 전용이다. GitLab 리포는 아래 checkpoints 명령으로 본다.
  • 같은 폴더에 살아 있는 구현 세션이 둘이면 기록이 섞인다 — doctor · 관리 페이지가 "둘째 세션은 worktree 로"를 알린다(concurrent-sessions).

체크포인트 보기 — checkpoints

--helpknots-sync checkpoints 
knots-sync checkpoints [--issue <키>] [--json] | checkpoints <체크포인트 id> [--json] — Entire 체크포인트 목록(이슈 브랜치 커밋의 Entire-Checkpoint 트레일러) · 설명(entire checkpoint explain, 10초 제한)
  • 목록: git log origin/<base>..<이슈 브랜치> 의 트레일러를 모으고, 각 id 가 refs/entire/checkpoints/ 에 있으면 local, 없으면 "원격에만 또는 없음"이다. --issue 를 빼면 지금 브랜치.
  • 설명: entire checkpoint explain <id> 를 10초 제한으로 부르고 출력을 글자 그대로(제어 문자 제거 · 상한) 보여 준다. 신뢰하지 않는 내용으로 다룬다.
  • 읽기만 한다. 체크포인트 ref 를 만들거나 push 하지 않는다. 모델도 부르지 않는다.
  • 관리 페이지 API 는 GET /api/v1/checkpoints?issue=<키> · /checkpoints/{id} 다. 이 판의 화면에는 체크포인트 전용 화면이 없다 — CLI 로 본다. 내보내기에는 id 만 넣고 설명은 넣지 않는다.
실제 출력모듈이 꺼진 리포에서 knots-sync checkpoints 
entire 모듈이 꺼져 있습니다(knots-sync add entire)

끄기 — remove entire

킷 몫(규칙 · 등록)을 빼고 flow.record = "none". 끝에 "기록을 끄려면 사람이 entire agent remove <구현 하네스> 또는 entire disable(전부 지우려면 --uninstall)을 실행한다(킷은 실행하지 않는다). .entire/ 와 체크포인트 ref 는 그대로 남는다"를 알린다.

doctor 점검

tool-version · implement-only(구현 하네스에만 켜졌나) · trailer-allowed · push-policy · global-hooks-path · gitlab-squash-template · concurrent-sessions.

살아 있는 체크포인트

e2e real 모드는 entire 0.13.4 를 실제로 설치해 켜기 · 끄기 · 외부 파일 불변을 확인했다. 하지만 체크포인트는 살아 있는 구현 세션의 훅이 만들기 때문에, "실제 세션에서 체크포인트가 생기고 checkpoints 에 보이는가"(E4)는 정해서 건너뛰었다(결정 D9). stub 모드는 가짜 트레일러로 목록 · 설명 경로만 시험했다. 팀이 처음 켤 때 한 번 확인한다.
