CLI 명령 참고

knots-sync(별칭 kns)의 명령 34개를 묶음별로 정리했다. 회색 상자 안의 글은 이 안내서를 쓰며 실제로 돌린 --help 와 출력을 손대지 않고 옮긴 것이다(CLI 2.0.0-alpha.0). 각 명령의 --help 는 사용법 한 줄을 낸다.

이 장의 knots-sync … 는 전역 설치한 CLI 다(npm i -g https://codeload.github.com/pscheol/harness-starter-kit/tar.gz/refs/tags/v2.0.0-alpha.3, → 설치 · CLI). npm 에는 아직 올리지 않았으니 npx knots-sync · npx kns 는 쓰지 않는다.

전체 도움말과 종료 코드

실제 출력knots-sync --help 
knots-sync 2.0.0-alpha.0 — 하네스 엔지니어링 스타터 킷

사용법: knots-sync <명령> [플래그]

명령:
  init       킷을 리포에 설치한다(질문 또는 플래그)
  plan       설치할 작업 목록만 출력한다(쓰지 않는다)
  add        하네스 · 모듈을 켜고 그 몫만 깐다(예: add codex jira-workflow)
  remove     하네스 · 모듈을 끄고 고치지 않은 그 몫만 지운다
  update     킷을 새 판으로 올린다. 사람이 고친 파일은 <경로>.new 로 받는다
  outdated   설치 · CLI · 소스 최신 태그 판을 비교한다. --check 면 새 판이 있을 때 exit 1
  repair     지워진 킷 파일을 같은 판으로 되살린다. 고친 파일은 그대로 둔다
  uninstall  킷 소유이면서 고치지 않은 파일을 지운다
  doctor     설치 상태를 점검한다(읽기만). --check 면 오류가 있을 때 exit 1
  list       설치 요약. --files 면 lock 항목
  dashboard  관리 페이지 서버(127.0.0.1). --export <폴더> 는 정적 HTML, --all · --root · --workspace 는 여러 프로젝트
  status     처리할 일 · 이슈 · 문서 · 검증 · 흐름(--json 은 관리 페이지 API 와 같다)
  approve    사람 터미널 승인(approvals.md 에 덧붙인다). answer 질문 답 · review show|decide 리뷰 판단
  sessions   켜 둔 세션. dispatch 세션에 작업 요청(사람이 고를 때만) · dispatch list|drop 대기함
  units      Unit 변경 제안(propose · discard). flow gates 흐름 틀 · quality 품질 결과 · projects 등록부
  skills     이 컴퓨터 · 리포의 스킬 목록(단계 · 하네스 · 이름 겹침). usage 토큰 사용량 · 킷이 덧붙인 양 · history 프롬프트 기록
  pack       pack new <이름> --dir <경로> --from <파일>… — 프로젝트 파일로 회사 팩 골격을 만든다
  local      local sync | list — 개인 층(.agents/local/)을 하네스 폴더에 배치한다(공유 lock 밖)
  mob        몹 정리 세션 start | next | close | status(진행자 터미널, 회차를 닫아도 세션에 요청하지 않는다)
  sync       맞추기 — sync aidlc [--intent <AI-DLC 폴더>] [--check] · sync jira [--approvals | --verify] · sync units [--check] [--unit <id>] [--adopt]
  checkpoints  Entire 체크포인트 목록 · 설명(entire 모듈을 켠 리포)
  intake     요구사항 접수 — 글 · 첨부를 Intent 폴더(bug 는 이슈 폴더)로 받는다(신뢰하지 않는 입력으로 표시). --from jira:<키>|notion:<페이지> 는 외부 출처, --from ops:<운영 기록>#INC-n|NX-n 은 운영 기록에서
  deploy     배포 기록 plan · check · record · run · result(승인은 approve deploy:<기록> --gate deploy). 킷은 운영 배포 명령을 부를 뿐이다
  ops        운영 기록 new · check(읽기는 status --ops)
  metrics    전달 지표 5개(git · 승인 기록 · 배포 기록에서만 계산) · --baseline 기준선 · --verify-baseline
  rules      규칙 후보 candidates · list · promote · reject(승격 · 거절은 사람 터미널만)

사람만 하는 일

아래 명령의 쓰기 동작은 사람 터미널에서만 된다. 에이전트 세션이면 exit 3, TTY 가 아니어도 exit 3 이다. 에이전트 하네스의 PreToolUse 훅도 이 명령들을 막는다.

--helpknots-sync approve
