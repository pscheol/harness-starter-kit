11 · 옮기기와 도움

옛 이름(harness-kit · v1)에서 옮기기

이미 v1(킷 1.0.x)이나 옛 이름 harness-kit 으로 깐 리포를 knots-sync 2.x 로 옮기는 요약이다. 전체 절차 · 리포별 순서 · 실측 숫자는 이전 안내서(docs/migration-guide.md)가 원본이다. 이 장은 그 안내서를 처음 읽는 사람을 위한 지도다.

이 장에서

  1. 이름이 바뀐 것
  2. 시작하기 전에
  3. 공통 절차 7단계
  4. AI-DLC 가 깔려 있던 리포의 결정
  5. 손으로 만든 하네스가 있는 리포
  6. 되돌리기
  7. MR 설명에 붙일 숫자와 알려진 차이

한 줄 요약: 읽기만 하는 점검 → 바뀔 목록 보기 → 사람 승인 → 적용 → .new 병합 → 검증 → 커밋 하나. 문제가 있으면 그 커밋 하나를 git revert 한다.

이름이 바뀐 것

사람이 손으로 옮길 것은 거의 없다 — update 가 옮긴다. 플러그인 재설치와 CI 변수 이름만 사람 몫이다.

옛 이름새 이름누가 옮기나
CLI harness-kitknots-sync(별칭 kns, 옛 harness-kit 도 한동안 같은 CLI)—
플러그인 harness-kit, 스킬 /harness-kit:hx-bootstrap플러그인 kns, 스킬 /kns:bootstrap · /kns:update …사람이 다시 설치(/plugin install kns@knots-sync)
Kiro 전역 스킬 ~/.kiro/skills/hx-*~/.kiro/skills/kns-*bash install-kiro.sh --force 가 옛 기록의 hx-* 를 치우고 새로 깐다
상태 파일 .agents/harness-kit.json · .lock.agents/knots-sync.json · .lockupdate(Node 없으면 update.sh)가 쓰기 처음에 옮긴다. doctor · update --dry-run 은 읽기만 하고 legacy-names 로 알린다
프로젝트 스킬 /hx-specify …/kns-specify …update 가 새 스킬을 깔고 고치지 않은 옛 hx-* 는 지운다. 고친 것은 orphan 으로 남겨 알린다 — 사람이 옮긴 뒤 지운다
환경 변수 HX_* · HARNESS_KIT_*KNS_* · KNOTS_SYNC_*CI 변수(예: HX_DEPLOY_RESUME)는 사람이 바꾼다
전역 설정 ~/.config/harness-kit/~/.config/knots-sync/—

그대로인 것: 저장소 이름 harness-starter-kit, 파일 머리 표지 HARNESS STARTER KIT, scripts/harness/ 폴더, 훅 id harness-*. "하네스 엔지니어링"이라는 개념 이름이거나 v1 파일을 알아보는 열쇠라서다. 관리 페이지의 색 설정도 옛 브라우저 저장 값(hx-palette)을 한 번 읽는다.

시작하기 전에

  • 원래 리포 폴더에서 바로 하지 않는다. git worktree add 로 작업 공간을 새로 만들고, 끝나면 같은 세션 안에서 지운다. git clone · 폴더 복사는 원본과 연결이 없어 쓰지 않는다.
  • Node 18.3 이상(node -v). 없으면 kit.sh 가 setup.sh 로 내려가는 길이 v2.0.x 동안만 있다.
  • 킷 판: v1 은 .agents/harness-kit.json 의 kitVersion, 옮긴 리포는 .agents/knots-sync.json 의 kit.version.
  • 사람이 고친 파일이 많을수록(점검의 drifted) .new 병합이 길어진다.
  • 외부 도구(AI-DLC · Entire)가 이미 깔려 있어도 킷은 그 파일을 지우거나 덮지 않는다. 외부 도구 명령을 실제 홈에서 처음 돌리지 않는다 — 시험은 일회용 HOME 에서.
  • 안내서의 knots-sync 는 전역 설치한 CLI 다(→ 설치 · CLI). Node 가 없으면 플러그인 안의 bash <플러그인>/skills/bootstrap/kit.sh <명령> 이 v1 스크립트로 내려간다. 플러그인만 깔았다면 리포 폴더에서 연 Claude Code 에 /kns:update 를 입력해도 된다.

공통 절차 7단계

  1. 점검 — knots-sync doctor

    읽기만 한다. 결과를 이전 이슈의 handoff 문서에 붙인다. lock-v1(v1 TSV lock, update 가 v2 로 바꾼다) · drifted N(사람이 고친 킷 파일, .new 로 받는다) · missing N(지워진 킷 파일, repair 로 되살릴지 정한다) · external-hooks-left(외부 도구 훅이 남아 있는데 모듈은 꺼짐) · "세션마다 실리는 양"을 본다.

  2. 계획 — knots-sync update --dry-run

    합계 줄(new · update · conflict · skip-user · orphan)과 conflict 목록. --json 이면 counts. 이것이 승인 대상이다.

  3. 승인 — 사람

    사람이 목록을 보고 이전 이슈의 tasks 계획을 승인한다(관리 페이지 또는 knots-sync approve). 대화에서 한 말은 승인이 아니다.

  4. 적용 — knots-sync update

    .new 생성, lock v2 쓰기. v1 설치본의 첫 update 는 "설치 전부터 있던 파일"과 "킷이 깐 파일"을 구별할 수 없어, 구별 못 하는 문서는 줄 병합 · JSON 은 키 병합을 하고 원본을 .agents/state/merge-backup/<시각>/ 에 둔다. 코드 · 그 밖의 파일은 .new 로 받는다.

  5. 병합 — .new 를 0개로

    $ find . -name '*.new' -not -path './.git/*'
$ diff -u <파일> <파일>.new      # 필요한 줄만 원본에 옮긴다
$ rm <파일>.new

    리포 .gitignore 가 *.new 를 무시하면 git status 에 안 보이니 find 로 센다.

  6. 검증

    knots-sync doctor --check --json(exit 0), bash scripts/board.sh 출력이 이전과 같은지, 진입 파일 크기(wc -c AGENTS.md CLAUDE.md, 24,576바이트 이하 목표), full 은 사람 터미널이나 CI. 외부 도구 파일 불변은 python3 scripts/harness/check_external.py --save(전) · --snapshot(후)으로 본다.

  7. 커밋 하나

    chore: 하네스 v<버전> 이전 — <단계>. 사람 승인 뒤.

AI-DLC 가 깔려 있던 리포의 결정

선택할 일결과
A. 쓴다knots-sync add aidlc — 파일을 external:aidlc 로 등록, flow.design = "aidlc"AI-DLC 훅 17개가 계속 돈다. 세션마다 약 73KB 가 실린다
B. 쓰지 않는다(AI-DLC Intent 가 0건이면 권장)flow.design = "kit". AI-DLC 훅은 aidlc uninstall 또는 사람이 설정에서 뺀다훅 17개가 빠진다. 킷은 파일을 지우지 않는다

사람이 고르고 ADR 로 남긴다. add aidlc 전에는 AI-DLC 파일이 lock 에서 user 소유로 보여, 세션 적재량의 external:aidlc 가 0 으로 나오고 user 가 크다(훅 17개만 external:aidlc 로 센다).

손으로 만든 하네스가 있는 리포

킷 없이 하네스를 손으로 만든 리포는 update 가 아니라 knots-sync init --adopt --dry-run → 검토 → 승인 → init --adopt 다. 있던 파일은 owner: user 로 남는다. 단 CLAUDE.md 에 킷 블록이 병합되고 보드 블록이 있는 문서에 보드가 덧붙으니, git diff --stat 의 변경 파일이 이 둘뿐인지 본다(→ 설치 · 이미 있는 하네스).

되돌리기

상황방법
적용 뒤 · 커밋 전계획 목록의 경로를 git restore --staged --worktree -- <경로들> 로 되돌리고 새 파일(??)을 지운다. 되돌리기 전 파일 · lock 은 .agents/state/backup/<시각>/ 에도 있다(최근 5개)
커밋 뒤이전 커밋 하나를 git revert. lock 은 v1 TSV 로 돌아온다
외부 도구를 add 한 단계revert 만으로는 외부 도구가 넣은 훅이 돌아오지 않을 수 있다. 그 도구의 명령으로 되돌린다(aidlc uninstall · entire disable)
릴리스태그를 지우거나 다시 쓰지 않는다. 문제 판은 patch 로 고쳐 낸다. npx github:<owner>/harness-starter-kit#v2.2.1 처럼 태그를 고정해 쓴다

MR 설명에 붙일 숫자와 알려진 차이

이전 MR 설명에는 doctor --check --json exit 0, 남은 .new 0줄, 보드 차이 0, 진입 파일 크기 전 → 후, "세션마다 실리는 양" 전 → 후(하네스별), 세션 훅 수 전 → 후, CI full 링크, 남은 작업 공간 0개를 붙인다.

복사본으로 미리 해 본 결과(2.0.0-alpha.0): v1 1.0.7 리포 하나는 계획이 new 141 · conflict 47 이었고, 적용 뒤 .new 48개, Claude Code 세션 적재량이 61,957 → 76,079바이트(훅 20 → 30)로 늘었다. 늘어난 것은 킷 스킬 설명 · 역할 · 규칙 복사본이다(v1 설치본은 .claude/skills 가 없었다). 사람이 고친 문서가 많은 리포는 충돌이 많으니 폴더 단위로 병합 커밋을 나눠도 된다. 자세한 표는 이전 안내서 6~7절에 있다.
