# Security Policy — {{PROJECT_NAME}}

## 시크릿

- 소스에 시크릿(API 키, 비밀번호, 토큰, 인증서)을 **절대 커밋하지 않는다.**
- 환경변수 또는 시크릿 매니저를 쓴다. 필수 시크릿은 **시작 시점에 존재를 검증**한다.
- 노출된 시크릿은 코드에서 지우는 것으로 끝나지 않는다. **회전(rotate)**까지 한다.
- 데모/개발용 하드코딩 자격증명이 있다면 여기에 명시하고 **제거 시점을 정한다.**

## 신뢰 경계

시스템 경계를 넘어 들어오는 모든 값은 **신뢰하지 않는다.**

- 사용자 입력, API 응답, 파일 내용, 프로세스 간 메시지, 환경변수
- 경계에서 스키마 기반으로 검증한다. 통과한 뒤에만 도메인 로직에 넘긴다.
- 빠르게 실패하고, 실패 메시지에 내부 구조를 노출하지 않는다.

## 주입

- 쿼리·명령·경로를 문자열 연결로 만들지 않는다. 파라미터화 또는 안전한 빌더를 쓴다.
- 사용자 값이 들어가는 템플릿·마크업은 이스케이프한다.
- 파일 경로는 정규화 후 허용 루트 안에 있는지 확인한다.

## 오류 처리

- 오류를 조용히 삼키지 않는다. 빈 catch 블록은 결함이다.
- 사용자에게는 행동 가능한 메시지를, 로그에는 진단 가능한 맥락을 남긴다.
- 로그에 시크릿·토큰·개인정보를 남기지 않는다.

## 커밋 전 체크

- [ ] 하드코딩된 시크릿이 없다
- [ ] 경계 입력이 검증된다
- [ ] 주입 가능한 문자열 연결이 없다
- [ ] 오류가 명시적으로 처리된다
- [ ] 오류 메시지가 내부 정보를 흘리지 않는다
- [ ] 디버그 출력이 남아 있지 않다

## 보안 이슈 발견 시

1. 즉시 멈춘다.
2. 영향 범위를 파악한다.
3. 심각한 항목을 먼저 고친다.
4. 노출된 시크릿을 회전한다.
5. **같은 패턴이 코드베이스 다른 곳에 있는지 검색한다.**
