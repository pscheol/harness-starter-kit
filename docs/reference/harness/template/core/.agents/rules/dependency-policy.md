# Dependency Policy — {{PROJECT_NAME}}

## 추가

새 의존성은 **사용자 승인 후**에 추가한다. 에이전트가 임의로 설치하지 않는다.

절차:

1. **목적 확인** — 같은 기능을 하는 기존 의존성이 있는가
2. **호환성 확인** — 현재 런타임·프레임워크 버전과 맞는가
3. **번들/빌드 영향 확인** — 모듈 형식, 트리셰이킹, 네이티브 빌드
4. **보안 확인** — 알려진 취약점, 유지보수 상태, 관리자 수
5. **사용자 승인** — 설치 명령 실행 전에 보고

추가 사유를 커밋 메시지에 남긴다.

## 제거

- 사용처 없는 의존성 제거는 **별도 PR로 분리**한다. 기능 PR에 묶지 않는다.
- 제거 전 import 사용처가 0건임을 검색으로 확인한다.

## 버전 갱신

- **마이너/패치**: 자유롭게.
- **메이저**: 하나의 작업 단위 = 하나의 메이저 갱신. 여러 메이저를 한 번에 올리면 회귀 원인을 특정할 수 없다.
- 메이저 갱신은 SDD spec을 만들고 진행한다.

## 락파일

- 락파일은 **손으로 편집하지 않는다.**
- 락파일 변경은 매니페스트 변경과 같은 커밋에 넣는다.
- `--force`, `--legacy-peer-deps` 같은 회피 플래그를 일상적으로 쓰지 않는다. 필요하면 이유를 커밋에 남긴다.

## 자동화로 잡히는 영역

- [x] 락파일 동기화 → CI
- [x] 알려진 취약점 → 감사 명령
- [ ] 의존성 사슬 영향 → 수동 검토

## 안티-규칙

- ❌ "더 나은 라이브러리가 있다"는 이유만으로 교체 제안
- ❌ 사용자 승인 없이 설치 명령 실행
- ❌ 락파일 수동 편집
- ❌ 여러 메이저를 한 커밋에 묶기
