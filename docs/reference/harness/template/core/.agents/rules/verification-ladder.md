# Verification Ladder — {{PROJECT_NAME}}

`{{CMD_TEST}}` 통과만으로는 사용자 대면 변경의 완료 근거가 되지 않는다. 무엇을 어디까지 확인했는지 **수준을 명시**한다.

## Levels

| Level | 이름               | 목적                                          | 기본 방법                                                                                                 | 책임                                        |
| ----- | ------------------ | --------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| L0    | 정적 + 단위 게이트 | 타입·린트·단위 회귀                           | `{{CMD_TYPECHECK}}`, `{{CMD_LINT}}`, `{{CMD_TEST}}`; 위험 변경은 `{{CMD_BUILD}}` 또는 `{{CMD_PRECOMMIT}}` | 에이전트                                    |
| L1    | 개발 빌드 스모크   | 실제 실행 환경에서 사용자 흐름 확인           | `{{CMD_DEV}}` 실행 + 조작/스크린샷                                                                        | 범위 내 비파괴는 에이전트, 최종 판단은 사람 |
| L2    | 배포 산출물 스모크 | 패키징/설치본과 개발 빌드의 차이 확인         | 산출물 설치·실행                                                                                          | 사람(릴리즈 담당)                           |
| L3    | 사람의 판단        | 시각 품질, 실장비, 공유 데이터, 기대값 모호성 | 수동 확인                                                                                                 | 사람                                        |

## 변경 유형별 기본 매핑

- **문서만 변경**: L0 생략 가능. 대신 문서 링크와 검토 기준을 남긴다.
- **순수 함수·헬퍼**: L0 필수.
- **사용자 대면 UI/알림/저장·삭제/가져오기·내보내기**: L0 필수 + 범위 내 L1 스모크. 사람 L1 권장.
- **프로세스 경계·인증·최초 실행·패키징·업데이터**: L0 + 빌드 확인 + 범위 내 L1 스모크. 사람 L1/L2 필수.
- **공유 원격 데이터 삭제, 실장비, 장시간 실행, 디자인 미세 정합**: L3 필수.

## 에이전트 스모크 자율성

범위 안의 **비파괴** L1 스모크는 구현 검증의 일부이므로, 에이전트가 매번 대화형 허락을 묻지 않고 수행한다.

허용:

```text
개발 서버/앱 기동 또는 기존 인스턴스 연결
클릭·입력·스크린샷 등 읽기 위주 조작
.agents/artifacts/<작업단위>/ 아래 스모크 스크립트·로그·스크린샷 생성
읽기 전용 흐름 또는 폐기 가능한 임시 데이터 흐름 확인
```

중단하고 승인을 받아야 하는 것:

```text
공유·공개 데이터의 삭제·이름 변경·저장 값 변경
설치 프로그램 실행, OS 보안 권한 변경
자격증명 또는 OTP 입력
외부 배포, 아티팩트 publish, force push
플랫폼 샌드박스 승인 프롬프트
```

> 도구별 permission 엔진은 공유되지 않는다. 이 문단은 **에이전트의 행동 규칙**이며, 런타임이 강제하는 승인 프롬프트를 우회하라는 뜻이 아니다.

## 사람 검토 기록 형식

통과:

```text
[HUMAN-REVIEW]
result: passed
testedBy:
testedAt:
testedTarget: dev-build | installer | installed-app
levels: L1 | L2 | L3
notes:
```

실패:

```text
[HUMAN-REVIEW]
result: failed
testedBy:
testedAt:
testedTarget:
level:
expected:
actual:
reproduction:
evidence:
```

실패한 작업은 **기존 브랜치와 코드 owner를 디버깅**한다. 새 병렬 구현을 만들지 않는다.

## 병합 전 검증

사람 검토를 통과한 작업을 병합할 때는 사람 테스트를 반복하지 않는다. 대신 **최신 기준 브랜치에서의 병합 안정성**을 확인한다.

```bash
git fetch origin
# 변경 파일과 base 커밋 확인
{{CMD_TYPECHECK}}
{{CMD_LINT}}
{{CMD_TEST}}
```

충돌·stale·테스트 실패가 있으면 병합하지 않고 되돌린다.
