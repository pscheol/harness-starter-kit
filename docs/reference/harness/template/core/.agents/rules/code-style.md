# Code Style — {{PROJECT_NAME}}

## 무엇을

- **포매터**: 편집 후 훅이 자동 실행한다. 모델은 포맷을 신경 쓰지 않는다.
- **린터**: `--fix`가 자동 적용된다. 수동 정렬·정리 금지.
- **파일 구조**: 하위 요소는 상위와 같은 폴더에 co-locate 한다. 배럴 re-export는 만들지 않는다.
- **파일 크기**: 200~400줄이 기본, `.agents/harness.json`의 `budget.largeFileThreshold`가 상한이다. 넘으면 기능을 더 얹기 전에 분해를 먼저 검토한다.
- **함수 크기**: 50줄 이내를 기본으로 한다.
- **중첩**: 4단계를 넘기지 않는다. 조기 반환을 쓴다.

## 왜

- 포맷·정렬을 자동화에 넘기면 모델도 리뷰어도 그 항목에 어텐션을 쓰지 않는다.
- 배럴 파일은 트리셰이킹을 방해하고 번들을 부풀린다.
- 거대 파일은 부분 read를 강제하고, 부분 read는 추측을 부른다. 파일 크기 제한은 스타일 문제가 아니라 **정확도 문제**다.

## 네이밍

- Boolean: `is*` / `has*` / `should*` / `can*`
- 핸들러: 내부 `handle*`, props로 전달 `on*`
- 상수: `UPPER_SNAKE_CASE`
- 타입·컴포넌트: `PascalCase`
- 그 외 변수·함수: `camelCase`

> 언어 관용이 다르면 언어 관용이 우선한다. 이 표는 기본값이다.

## 언어

- **코드 식별자·기술 용어**: 영어 원문
- **주석·문서·사용자 응답**: {{DOC_LANGUAGE}}

## 추상화

- **3회 사용부터** 추상화한다. 사용처가 1곳인 추상화는 만들지 않는다.
- 3줄 미만 중복은 추출하지 않는다.
- speculative generality 금지 — 필요해진 다음에 만든다.

## 불변성

새 객체를 만들고 기존 객체를 변형하지 않는다. 다만 **언어 관용이 다르면 언어 관용을 따른다** (예: Go의 포인터 리시버).

## 자동화로 잡히는 영역

- [x] 들여쓰기·세미콜론·따옴표 → 포매터
- [x] 미사용 변수 → 린터
- [x] import 순서·중복 → 린터
- [x] 타입 오류 → 타입체커

→ **위 항목은 리뷰에서 코멘트하지 않는다.**

## 안티-규칙

- ❌ "이름이 더 명확했으면" 만으로 코멘트 — 명확한 _오해 유발_ 케이스만
- ❌ 3줄 미만 중복 추출 제안
- ❌ 사용처 1곳인 추상화 생성
- ❌ 기존 파일의 언어·확장자 일괄 변환 제안 — 변경 범위가 폭증한다
- ❌ 거대 파일 내부의 범위 밖 리팩터링 제안
