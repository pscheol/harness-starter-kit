# Golden Rules — {{PROJECT_NAME}}

> 본 파일은 단일 진실이다. 다른 정책과 충돌하면 본 파일이 우선한다.
> 개별 규칙은 `.agents/rules/*.md`, 도메인 절차는 `.agents/skills/`에 둔다.

## 1. 단일 진실은 `.agents/`

- 정책·스킬은 `.agents/`에만 작성한다. 도구 진입점(`AGENTS.md`, `.claude/`, `.codex/`)은 **참조만** 한다.
- 같은 정책의 사본을 도구별로 만들지 않는다. 사본은 반드시 드리프트를 만든다.
- 정책을 바꿀 때는 `.agents/` 원본만 고친다.

## 2. 컨텍스트는 희소 자원

- `AGENTS.md`는 **목차**다. 상세는 `.agents/`가 system of record.
- 한 번에 모든 정책을 읽지 않는다. 작업 도메인에 맞는 SKILL.md만 적재한다.
- 거대 파일(`.agents/harness.json`의 `budget.largeFileThreshold` 초과)은 **부분 read + Edit**. 전체 read 금지.

## 3. 모든 것을 저장소 안으로

- 에이전트가 컨텍스트에서 접근하지 못하는 정보는 **존재하지 않는 것과 같다**.
- 외부 문서(채팅, 위키, 티켓 코멘트)에만 있는 결정에 의존하지 않는다. 필요하면 `.agents/docs/`로 끌어온다.
- 외부 라이브러리 문서는 공식 문서를 확인한 뒤 필요한 부분만 `.agents/docs/references/`에 요약·캐시한다.

## 4. 추측 금지

- 라이브러리 API를 기억으로 작성하지 않는다. 공식 문서를 조회한 뒤 적용한다.
- 읽지 않은 파일의 내용을 추측하지 않는다. Read 또는 `rg`로 확인한다.
- 프로젝트 고유 패턴은 기존 코드 검색으로 확인한다.

## 5. 자동화에 위임한 영역은 건드리지 않는다

- 포맷·린트·타입체크·테스트 실행은 훅과 게이트가 처리한다.
- 에이전트도 리뷰어도 이 항목에 토큰을 쓰지 않는다. 코멘트도 하지 않는다.
- 자동화가 잡을 수 있는 것을 문서로 강제하지 않는다. 문서는 자동화가 잡지 못하는 것만 담는다.

## 6. 프로젝트 불변 조건 (invariants)

> 설치 후 이 표를 채운다. **이 표가 비어 있으면 하네스는 절반만 동작한다.**
> 후보: 보안 경계 옵션, 상태 머신 전이, 리소스 정리 의무, 스키마·카탈로그 동기화, 짝을 이뤄 갱신해야 하는 설정.
> 여기 적은 항목 중 기계로 검사 가능한 것은 `.agents/harness.json`의 `guards`에 스크립트로 등록한다.

## 7. 처리량 우선 머지 정책

- PR은 수명을 짧게 유지한다. **작업 단위 = 머지 단위 = revert 단위**.
- 차단 게이트는 최소로 둔다. 불안정한 테스트는 후속 작업으로 분리한다.
- 큰 변경은 되돌릴 수 있는 단위로 쪼갠다.

## 8. 사람 ↔ 에이전트 피드백 루프

- 에이전트가 막히면 **하네스의 결함 신호**로 본다. 도구·가드레일·문서 중 무엇이 없었는지 파악한다.
- 같은 실수를 두 번 지적했다면, 지적 대신 `.agents/` 또는 `scripts/`에 인코딩한다.
- 사람의 문체 취향과 충돌하면 **에이전트 가독성 + 정확성 + 유지보수성**을 우선한다.

## 9. 도구 추상화

본 저장소는 특정 에이전트 도구에 잠기지 않는다.

| 추상 동작        | 구현                                 |
| ---------------- | ------------------------------------ |
| 정책 자동 로드   | `AGENTS.md` (+ 도구별 심볼릭)        |
| 스킬 탐색        | `.agents/skills/` (+ 도구별 심볼릭)  |
| 세션 시작 검증   | `scripts/assert-harness-context.cjs` |
| 편집 후 정리     | `scripts/format-and-lint-hook.cjs`   |
| 커밋 전 게이트   | `scripts/precommit.cjs`              |
| 하네스 회귀 검사 | `scripts/verify-harness.cjs`         |

**`scripts/`가 진실이고, 훅과 슬래시 커맨드는 그 호출에 불과하다.** 새 도구를 붙일 때는 어댑터에서 같은 스크립트를 부르게만 한다.

## 10. 가비지 컬렉션

- 나쁜 패턴이 코드베이스에 며칠 이상 머물지 않게 한다.
- 자체 헬퍼보다 공유 유틸리티를 선호한다. 불변 조건을 한 곳에서 관리하기 위해서다.
- 형태를 추측하지 말고 타입 있는 경계 검증을 사용한다.
- 남은 부채는 `.agents/docs/exec-plans/tech-debt-tracker.md`에 기록한다. 기록되지 않은 부채는 사라지지 않고 반복된다.

## 위반 시

- 가능하면 CI 실패 또는 린트 경고로 노출한다. 문서만으로 강제하지 않는다.
- 위반을 인라인 억제 주석(`eslint-disable`, `@ts-ignore` 등)으로 덮지 않는다. 억제가 필요하면 규칙 자체를 고친다.
