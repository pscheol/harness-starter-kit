# PR Review Policy — {{PROJECT_NAME}}

리뷰의 목적은 **결함을 잡는 것**이지 취향을 관철하는 것이 아니다. 자동화가 잡는 것과 취향 문제를 걷어내면, 남는 코멘트의 채택률이 올라가고 리뷰가 신뢰를 얻는다.

## 코멘트 우선순위

| 순위 | 카테고리       | 설명                                            |
| ---- | -------------- | ----------------------------------------------- |
| 1    | Logic error    | 조건·상태 전이·수명주기 오류                    |
| 2    | Security       | 인증·권한·시크릿 노출·경계 우회                 |
| 3    | Race condition | 정리 누락, 취소 미적용, 순서 의존               |
| 4    | Data loss      | 덮어쓰기, 미저장 상태 이탈, 되돌릴 수 없는 삭제 |
| 5    | API contract   | 공개 계약(스키마·채널·파라미터) 불일치          |

**위 5개 카테고리에 해당하지 않으면 코멘트하지 않는다.**

## 톤 / 형식

- "Consider…", "This may…" 형태의 제안형. 단정문 금지.
- 한 코멘트 = 한 이슈.
- PR 최종 상태만 리뷰한다. 중간 커밋 단위 리뷰 금지.
- 같은 PR 안에서 자기모순 금지.

## 자동화에 위임된 영역 (코멘트 금지)

- ❌ 포맷 — 포매터가 처리
- ❌ 린트 규칙 — 린터가 처리
- ❌ 타입 오류 — 타입체커가 처리
- ❌ import 순서 / 미사용 변수
- ❌ 테스트 실행 / 커버리지 수치

## 프로젝트 negative knowledge

> 설치 후 이 표를 채운다. **"알지만 지금은 안 고치기로 한 것"** 목록이다.
> 이 표가 비어 있으면 리뷰어가 매번 같은 것을 지적하고, 그 지적은 매번 무시된다.

| ❌ 지적하지 말 것 | 이유 |
| ----------------- | ---- |
|                   |      |

## Scope

- 리뷰는 **변경된 라인 ± 컨텍스트 5줄** 안에서만 한다.
- 변경되지 않은 코드의 스타일·구조 제안 금지.
- 거대 파일 내부의 일반 리팩터링 제안 금지 — 별도 계획으로 다룬다.

## 프로젝트 중점 점검 영역

> 설치 후 채운다. 회귀가 반복되는 영역을 적고, 그 영역이 바뀌면 **적극적으로** 코멘트한다.

## 측정 / 튜닝

- 주기적으로 코멘트 채택률(applied / proposed)을 본다.
- 채택률 30% 미만 카테고리는 "자동화 위임" 또는 "negative knowledge"로 옮긴다.
- 채택률 70% 초과 카테고리는 우선순위 상향을 검토한다.
