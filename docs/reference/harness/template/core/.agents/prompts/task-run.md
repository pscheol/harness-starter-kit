# 작업 실행 프롬프트

```text
작업: <작업 설명 또는 이슈 ID>

다음 순서로 진행해.

1. 착수 전
   - AGENTS.md와 관련 .agents/rules를 확인한다.
   - rg 로 기존 owner(코드·테스트·문서)를 찾는다. (.agents/rules/reuse-before-new.md)
   - 영향 범위와 부작용 범위를 정의한다.
   - 여러 파일에 걸치면 .agents/docs/product-specs/<작업단위>/ 에 SDD 산출물을 만든다.
     간단한 작업이면 "SDD exception: <이유>" 를 보고에 남긴다.

2. 계획 보고
   - 무엇을 어떤 순서로 바꿀지, 어떤 검증을 돌릴지 먼저 알려준다.
   - 기준 브랜치가 불명확하면 여기서 멈추고 물어본다.

3. 구현
   - tasks.md 의 가장 작은 검증 가능한 단위 하나부터.
   - 거대 파일은 부분 read + Edit.
   - 라이브러리 API 는 추측하지 말고 공식 문서를 확인한다.

4. 검증
   - .agents/rules/verification-ladder.md 로 필요한 수준을 정한다.
   - 대상 테스트 -> 필수 게이트 순서.
   - 못 돌린 검증은 생략 사유와 잔여 위험을 반드시 적는다.

5. 보고
   - 변경 파일 목록
   - 실행한 검증과 결과 (실패한 것은 실패로 적는다)
   - SDD spec 경로 또는 exception 사유
   - 잔여 위험과 사람이 확인해야 할 항목
```
