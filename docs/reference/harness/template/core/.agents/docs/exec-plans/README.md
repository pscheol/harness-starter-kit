# exec-plans — 실행 계획

**여러 작업 단위·여러 저장소·장기 rollout**에 걸치는 상위 계획을 둔다.

개별 티켓이나 단일 기능은 여기가 아니라 `.agents/docs/product-specs/<작업단위>/`에 둔다.

## 구조

```text
exec-plans/
├── active/                  # 진행 중인 계획
├── completed/               # 종료된 계획 (회고·재실행 참조용)
└── tech-debt-tracker.md     # 알고도 미룬 부채 목록
```

## 언제 exec-plan 을 만드는가

| 상황                                                   | 위치                        |
| ------------------------------------------------------ | --------------------------- |
| 단일 기능/버그                                         | `product-specs/<작업단위>/` |
| 의존성 메이저 전환처럼 여러 단계·여러 PR로 나뉘는 작업 | `exec-plans/active/`        |
| 여러 저장소에 걸친 rollout                             | `exec-plans/active/`        |
| 반복 적용되는 방법론                                   | `design-docs/`              |

## 계획 문서 형식

```markdown
# <계획 이름>

- 상태: active | completed
- 시작:
- 종료 조건: (무엇이 참이면 이 계획을 닫는가)

## 배경

## 단계 / 카드

- [ ] CARD-1 <제목>
  - 범위:
  - 검증:
  - 되돌리기:

## 사람 체크포인트

## 결과
```

## 운영 규칙

- **카드 하나 = 머지 하나 = revert 하나.** 되돌릴 수 없는 카드는 카드가 아니다.
- 진행 결과는 계획 문서에 **즉시** 기록한다. 코드 변경과 같은 커밋에 넣는다.
- 종료 조건을 만족하면 `active/` → `completed/`로 옮긴다.
- 상위 계획이 있으면 하위 완료 링크와 근거를 상위에 남긴다.
