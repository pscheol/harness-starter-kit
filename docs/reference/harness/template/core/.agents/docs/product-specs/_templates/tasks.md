## 작업 규칙

- 한 번에 1~2개 작업만 진행하고 검증 후 다음으로 넘어간다.
- 설계와 어긋나면 **먼저 `design.md`를 갱신한 뒤** 구현한다.
- 코드 변경과 체크박스 갱신은 **같은 커밋**에 포함한다.
- 체크박스는 `- [ ]`와 `- [x]` 두 상태만 사용한다.

## 검증 (완료 기준)

- [ ] 대상 테스트 통과 — 명령:
- [ ] 린트 통과
- [ ] 타입체크 통과
- [ ] 전체 테스트 통과
- [ ] 필요 시 통합 게이트 통과
- [ ] 성공 케이스와 최소 1개 실패 케이스 테스트
- [ ] 권한/인증 영향이 있으면 실패 케이스 확인
- [ ] UI 영향이 있으면 스모크 결과와 산출물 경로 기록
- [ ] 공개 계약 변경 시 관련 문서 갱신

## 완료 처리

1. 완료 기준과 필수 게이트를 충족하면 체크박스를 완료로 바꾼다.
2. 결과 섹션에 검증 근거와 산출물 경로를 적고 검토를 요청한다.
3. **사람이 통과를 명시하기 전에는 완료로 전환하지 않는다.**
