## 기준 문서

> 설치 후 채운다. **어느 것이 최신 기준인지** 명시한다.

| 종류           | 위치 | 우선순위   | 비고                      |
| -------------- | ---- | ---------- | ------------------------- |
| 디자인 가이드  | TBD  | 1          |                           |
| 레이아웃 기준  | TBD  | 2          |                           |
| 변경/최신 반영 | TBD  | 0 (최우선) | 최근 변경은 여기부터 확인 |
| 사용자 매뉴얼  | TBD  | 3          |                           |

기준이 충돌하면 **위 우선순위 숫자가 작은 쪽**을 따른다. 그래도 모호하면 구현하지 말고 확인한다.

## 핵심 원칙

**기준 확인 없이 새 color / spacing / radius / font scale 을 만들지 않는다.**

에이전트는 "적당히 어울리는 값"을 잘 만들어낸다. 그 값들이 쌓이면 디자인 시스템이 사라진다.

1. 먼저 기존 토큰에 맞는 값이 있는지 확인한다.
2. 없으면 디자인 소스에서 확인한다.
3. 디자인 소스에도 없으면 **구현을 멈추고 묻는다.**

## 토큰 owner

> 설치 후 채운다.

| 종류        | 정의 위치 |
| ----------- | --------- |
| 색상        |           |
| 간격        |           |
| 타이포      |           |
| 반경/그림자 |           |
| 모션        |           |

토큰은 위 owner에만 추가한다. 화면 하나의 특수 값을 공통 토큰으로 올리지 않는다.

## 컴포넌트

- 새 컴포넌트 전에 `.agents/rules/reuse-before-new.md`의 Inventory 를 수행한다.
- 같은 역할의 컴포넌트가 다른 이름으로 있으면 **기존 것을 개선**한다.
- 상태(hover/focus/active/disabled/loading/empty/error)를 빠뜨리지 않는다.

## 접근성 기준선

- 의미에 맞는 시맨틱 요소를 쓴다. 범용 컨테이너로 대체하지 않는다.
- 키보드로 도달·조작 가능한가.
- 대비가 기준을 만족하는가.
- 모션 감소 설정을 존중하는가.
