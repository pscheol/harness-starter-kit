# 이슈 정리(intake) 프롬프트

티켓이 pull gate 를 통과할 수 있는 상태인지 확인하고, 부족하면 채운다.

```text
<티켓 ID> 를 구현 가능한 상태로 정리해줘. 구현은 하지 마.

1. 읽기
   - 티켓 본문, 코멘트, 연결 이슈, 첨부, 기존 브랜치/MR 근거를 전부 읽는다.
   - 관련 코드 owner 를 rg 로 찾는다.

2. Pull gate 점검 — 각 항목을 있음/없음으로 판정
   - 대상 저장소
   - 완료 조건 또는 수용 기준
   - 테스트 방법 (사람이 실제로 클릭/입력할 절차)
   - 기대값 (무엇을 보면 통과인가)
   - 근거 (스크린샷·로그·명세 링크)

3. 없는 항목 채우기 제안
   - 코드와 기존 명세에서 추론 가능한 것은 초안을 만든다.
   - 추론 불가능한 것은 "확인 필요" 로 남긴다. 추측해서 채우지 않는다.

4. 분해 판단
   - 여러 독립 변경이 섞여 있으면 분리 후보를 제안한다.
   - 분리 기준: 되돌릴 수 있는 단위인가.

5. 보고
   - gate 통과 여부
   - 채운 항목과 확인 필요 항목
   - 분해 제안
   - 예상 영향 범위
```
