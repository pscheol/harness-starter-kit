# 보안 가드레일 — {{PROJECT_NAME}}

이 규칙 위반은 **코드리뷰 즉시 차단 대상**이다. 일정·성능보다 우선한다.
프로젝트 고유의 데이터 모델·권한 모델은 여기가 아니라 `product.md`와 설계 문서에서 정한다.
이 파일은 **어느 프로젝트에서나 지켜야 하는 최소 방어선**만 규정한다.

## 인증 / 인가 경계

- 인증 실패는 401, 권한 없음은 403으로 구분한다. 둘을 섞지 않는다.
- 보호를 라우터 그룹 단위로 건다. 핸들러마다 인증 코드를 복붙하면 누락이 기본값이 된다 — 보호 그룹에 미들웨어를 걸고, 공개 경로만 예외로 명시한다(allowlist).
- JWT를 쓴다면 검증된 라이브러리로 하고 **알고리즘을 명시적으로 제한**한다(`alg=none`·HMAC/RSA 혼동 공격 차단). `aud`·`iss`·`exp`를 반드시 검증한다.
- 인증 결과는 **타입 있는 구조체**로 ctx에 담는다. 핸들러 안쪽으로 raw map을 흘리지 않는다.
- 요청 컨텍스트는 `context.Context`로 전파한다. 패키지 전역 변수에 담으면 동시 요청 간에 섞인다(치명적 교차 노출).
  - context 키는 **비공개 타입**(`type ctxKey struct{}`)으로 정의한다. 문자열 키는 다른 패키지와 충돌한다.
- 인증 실패 응답도 공통 envelope로 나간다.

## 접근 제어는 두 곳에서 (미들웨어 + 유스케이스)

권한은 **경계와 로직 두 곳에서** 강제한다. 어느 한쪽만으로는 안 된다.

1. **미들웨어(1차)**: 인증 여부·역할처럼 요청 단위로 판단 가능한 것.
2. **유스케이스 진입(2차)**: "이 요청자가 이 리소스에 접근할 수 있는가"는 로직 안에서 다시 확인한다. 식별자만 바꾸면 남의 리소스가 보이는 IDOR은 미들웨어로 막히지 않는다.
3. **fail-closed**: 판단에 필요한 컨텍스트가 없거나 비면 기본 거부한다. 컨텍스트 누락 시 데이터가 새면 안 된다.
4. 소유·권한 판정이 있는 리소스는 권한 없는 접근이 차단되는지 자동 테스트로 고정한다(허용 200 · 비허용 403/404 · 미인증 401).
5. 사용자·요청자에 종속된 데이터를 캐시할 때는 캐시 키에 스코프를 반드시 포함한다(교차 노출 차단).

## Secret / 자격증명 처리 (평문 저장 금지)

- 시크릿은 **환경변수·시크릿 매니저로 주입**한다. 코드·리포·커밋되는 설정 파일에 두지 않는다.
- 저장이 필요하면 용도로 방식을 가른다:
  - 재검증만 필요한 값(발급 토큰·키): 해시만 저장하고 원문은 발급 응답에서 1회만 반환한다.
    - 비교는 `crypto/subtle.ConstantTimeCompare` 또는 `hmac.Equal`로 한다(타이밍 공격 방지). `==`·`bytes.Equal` 금지.
  - **사용자 비밀번호**: 느린 KDF(`golang.org/x/crypto/argon2` 또는 `bcrypt`)로 해시한다. SHA-256 단독 금지.
  - 원문을 다시 써야 하는 값(외부 서비스 자격증명 등): AES-256-GCM 등 인증 암호화로 저장한다.
    - GCM nonce는 **매번 새로 생성**하고 재사용하지 않는다(재사용 시 기밀성이 무너진다).
- 난수·토큰은 **`crypto/rand`** 로 생성한다. `math/rand` 금지(예측 가능 — gosec이 잡는다).
- 로그·응답·주석·예시에 secret 값을 절대 출력하지 않는다. 에러 메시지에도 넣지 않는다(스택이 로그로 나간다).
- 구조체를 통째로 로깅하지 않는다(secret 필드가 딸려 나간다). 민감 필드는 `String()`을 재정의해 마스킹한다.

## Go 고유 위험 (금지 목록)

- **SQL 인젝션**: 문자열 결합·`fmt.Sprintf`로 쿼리를 만들지 않는다. 파라미터 바인딩(`$1`·`?`)만 쓴다. 식별자(테이블/컬럼)를 동적으로 넣어야 하면 allowlist로 검증한다.
- **명령 실행**: `exec.Command`에 사용자 입력을 그대로 넣지 않는다. 셸을 경유하지 않고(`sh -c` 금지) 인자를 분리해 전달한다.
- **경로 순회**: 사용자 입력으로 경로를 만들 때 `filepath.Clean` 후 base 하위인지 검증한다(`strings.HasPrefix`만으로는 부족 — `filepath.Rel`로 확인). Go 1.24+면 `os.Root`를 검토한다.
- **SSRF**: 사용자 제공 URL로 요청하기 전에 스킴·호스트 allowlist로 좁히고 사설 대역을 차단한다.
- **TLS**: `InsecureSkipVerify: true` 금지(내부 호출 포함). 사설 CA는 CertPool에 추가한다.
- **정수 오버플로/변환**: 외부 입력을 좁은 타입으로 변환할 때 범위를 검사한다(`int64` → `int32` 등).
- **역직렬화 상한**: 요청 본문은 `http.MaxBytesReader`로 제한한다. 압축 해제(zip/gzip)는 해제 후 크기 상한을 둔다(zip bomb).
- **panic 노출**: recover 미들웨어에서 스택을 응답에 담지 않는다(로그에만).
- **pprof·debug 엔드포인트**: 운영에서 외부 노출 금지. `net/http/pprof`를 import하면 DefaultServeMux에 자동 등록되므로 별도 내부 전용 서버에만 붙인다.
- **의존성 보안**: `go.sum` 커밋 + `govulncheck` 정기 실행. `gosec`을 golangci-lint에 포함한다.

## 감사 / 기타

- 리버스 프록시·게이트웨이를 앞단에 두더라도 **인가는 애플리케이션에서 반드시 다시 강제**한다(앞단만 믿지 않는다).
- 보안 이벤트(권한 변경·자격증명 발급/폐기·시크릿 접근·인증 실패)는 감사 로그로 남긴다(누가·언제·무엇을·결과).
- 외부에서 들어오는 콜백/Webhook은 signature 검증(`hmac.Equal`) + 이벤트 식별자 기준 멱등 처리.
- 입력은 시스템 경계에서 검증한다(DTO 디코딩 → 도메인 생성자 2차 방어선). 검증 규약은 [`api-standards.md`](./api-standards.md).
