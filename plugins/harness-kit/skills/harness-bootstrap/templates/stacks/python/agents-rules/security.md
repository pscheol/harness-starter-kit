# 보안 가드레일 — {{PROJECT_NAME}}

이 규칙 위반은 **코드리뷰 즉시 차단 대상**이다. 일정·성능보다 우선한다.
프로젝트 고유의 데이터 모델·권한 모델은 여기가 아니라 `product.md`와 설계 문서에서 정한다.
이 파일은 **어느 프로젝트에서나 지켜야 하는 최소 방어선**만 규정한다.

## 인증 / 인가 경계

- 인증 실패는 401, 권한 없음은 403으로 구분한다. 둘을 섞지 않는다.
- 인증/인가는 **라우터 의존성**(`Depends(require_auth)` 등)에서 1차로 막는다.
- 의존성을 라우터마다 복붙하지 않는다. 보호가 필요한 라우터는 `APIRouter(dependencies=[Depends(require_auth)])`로 묶어 **누락이 기본값이 되지 않게** 한다.
- JWT를 쓴다면 검증된 라이브러리로 한다(`PyJWT`/`python-jose` 등). `options={"verify_signature": False}`·`algorithms` 미지정 금지(alg=none 공격). `aud`·`iss`·`exp`를 반드시 검증한다.
- 인증 결과는 **타입이 있는 principal 객체**(dataclass/Pydantic)로 좁혀서 전달한다. 라우터 안쪽으로 raw dict를 흘리지 않는다.
- 요청 컨텍스트는 **`contextvars`** 로 전파한다. 전역 변수·모듈 상태로 두면 async 동시 요청 간에 섞인다(치명적 교차 노출).
- 인증 실패 응답도 공통 envelope로 나간다(핸들러 경유). 미들웨어 단계 오류는 `Accept-Language`를 직접 읽어 i18n 처리한다.

## 접근 제어는 두 곳에서 (의존성 + 유스케이스)

권한은 **경계와 로직 두 곳에서** 강제한다. 어느 한쪽만으로는 안 된다.

1. **라우터 의존성(1차)**: 인증 여부·역할처럼 요청 단위로 판단 가능한 것.
2. **유스케이스 진입(2차)**: "이 요청자가 이 리소스에 접근할 수 있는가"는 로직 안에서 다시 확인한다. 식별자만 바꾸면 남의 리소스가 보이는 IDOR은 의존성으로 막히지 않는다.
3. **fail-closed**: 판단에 필요한 컨텍스트가 없거나 비면 기본 거부한다. 컨텍스트 누락 시 데이터가 새면 안 된다.
4. 소유·권한 판정이 있는 리소스는 권한 없는 접근이 차단되는지 자동 테스트로 고정한다(허용 200 · 비허용 403/404 · 미인증 401).
5. 사용자·요청자에 종속된 데이터를 캐시할 때는 캐시 키에 스코프를 반드시 포함한다(교차 노출 차단).

## Secret / 자격증명 처리 (평문 저장 금지)

- 시크릿은 **환경변수·시크릿 매니저로 주입**한다. 코드·리포·커밋되는 설정 파일에 두지 않는다.
- 저장이 필요하면 용도로 방식을 가른다:
  - 재검증만 필요한 값(발급 토큰·키): 해시만 저장하고 원문은 발급 응답에서 1회만 반환한다.
    - 비교는 `hmac.compare_digest` 로 한다(타이밍 공격 방지). `==` 금지.
  - **사용자 비밀번호**: 반드시 느린 KDF(argon2id 권장, bcrypt 대안)로 해시한다. SHA-256 단독 금지.
  - 원문을 다시 써야 하는 값(외부 서비스 자격증명 등): AES-256-GCM 등 인증 암호화로 저장한다.
- 난수·토큰 생성은 **`secrets`** 모듈로 한다(`random` 모듈 금지 — 예측 가능).
- 로그·응답·주석·예시에 secret 값을 절대 출력하지 않는다. 로깅 컨텍스트(structlog bind)에도 넣지 않는다.
- 예외 메시지에 원문 값을 넣지 않는다(스택트레이스가 로그로 나간다).

## Python 고유 위험 (금지 목록)

- `eval`/`exec`/`pickle.loads` 로 신뢰할 수 없는 입력 처리 금지(RCE). 직렬화는 JSON을 쓴다.
- **`subprocess`**: `shell=True` 금지. 인자를 리스트로 전달하고 사용자 입력을 그대로 넣지 않는다.
- **SQL**: 문자열 포매팅(f-string·`%`·`+`)으로 쿼리를 만들지 않는다. 파라미터 바인딩(`text(...)` + 바인드 파라미터, ORM 표현식)만 쓴다.
- **경로 처리**: 사용자 입력으로 파일 경로를 만들 때 `Path(base) / user_input` 후 `resolve()` 하고 base 하위인지 확인한다(경로 순회 차단).
- **역직렬화·YAML**: `yaml.safe_load`만 쓴다(`yaml.load` 금지).
- **HTTP 클라이언트**: TLS 검증을 끄지 않는다(`verify=False` 금지). 내부 호출도 마찬가지.
- **SSRF**: 사용자 제공 URL로 요청하기 전에 스킴·호스트 allowlist로 좁히고 사설 대역을 차단한다.
- **의존성 보안**: 잠금 파일을 커밋하고, 취약점 스캔(`pip-audit`/`uv pip audit` 등)을 정기 실행한다. Ruff `S`(bandit) 룰을 게이트에 포함한다.
- **디버그 노출**: 운영에서 `/docs`·상세 스택트레이스·`debug=True` 노출 금지(설정으로 제어).

## 감사 / 기타

- 리버스 프록시·게이트웨이를 앞단에 두더라도 **인가는 애플리케이션에서 반드시 다시 강제**한다(앞단만 믿지 않는다).
- 보안 이벤트(권한 변경·자격증명 발급/폐기·시크릿 접근·인증 실패)는 감사 로그로 남긴다(누가·언제·무엇을·결과).
- 외부에서 들어오는 콜백/Webhook은 signature 검증(`hmac.compare_digest`) + 이벤트 식별자 기준 멱등 처리.
- 입력은 시스템 경계에서 검증한다(Pydantic → 도메인 VO 2차 방어선). 검증 규약은 [`api-standards.md`](./api-standards.md).
