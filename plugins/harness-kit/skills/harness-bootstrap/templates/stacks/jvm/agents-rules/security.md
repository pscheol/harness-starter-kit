# 보안 가드레일 — {{PROJECT_NAME}}

이 규칙 위반은 **코드리뷰 즉시 차단 대상**이다. 일정·성능보다 우선한다.
프로젝트 고유의 데이터 모델·권한 모델은 여기가 아니라 `product.md`와 설계 문서에서 정한다.
이 파일은 **어느 프로젝트에서나 지켜야 하는 최소 방어선**만 규정한다.

## 인증 / 인가 경계

- 인증 실패는 **401**, 권한 없음은 **403**으로 구분한다. 둘을 섞지 않는다.
- 인증/인가는 **Spring Security 필터 체인**에서 1차로 막는다.
- **보호를 경로 매처 단위로 건다.** 컨트롤러마다 검사 코드를 복붙하면 누락이 기본값이 된다 — 보호 규칙을 필터 체인에 선언하고 공개 경로만 예외로 명시한다(allowlist).
- JWT를 쓴다면 검증된 라이브러리로 하고 **알고리즘을 명시적으로 제한**한다(`alg=none`·HMAC/RSA 혼동 공격 차단). `aud`·`iss`·`exp`를 반드시 검증한다.
- 인증 결과는 **타입이 있는 principal 객체**로 좁혀서 전달한다. 컨트롤러 안쪽으로 raw map을 흘리지 않는다.
- 보안 필터단에서 나가는 오류 응답도 공통 envelope로 쓴다(`ApiAuthErrorWriter` 등). 필터는 `DispatcherServlet` 이전이라 `Accept-Language`를 직접 읽어 i18n 처리한다.

## 접근 제어는 두 곳에서 (필터 체인 + 유스케이스)

권한은 **경계와 로직 두 곳에서** 강제한다. 어느 한쪽만으로는 안 된다.

1. **Spring Security(1차)**: 인증 여부·역할처럼 요청 단위로 판단 가능한 것.
2. **오케스트레이션 계층 진입(2차)**: "이 요청자가 **이 리소스**에 접근할 수 있는가"는 유스케이스 안에서 다시 확인한다. 식별자만 바꾸면 남의 리소스가 보이는 IDOR은 필터로 막히지 않는다.
3. **fail-closed**: 판단에 필요한 컨텍스트가 없거나 비면 **기본 거부**한다. 컨텍스트 누락 시 데이터가 새면 안 된다.
4. 소유·권한 판정이 있는 리소스는 **권한 없는 접근이 차단되는지 자동 테스트로 고정**한다(허용 200 · 비허용 403/404 · 미인증 401).
5. 사용자·요청자에 종속된 데이터를 캐시할 때는 **캐시 키에 스코프를 반드시 포함**한다(교차 노출 차단).

## Secret / 자격증명 처리 (평문 저장 금지)

- 시크릿은 **환경변수·시크릿 매니저로 주입**한다. 코드·저장소·커밋되는 설정 파일(`application.yml` 등)에 두지 않는다.
- 저장이 필요하면 용도로 방식을 가른다:
  - **재검증만 필요한 값**(발급 토큰·키): 해시만 저장하고 원문은 **발급 응답에서 1회만** 반환한다. 이후 목록·상세에서 절대 반환하지 않는다.
    - 검증 핫패스는 고엔트로피 hash 단건 인덱스 조회로 처리한다(단방향이지만 검색 가능).
    - 비교는 **`MessageDigest.isEqual`** 등 상수시간 비교로 한다(타이밍 공격 방지). `equals` 금지.
  - **사용자 비밀번호**: **느린 KDF**(`Argon2PasswordEncoder`·`BCryptPasswordEncoder`)로 해시한다. SHA-256 단독 금지.
  - **원문을 다시 써야 하는 값**(외부 서비스 자격증명 등): **AES-256-GCM 등 인증 암호화**로 저장한다(복호화 가능).
- 난수·토큰은 **`SecureRandom`** 으로 생성한다. `java.util.Random`·`kotlin.random.Random` 금지(예측 가능).
- 로그·응답·주석·예시에 secret 값을 절대 출력하지 않는다(키 이름으로만 참조). `requestId`는 MDC로 자동 포함되지만 secret은 MDC에도 넣지 않는다.
- data class·엔티티를 통째로 로깅하지 않는다(`toString()`에 민감 필드가 딸려 나간다). 민감 필드는 `toString()`을 재정의해 마스킹한다.

## JVM / Spring 고유 위험 (금지 목록)

- **SQL·JPQL 인젝션**: 문자열 결합·템플릿으로 쿼리를 만들지 않는다. **바인드 파라미터**(`:param`·`?1`)만 쓴다. 정렬·식별자를 동적으로 넣어야 하면 allowlist로 검증한다.
- **역직렬화**: Java 직렬화로 신뢰할 수 없는 입력을 복원하지 않는다. Jackson의 polymorphic typing(`activateDefaultTyping`)을 켜지 않는다(RCE 경로).
- **XXE**: XML 파서(`DocumentBuilderFactory`·`XMLInputFactory`)는 외부 엔티티·DTD를 비활성화한 뒤 쓴다.
- **표현식 인젝션**: 사용자 입력을 SpEL·OGNL·템플릿 표현식으로 평가하지 않는다. 로그 메시지 포맷 문자열에 사용자 입력을 직접 넣지 않는다.
- **명령 실행**: `ProcessBuilder`에 사용자 입력을 그대로 넣지 않는다. 셸을 경유하지 않고 인자를 분리해 전달한다.
- **경로 순회**: 사용자 입력으로 경로를 만들 때 `Path.normalize()` 후 **base 하위인지 `startsWith`로 검증**한다.
- **SSRF**: 사용자 제공 URL로 요청하기 전에 스킴·호스트 allowlist로 좁히고 사설 대역을 차단한다.
- **TLS**: 검증을 끄지 않는다 — 신뢰-전체 `TrustManager`·`HostnameVerifier` 오버라이드 금지(내부 호출 포함).
- **요청 크기 상한**: 업로드·본문 크기 상한을 설정한다. 압축 해제(zip/gzip)는 해제 후 크기 상한을 둔다(zip bomb).
- **스택 노출**: 예외 응답에 스택트레이스·내부 경로를 담지 않는다(로그에만).
- **Actuator·debug 엔드포인트**: 운영에서 외부 노출 금지. 노출 엔드포인트를 명시적으로 좁히고 별도 포트/인증 뒤에 둔다.
- **의존성 보안**: 잠금 파일을 커밋하고 취약점 스캔(OWASP dependency-check 등)을 정기 실행한다.

## 감사 / 기타

- 리버스 프록시·게이트웨이를 앞단에 두더라도 **인가는 애플리케이션에서 반드시 다시 강제**한다(앞단만 믿지 않는다).
- 보안 이벤트(권한 변경·자격증명 발급/폐기·시크릿 접근·인증 실패)는 감사 로그로 남긴다(누가·언제·무엇을·결과).
- 외부에서 들어오는 콜백/Webhook은 signature 검증 + 이벤트 식별자 기준 멱등 처리(중복 수신 시 기존 결과 반환).
- 입력은 시스템 경계에서 검증한다(Jakarta Validation → 도메인 VO `require` 2차 방어선). 자세한 검증 규약은 [`api-standards.md`](./api-standards.md).
