# 핵심 원칙 — 에이전트가 주로 작업하는 리포

상태: 채택 · 최종수정 기준: 하네스 초기 구축

이 리포지터리는 코드 대부분을 AI 에이전트가 쓰고 검토하는 것을 전제로 한다.
사람은 의도를 밝히고 환경을 설계하고 결과를 검증하며, 실제 작업은 에이전트가 한다.

## 1. 리포에 적힌 것만 남는다

- 에이전트는 컨텍스트에 들어온 것만 안다. 결정과 배경은 반드시 리포에 문서로 남긴다.
- Slack이나 회의, 머릿속에만 있는 내용은 마크다운으로 옮겨두지 않으면 없는 것과 같다.

## 2. 지침은 목차로, 깊이는 docs로

- 거대한 지침 파일 하나를 만들지 않는다. 진입 파일은 짧은 목차로 둔다.
- 전부 중요하다고 표시하면 무엇이 중요한지 알 수 없게 된다. 핵심 제약만 항상 로드한다.

## 3. 제약이 속도를 만든다

- 경계가 분명하고 구조가 예측 가능할 때 에이전트가 가장 잘 작동한다.
- 아키텍처 불변식은 문서로 약속하지 말고 린터나 구조 테스트로 강제한다. 가능해지는 즉시 옮긴다.
- 경계는 중앙에서 정하고, 경계 안쪽은 자율에 맡긴다.

## 4. 추측하지 않는다

- 경계에서 데이터 형태를 파싱하고 검증한다(스키마 검증, DTO 등). 추측한 형태 위에 쌓지 않는다.
- 확인하지 않은 것은 단정하지 않는다. `.agents/rules/guardrails.md`와 같은 원칙이다.

## 5. 문체 취향보다 정확성

- 결과물이 정확하고 유지보수 가능하며 에이전트가 읽기 좋으면 기준을 충족한 것이다.
- 사람의 문체 취향은 리뷰나 리팩터 PR을 통해 문서와 툴링에 반영해 다음 작업부터 계속 적용되게 한다.

## 6. 작은 정리를 미루지 않는다

- 어긋난 부분과 중복은 쌓이기 전에 정리한다. 직접 만든 헬퍼보다 공유 유틸리티를 먼저 찾는다.
- 문서 정리와 품질 등급 갱신은 생각날 때가 아니라 정기 작업으로 돌린다.

## 검증 상태 표기 규칙
