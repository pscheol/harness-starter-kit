# 핵심 신념 (Core Beliefs) — 에이전트 우선 운영

상태: 채택 · 최종수정 기준: 하네스 초기 구축

이 리포지터리는 다수 코드를 AI 에이전트가 작성/검토하는 것을 전제로 한다.
사람은 의도를 명시하고, 환경을 설계하고, 결과를 검증한다. 에이전트가 수행한다.

## 1. 리포지터리가 곧 진실이다

- 에이전트는 컨텍스트에서 접근 가능한 것만 안다. 결정·맥락은 반드시 리포지터리에 문서로 남긴다.
- Slack/회의/머릿속 지식은 코드베이스에 마크다운으로 인코딩하지 않으면 존재하지 않는 것이다.

## 2. 지침은 목차로, 깊이는 docs로

- 거대한 단일 지침 파일을 만들지 않는다. 진입 파일은 짧은 map.
- "모든 것이 중요하면 아무것도 중요하지 않다." 핵심 제약만 항상 로드한다.

## 3. 제약이 속도를 만든다

- 엄격한 경계·예측 가능한 구조에서 에이전트가 가장 잘 작동한다.
- 아키텍처 불변식은 문서가 아니라 린터/구조 테스트로 강제한다(가능해지는 즉시).
- 경계는 중앙에서, 경계 안은 자율적으로.

## 4. 추측하지 않는다 (Parse, don't guess)

- 경계에서 데이터 형태를 파싱·검증한다(예: 스키마 검증/DTO). 추측한 형태로 빌드하지 않는다.
- 확인하지 않은 것은 단정하지 않는다. (`.agents/rules/guardrails.md`와 동일 원칙)

## 5. 정확성 > 사람 문체 취향

- 출력이 정확·유지보수 가능·에이전트 가독성이 좋으면 기준 충족이다.
- 사람의 취향은 리뷰/리팩터 PR로 문서·툴링에 인코딩해 복리로 적용한다.

## 6. 작은 빚을 매일 갚는다 (Garbage Collection)

- 드리프트·중복은 누적되기 전에 정리한다. 공유 유틸리티를 직접 헬퍼보다 선호한다.
- 정기 정리(doc-gardening, 품질 등급 갱신)를 프로세스로 둔다.

## 검증 상태 표기 규칙

각 design-doc 상단에 `제안 | 채택 | 폐기` 중 하나를 명시한다.
