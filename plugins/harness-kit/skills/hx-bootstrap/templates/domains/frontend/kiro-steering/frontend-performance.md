# 프론트엔드 성능 (포인터)

원본: `.agents/rules/frontend-performance.md` — 성능을 이유로 코드를 고치기 전에 연다.

요약:

- 예산이 먼저다(LCP·INP·CLS / 콜드 스타트·메모리·IPC / 번들). 설치 후 실측으로 채운다.
- **측정 없이 고치지 않는다** — 재현 → 측정 → 한 번에 하나 수정 → 재측정. 안 움직이면 되돌린다.
- 초기 번들은 첫 화면에 필요한 것만. 무거운 라이브러리는 동적 import, 스플리팅은 라우트 단위.
- 이미지에는 폭·높이를 명시한다(레이아웃 이동의 최대 원인).
- 애니메이션은 `transform`·`opacity`·`clip-path` 만. 레이아웃 속성은 매 프레임 재계산이다.
- Electron: main 프로세스를 막지 않는다. IPC 는 배치로, 큰 데이터는 통째로 넘기지 않는다.
- 예산 초과는 그 PR 의 문제다. "나중에 최적화"로 미루지 않는다.
