# ARCHITECTURE — {{PROJECT_NAME}} (Next.js App Router)

이 문서는 `{{PROJECT_NAME}}`의 **기술 아키텍처 원본**이다. 진입 가이드는 `./AGENTS.md`·`./CLAUDE.md`, 빌드·실행 상세는 `./README.md`와 `.agents/rules/tech.md`를 본다.

이 변형의 축은 디렉터리가 아니라 **서버/클라이언트 경계**다. 같은 언어로 쓰지만 두 코드는 다른 곳에서 돌고,
권한도 다르다. 경계를 흐리면 비밀이 브라우저로 새거나 서버 전용 모듈이 번들에 끌려 들어간다.

스택 기준(버전 기준은 `package.json` — 구체 버전은 **예시이며 프로젝트에서 확정**):
TypeScript(strict) · React · Next.js App Router · 서버 상태 라이브러리 · 스키마 파서 · ESLint · Prettier · 테스트 러너 · E2E.

## 0. 이 변형을 언제 쓰나 (선택 기준)

**쓴다:**
- 서버 렌더가 필요하다 — SEO, 첫 페인트, 공개 페이지.
- 데이터 접근을 서버에 두고 브라우저에 자격증명을 내리지 않고 싶다.
- 화면 단위 코드 스플리팅과 스트리밍을 프레임워크가 해 주길 원한다.
- 백엔드가 따로 있어도 **BFF 한 겹**(라우트 핸들러)이 있으면 화면이 단순해진다.

**쓰지 않는다:**
- 로그인 뒤에서만 도는 대시보드라 SEO·첫 페인트가 무의미하다 → `react-spa`(빌드·배포가 훨씬 단순하다).
- 기능 수가 많고 팀이 여럿이라 **슬라이스 경계**가 더 급하다 → `feature-sliced`.
- 정적 사이트 생성만 필요하다 → 더 가벼운 정적 생성기.

승격/전환 신호(이 중 둘 이상이면 `feature-sliced` 도입을 검토한다):
1. `src/features/` 하위가 20개를 넘고 서로를 자유롭게 import하기 시작한다.
2. "이 컴포넌트를 어디에 둬야 하나"가 리뷰마다 논쟁이 된다.
3. 공용 디렉터리(`components/`·`lib/`)가 도메인 지식을 갖기 시작한다.

경계 오류 신호(전환이 아니라 경계를 다시 그어야 한다):
- `'use client'`가 루트 레이아웃 근처로 올라간다(= 서버 컴포넌트의 이점이 사라진다).
- 서버 전용 모듈을 클라이언트에서 import해 빌드가 깨지는 일이 반복된다.

전환 절차는 §12.

## 1. 아키텍처 원칙 (요약)

| 원칙 | 강제 수단 | 위반 시 |
|---|---|---|
| 서버 전용 모듈이 클라이언트 번들에 들어가지 않는다 | `server-only` import(빌드 에러) | 빌드 실패 |
| 클라이언트 전용 모듈이 서버에서 실행되지 않는다 | `client-only` import | 빌드 실패 |

| 컴포넌트가 `fetch`를 직접 부르지 않는다 | ESLint `no-restricted-globals`·리뷰 | 게이트 차단 |
| 타입 경계 | `strict` + `noUncheckedIndexedAccess` | 타입 검사 실패 |
| 외부 응답은 스키마로 파싱 | 리뷰 + 테스트 | 리뷰 차단 |
| 접근성 기본 | `eslint-plugin-jsx-a11y` | 게이트 차단 |
| 라우트마다 렌더 모드를 명시 | 리뷰 + 주석(§5.1) | 리뷰 차단 |
| 서버 렌더 결과와 클라이언트 첫 렌더가 같다 | 빌드 경고 + E2E(§5.2) | 하이드레이션 불일치 |
| 권한은 미들웨어가 아니라 데이터 경로에서 판정 | 리뷰(§5.3) | 리뷰 차단 |
| 테스트 우선(TDD) | RED→GREEN→REFACTOR. 커버리지 ≥ 80% | 커버리지 게이트 |

- `app/`은 **라우팅과 조립**만 한다. 화면 로직은 `src/features/`, 데이터는 `src/server/`.
- 임포트 별칭 루트는 `{{PACKAGE_NS}}`(`tsconfig.json`의 paths). 상대 경로 `../../../`를 만들지 않는다.
- 테스트는 대상 옆(`*.test.ts`)에 둔다. E2E만 `e2e/`에 모은다.

### 3.1 서버/클라이언트 경계 규약 (이 변형의 핵심)

- **기본은 서버 컴포넌트**다. `'use client'`는 상호작용이 실제로 필요한 **잎 컴포넌트**에만 붙인다.
  위로 올릴수록 그 아래 전체가 클라이언트 번들에 들어간다.
- `src/server/**` 모든 진입 파일 최상단에 `import 'server-only'`를 둔다. 클라이언트가 실수로
  import하면 **빌드가 실패한다** — 이것이 이 변형에서 유일하게 컴파일 수준으로 강제되는 경계다.
- 브라우저 API(`window`·`localStorage`)를 쓰는 모듈에는 `import 'client-only'`.
- 서버 → 클라이언트로 넘기는 props는 직렬화 가능해야 한다. 함수·클래스 인스턴스·`Date` 이외의
  복합 객체를 넘기지 않는다. **엔티티를 통째로 넘기지 않는다**(내부 필드가 페이지 소스에 남는다).
- 비밀 환경변수는 서버에서만 읽는다. 공개 접두사 변수는 **번들에 인라인**된다.
- 서버 액션(있다면)은 공개 엔드포인트와 같다. **입력을 파싱하고 권한을 다시 판정한다.**

### 3.2 ESLint 경계 규칙 (골격)

```js
// eslint.config.js — 등록하지 않은 경계는 존재하지 않는 경계다.
{
  files: ['src/features/**', 'src/components/**', 'app/**'],
  rules: {
    'no-restricted-imports': ['error', {
      patterns: [
        { group: ['{{PACKAGE_NS}}/server/*'],
          message: "서버 전용 모듈이다. 서버 컴포넌트/라우트 핸들러에서만 import 한다" },
        { group: ['../../*'],
          message: '별칭({{PACKAGE_NS}}/…)을 쓴다. 깊은 상대 경로 금지' },
      ],
    }],
  },
},
{
  files: ['src/components/**'],       // 공용 UI 는 도메인을 모른다
  rules: {
    'no-restricted-imports': ['error', {
      patterns: [{ group: ['{{PACKAGE_NS}}/features/*'], message: '공용 UI 는 기능을 모른다' }],
    }],
  },
},
{
  files: ['src/lib/**'],              // 순수 유틸: 네트워크·DOM·서버 의존 금지
  rules: {
    'no-restricted-imports': ['error', {
      patterns: [{ group: ['{{PACKAGE_NS}}/server/*', '{{PACKAGE_NS}}/features/*'] }],
    }],
  },
}
```

> 위 규칙은 `app/**`에도 걸려 있다. 서버 컴포넌트에서 `src/server/*`를 쓰려면 그 파일만 예외로
> 열되(**파일 단위 override**), 예외를 늘릴 때마다 왜 필요한지 남긴다.

### 3.3 경계 검사 자동화

컴파일러가 없으므로 아래 셋을 게이트에 묶는다(`scripts/verify.sh`).

1. `tsc --noEmit` — 타입 경계.
2. `eslint` — import 방향·접근성·훅 규칙.
3. `next build` — 서버/클라이언트 혼입, 동적 import 경로, 환경변수 누락은 **빌드 때만 드러난다.**

빌드를 게이트에서 빼면 이 변형의 가장 흔한 결함이 배포까지 간다.

## 4. 데이터 접근

- **조회**: 서버 컴포넌트가 `src/server/<domain>/`의 함수를 호출한다. 컴포넌트 안에서 URL을 조립하지 않는다.
- **변경**: 라우트 핸들러 또는 서버 액션. 클라이언트는 그 엔드포인트만 호출한다.
- **클라이언트 조회**가 필요한 화면(무한 스크롤·실시간 필터)은 서버 상태 라이브러리를 쓴다.
  응답은 스키마로 파싱하고, 캐시 키에 **사용자 스코프**를 포함한다(`.agents/rules/api-standards.md`).
- 외부 응답 → 화면 모델 변환은 `src/server/` 또는 기능의 스키마 파일에서 한 번만 한다.
- 서버·클라이언트 양쪽에서 쓰는 타입은 `src/features/<f>/schema.ts`에 두고 **런타임 파서와 타입을 함께** 내보낸다.

## 5. 렌더 전략(SSR) · 하이드레이션 · 미들웨어 · 캐시

원본 규약은 `.agents/rules/guardrails.md`의 "서버 렌더링(SSR)과 하이드레이션" 절이다.
여기서는 이 변형에서 **실제로 어디에 무엇을 쓰는지**를 정한다.

### 5.1 라우트마다 렌더 모드를 명시한다

| 모드 | 이 리포에서의 위치 | 쓰는 곳 |
|---|---|---|
| 정적 생성 | 기본. 동적 함수를 쓰지 않으면 이 모드가 된다 | 공개 페이지·문서·마케팅 |
| 서버 렌더(요청마다) | 쿠키·헤더·검색 파라미터를 읽는 순간 전환된다 | 인증 화면·개인화 목록 |
| 증분 재검증 | 재검증 주기 또는 태그 지정 | 상품·게시글처럼 가끔 바뀌는 공개 데이터 |
| 클라이언트 렌더 | `'use client'` + 서버 상태 라이브러리 | 무한 스크롤·실시간 필터·에디터 |

- **모드를 명시적으로 선언하고 근거를 한 줄 주석으로 남긴다.** 기본값이 조용히 바뀌는 것이 이 변형에서
  가장 흔한 성능·정합성 사고다(동적 함수 하나를 추가했더니 페이지 전체가 요청마다 렌더된다).
- 사용자별 데이터가 있는 라우트를 정적으로 두지 않는다. 다른 사용자에게 캐시된 화면이 나간다.
- 재검증 주기·태그는 **한 곳에 상수로** 모은다. 화면마다 다른 숫자를 흩지 않는다.
- 변경 후 무엇을 무효화하는지 코드에서 읽혀야 한다.

### 5.2 하이드레이션 — 서버 결과와 클라이언트 첫 렌더가 같아야 한다

서버 컴포넌트는 하이드레이션 대상이 아니지만, `'use client'` 경계 **아래**는 전부 대상이다.
그 안에서 아래를 하면 마크업이 어긋나 React가 다시 그린다.

- 렌더 중 `Date.now()`·`new Date()`·`Math.random()` — 시각은 서버에서 계산해 props로 내리고,
  상대 시간("3분 전")은 마운트 후에 갱신한다.
- 렌더 중 `window`·`localStorage`·`matchMedia` — 서버에는 없다. effect로 미룬다.
- `typeof window !== 'undefined'` 분기로 다른 마크업 그리기 — 초기 마크업은 양쪽이 같아야 한다.
- 테마·언어 같은 초기 설정을 브라우저 저장소에서 읽어 초기 상태로 쓰기 — 서버가 아는 값(쿠키·헤더)으로
  내려 주거나, 첫 렌더는 중립값으로 그리고 마운트 후 전환한다.

`suppressHydrationWarning`은 국소적이고 원인이 분명할 때만. 왜 안전한지 주석을 남긴다.

### 5.3 미들웨어는 UX다, 접근 제어가 아니다

- 미들웨어에서 세션을 확인해 리다이렉트하더라도 **라우트 핸들러·서버 액션·`src/server/` 함수에서
  권한을 다시 판정한다.** 미들웨어는 매처에서 빠진 경로를 놓친다.
- 매처는 좁게 잡는다. 정적 자산·이미지 최적화 경로까지 통과시키면 모든 요청이 느려진다.
- 미들웨어에서 DB 조회·외부 호출을 하지 않는다. 쿠키 존재 확인 수준까지만.
- 미들웨어는 응답 헤더·리다이렉트까지만 다룬다. 본문을 다시 쓰지 않는다.

### 5.4 스트리밍

- `loading.tsx` + Suspense는 **느린 부분만** 감싼다. 페이지 전체를 감싸면 스트리밍의 이점이 없다.
- 스켈레톤 크기를 최종 레이아웃과 맞춘다. 다르면 화면이 튀고 CLS 예산이 깨진다.

---

## 6. 코드 주석 규약 (요약)

- 주석은 기본이 '없음'이다. Why · 함정 · 외부 근거 · 억제 이유만 적는다.
- **`'use client'`를 붙였다면 왜 필요한지** 한 줄을 남긴다(무엇이 상호작용을 요구하는가).
- 렌더 전략·재검증 값에는 근거를 남긴다.
- effect의 정리 대상, 의존성 배열에서 뺀 값의 안전성 근거를 적는다.
- 한국어로 작성한다. 원본·Bad/Good 예시: `.agents/rules/code-comments.md`.

## 7. 상수·설정 외부화 (매직 리터럴 금지)

| 계층 | 무엇 | 위치/수단 |
|---|---|---|
| (a) 디자인 값 | 색·간격·타이포·모션·z-index | 토큰(`src/styles/`) — `.agents/rules/design-system.md` |
| (b) 도메인 상수 | 상태 라벨·역할·정렬 키 | 기능의 `constants.ts`(타입 있는 상수) |
| (c) 환경별 설정 | API 베이스·기능 플래그 | 서버는 `src/server/config`, 공개 값만 공개 접두사 변수 |
| (d) 게이트 값 | 재검증 주기·페이지 크기·타임아웃 | 이름 있는 상수 한 곳 |

- 비밀은 `src/server/config`에서만 읽는다. 공개 접두사 변수에 비밀을 넣지 않는다.
- 환경변수는 **시작 시 스키마로 검증**한다. 누락을 런타임 500이 아니라 기동 실패로 만든다.

## 8. 성능 예산

- 예산 표와 측정 절차의 원본은 `.agents/rules/frontend-performance.md`다. 여기서는 이 변형 고유의 것만 적는다.
- `'use client'` 경계가 곧 번들 경계다. 클라이언트 컴포넌트에서 무거운 라이브러리를 정적 import하면
  그 화면 전체가 무거워진다 — 동적 import로 내린다.
- 서버 컴포넌트에서의 데이터 요청은 **병렬화**한다. 순차 `await`가 그대로 응답 지연이 된다.
- 이미지에 폭·높이를 준다. 폰트는 필요한 굵기만 서브셋으로.
- 번들 분석을 CI에 붙여 회귀를 잡는다.

## 9. TDD 워크플로 (요약)

```
RED   행위 1개에 대한 실패 테스트
GREEN 최소 구현으로 통과
REFACTOR 중복 제거·의도 드러내기
```

| 대상 | 도구 | 비고 |
|---|---|---|
| 순수 로직(`src/lib`) | 테스트 러너 | DOM 없음. 가장 빠르고 가장 많이 |
| 스키마·매핑 | 테스트 러너 | 잘못된 응답이 에러가 되는지 |
| 훅·클라이언트 컴포넌트 | 테스트 러너 + 렌더 유틸 | **사용자가 보는 것**으로 단언 |
| 서버 함수(`src/server`) | 테스트 러너 | 외부는 요청 가로채기로 고정 |
| 라우트 핸들러 | 테스트 러너 | 입력 파싱·권한·오류 형태 |
| 화면 흐름 | E2E | 핵심 경로 1개 이상 |

- 네트워크는 **요청 수준에서** 고정한다(모듈 목 남발 금지).
- 검증 게이트: `bash scripts/verify.sh`(CI·pre-commit·hook이 모두 이 스크립트를 호출).

---

## 10. 새 화면 추가 워크플로

1. **라우트 결정**: URL이 곧 구조다. 공유·새로고침·뒤로가기가 살아야 하는 값은 경로·쿼리에 둔다.
2. `app/<route>/page.tsx`(서버) + `loading.tsx` + `error.tsx`(클라이언트)를 함께 만든다.
   **네 상태(loading·empty·error·partial)를 처음부터** 만든다.
3. 데이터는 `src/server/<domain>/`에 함수로 추가한다. 컴포넌트에서 직접 조회하지 않는다.
4. 상호작용이 필요한 부분만 `src/features/<f>/`의 클라이언트 컴포넌트로 분리한다.
5. 공용으로 올릴 UI가 있으면 먼저 Inventory(`.agents/rules/reuse-before-new.md`).
6. **검증**: `bash scripts/verify.sh` 통과 + 화면 명세 갱신 + 키보드/대비 확인.

## 11. Anti-pattern (코드리뷰 즉시 차단)

- 루트 레이아웃·상위 컴포넌트에 `'use client'`를 붙여 트리 전체를 클라이언트로 만들기.
- `src/server/*`를 클라이언트 컴포넌트에서 import(그리고 `server-only`를 빼서 빌드를 통과시키기).
- 공개 접두사 환경변수에 비밀 넣기.
- 서버에서 엔티티를 통째로 클라이언트 props로 넘기기.
- 컴포넌트 안에서 `fetch` + URL 문자열 조립.
- 응답을 `as`로 단정하거나 `any`로 받기.
- 사용자별 데이터가 있는 라우트를 정적으로 두기.
- 라우트 핸들러·서버 액션에서 권한 재판정 생략(화면이 이미 확인했다고 가정).
- **미들웨어에서 인증을 확인했으니 됐다고 보고 데이터 경로의 권한 판정을 빼기.**
- 클라이언트 컴포넌트 렌더 중 `Date.now()`·`Math.random()`·`window`·`localStorage` 사용(하이드레이션 불일치).
- `typeof window` 분기로 서버와 다른 초기 마크업 그리기.
- 하이드레이션 경고를 `suppressHydrationWarning`으로 덮고 원인을 안 찾기.
- 렌더 모드를 명시하지 않아 동적 함수 하나로 페이지 전체가 요청마다 렌더되는 상태를 방치.
- 미들웨어 매처를 넓게 잡아 정적 자산까지 통과시키거나 그 안에서 DB를 조회하기.
- 측정 없이 `memo`·`useMemo`·`useCallback`을 습관적으로 붙이기.
- `error.tsx`에 원인 문자열만 표시하고 다음 행동을 주지 않기.
- `loading.tsx` 스켈레톤 크기가 최종 레이아웃과 달라 화면이 튀기.
- 모듈 최상위에 가변 캐시를 두기(요청 간 공유 → 사용자 데이터 혼선).
- 새 경계를 만들고 ESLint 규칙에 등록하지 않기.

## 12. 다른 변형으로 전환하기

| 목표 | 디렉터리 이동 | 강제 규칙 교체 지점 |
|---|---|---|
| → `feature-sliced` (기능이 많아질 때) | `src/features/<f>`를 FSD 슬라이스로 승격하고 각 슬라이스에 `index.ts` 공개 API를 만든다. `src/components`→`shared/ui`, `src/lib`→`shared/lib`, `app/` 라우트는 `pages` 계층을 얇게 감싼다. | `no-restricted-imports` 를 계층 방향 규칙(위→아래)으로 교체하고 슬라이스 내부 직접 import 금지를 추가 |
| → `react-spa` (서버 렌더가 불필요해질 때) | `app/`을 라우터 선언 한 곳으로 접고, `src/server/`의 데이터 함수를 API 클라이언트 호출로 바꾼다. 비밀에 접근하던 경로는 **백엔드로 옮긴다**(이게 전환의 본체다). | `server-only` 규칙 제거. 대신 "API 클라이언트 경유" 규칙을 강화 |

- 전환 전에 `.agents/docs/decisions/`에 ADR을 남긴다(왜 옮기는지·되돌릴 조건).
- 한 번에 한 라우트씩 옮기고 각 단계마다 `scripts/verify.sh`를 통과시킨다.
