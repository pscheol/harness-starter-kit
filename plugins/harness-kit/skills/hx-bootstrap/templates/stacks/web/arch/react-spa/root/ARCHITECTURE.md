# ARCHITECTURE — {{PROJECT_NAME}} (React SPA)

이 문서는 `{{PROJECT_NAME}}`의 **기술 아키텍처 원본**이다. 진입 가이드는 `./AGENTS.md`·`./CLAUDE.md`, 빌드·실행 상세는 `./README.md`와 `.agents/rules/tech.md`를 본다.

서버 렌더가 없는 단일 페이지 앱이다. 서버가 없으므로 **모든 코드가 브라우저에 있고, 모든 데이터는 API에서 온다.**
이 변형에서 구조를 지탱하는 축은 둘이다 — **라우팅 선언 한 곳**과 **서버 상태/클라이언트 상태 분리**.

스택 기준(버전 기준은 `package.json` — 구체 버전은 **예시이며 프로젝트에서 확정**):
TypeScript(strict) · React · Vite 등 번들러 · 클라이언트 라우터 · 서버 상태 라이브러리 · 스키마 파서 · ESLint · Prettier · 테스트 러너 · E2E.

## 0. 이 변형을 언제 쓰나 (선택 기준)

**쓴다:**
- 로그인 뒤에서 도는 앱이다. SEO·첫 페인트가 제품 가치의 핵심이 아니다.
- 백엔드 API가 이미 있고 프론트는 그것을 소비한다.
- 배포가 정적 파일 업로드로 끝나길 원한다(서버 런타임 운영 부담 0).
- 화면 간 상태 유지·즉각적인 전환이 중요하다(대시보드·에디터·콘솔).

**쓰지 않는다:**
- 공개 페이지의 검색 노출·첫 페인트가 중요하다 → `nextjs-app`.
- 브라우저에 내릴 수 없는 자격증명으로 외부 API를 호출해야 한다 → 서버 경로가 필요하다(`nextjs-app` 또는 별도 BFF).
- 기능 수가 많고 팀이 여럿이라 슬라이스 경계가 급하다 → `feature-sliced`.

승격 신호(이 중 둘 이상이면 `feature-sliced` 전환을 검토한다):
1. `src/features/` 하위가 15~20개를 넘고 서로를 자유롭게 import한다.
2. 공용 디렉터리(`components/`·`lib/`)가 도메인 지식을 갖기 시작한다.
3. 두 팀이 같은 파일을 자주 충돌시킨다.

경계 오류 신호(전환이 아니라 경계를 다시 그어야 한다):
- 라우트 선언이 여러 파일에 흩어져 어디서 코드 스플리팅이 일어나는지 아무도 모른다.
- 서버에서 온 데이터를 클라이언트 스토어에 복사한 뒤 무효화 코드를 손으로 쓰고 있다.

전환 절차는 §12.

- 정적 호스팅은 **모든 경로를 `index.html`로 폴백**해야 한다. 이 설정이 없으면 새로고침이 404가 된다.

- `pages/`는 **조립만** 한다. 화면 로직이 길어지면 `features/`로 내린다.
- `api/`가 네트워크의 유일한 출입구다. 컴포넌트에서 `fetch`를 부르지 않는다.
- 임포트는 별칭(`{{PACKAGE_NS}}/…`)으로 한다. `../../../`가 나오면 위치가 잘못된 것이다.

### 3.1 라우팅 단일 지점 (이 변형의 핵심)

```tsx
// src/app/routes.tsx — 라우트는 여기서만 선언한다.
const {{DOMAIN_EXAMPLE}}Page = lazy(() => import('{{PACKAGE_NS}}/pages/{{DOMAIN_EXAMPLE}}'));
```

- 라우트를 화면 곳곳에서 선언하면 **어디서 청크가 갈라지는지 아무도 모르게 된다.** 한 곳에 모은다.
- 라우트 단위 지연 로드가 기본 스플리팅 지점이다. 첫 진입 화면만 정적으로 둔다.
- URL이 상태다: 필터·정렬·페이지·탭·검색어는 쿼리스트링에 둔다(`.agents/rules/ui-state.md`).
- 라우트 가드는 **화면 접근을 정리하는 UX**다. 서버 권한 판정을 대체하지 않는다.
- 라우트 전환 실패(지연 로드 청크 404)를 처리한다. 배포 직후 구버전 청크가 사라져 자주 발생하고,
  이때 필요한 것은 재시도가 아니라 **새로고침**이다(`.agents/rules/reliability.md`).

### 3.3 경계 검사 자동화

컴파일러가 없으므로 아래 셋을 게이트에 묶는다(`scripts/verify.sh`).

1. `tsc --noEmit` — 타입 경계.
2. `eslint` — import 방향·접근성·훅 규칙.
3. 프로덕션 빌드 — 동적 import 경로·환경변수 누락은 빌드에서만 드러난다.

### 3.4 SSR·프리렌더가 필요해지면

이 변형은 **기본이 클라이언트 렌더**다. 서버 렌더가 필요해지는 이유는 대개 셋 중 하나다 —
검색 노출, 첫 페인트, 브라우저에 내릴 수 없는 자격증명. **어느 쪽이 이유인지 먼저 확정한다.**
이유에 따라 답이 다르고, 가장 비싼 답을 먼저 고르는 실수가 흔하다.

| 이유 | 가장 싼 답 | 그것으로 안 될 때 |
|---|---|---|
| 공개 페이지 몇 개의 SEO·첫 페인트 | **빌드 시 프리렌더**(정적 생성). 앱은 그대로 SPA로 둔다 | 페이지가 많거나 자주 바뀌면 아래로 |
| 로그인 전 화면 전체의 SEO·첫 페인트 | 번들러/라우터의 **SSR 모드**를 얹는다(서버 런타임이 생긴다) | 라우팅·데이터 규약을 프레임워크에 맡기고 싶으면 `nextjs-app` 전환 |
| 브라우저에 내릴 수 없는 비밀 | **백엔드 또는 BFF 한 겹.** 프론트 렌더 방식과 무관한 문제다 | — |

SSR을 얹기로 했다면 그 순간부터 **서버·클라이언트 두 번 실행**이 전제가 된다. 원본 규약은
`.agents/rules/guardrails.md`의 "서버 렌더링(SSR)과 하이드레이션" 절이고, 이 변형에서 특히 걸리는 것은:

- **모듈 최상위 상태** — SPA에서는 탭 하나가 곧 프로세스라 안전했다. 서버에서는 요청 간에 공유되어
  **다른 사용자 데이터가 섞인다.** `api/` 클라이언트의 토큰 캐시, 전역 스토어 싱글턴이 대표적이다.
- **`app/providers.tsx`** — 프로바이더에 브라우저 전용 초기화가 들어 있으면 서버에서 터진다.
- **초기 상태** — 브라우저 저장소에서 읽어 스토어를 초기화하던 코드가 하이드레이션 불일치를 만든다.
  서버가 아는 값으로 내리거나 마운트 후 적용으로 바꾼다.
- **`index.html` 폴백 전제** — 정적 호스팅 폴백이 서버 라우팅으로 바뀐다. 배포 구성이 함께 바뀐다.

**서버 런타임이 생기면 운영 부담이 함께 생긴다.** 정적 파일 업로드로 끝나던 배포가 아니게 되므로,
프리렌더로 해결되는 문제라면 거기서 멈춘다. 전환 판단은 §12.

## 4. 데이터 접근

- `src/api/`가 **네트워크의 유일한 출입구**다: 베이스 URL·인증 헤더·타임아웃·에러 매핑을 여기서 한 번만 한다.
- 엔드포인트 문자열은 `api/endpoints.ts` 한 곳에. 응답은 `api/<domain>/schema.ts`에서 파싱한다.
- 서버 상태는 **쿼리 라이브러리가 소유**한다. 응답을 클라이언트 스토어로 복사하지 않는다.
  캐시 키에 **사용자 스코프**를 포함한다(빠지면 계정 전환 시 이전 데이터가 남는다).
- 클라이언트 상태는 지역 상태가 기본. 전역은 "여러 화면이 동시에 읽고 쓴다"일 때만 승격한다.
- 인증 토큰 갱신은 클라이언트 한 곳에서 **한 번만** 수행하고 나머지 요청은 그 결과를 기다린다.
- 상세 규약은 `.agents/rules/api-standards.md`.

## 5. 앱 셸 · 전역 관심사

- 프로바이더 조립은 `app/providers.tsx` 한 곳. 화면에서 프로바이더를 새로 만들지 않는다.
- 전역 에러 경계는 앱 셸에, **영역별 에러 경계는 의미 있는 단위마다** 둔다. 하나만 두면 위젯 하나가
  전체 화면을 날린다(`.agents/rules/reliability.md`).
- 인증 상태는 한 곳에서 관리하고 401 처리(현재 위치 기억 → 재인증 → 복귀)를 그 한 곳에 둔다.
- 전역 토스트·모달 같은 오버레이는 앱 셸이 소유하고 층 순서를 토큰으로 관리한다.

## 7. 상수·설정 외부화 (매직 리터럴 금지)

| 계층 | 무엇 | 위치/수단 |
|---|---|---|
| (a) 디자인 값 | 색·간격·타이포·모션·z-index | 토큰(`src/styles/`) — `.agents/rules/design-system.md` |
| (b) 도메인 상수 | 상태 라벨·역할·정렬 키 | 기능의 `constants.ts` |
| (c) 환경별 설정 | API 베이스·기능 플래그 | 빌드 시 주입되는 환경변수(**전부 공개**) |
| (d) 게이트 값 | 캐시 수명·페이지 크기·타임아웃·재시도 | 이름 있는 상수 한 곳 |

- **환경변수는 전부 번들에 인라인된다.** 비밀을 넣지 않는다. 비밀이 필요한 호출은 백엔드가 한다.
- 환경변수는 앱 시작 시 스키마로 검증하고 한 모듈에서만 읽는다.

## 8. 성능 예산

- 예산 표와 측정 절차의 원본은 `.agents/rules/frontend-performance.md`다. 여기서는 이 변형 고유의 것만 적는다.
- SPA는 **첫 진입 번들이 곧 첫 화면 시간**이다. 라우트 지연 로드를 빠뜨리면 예산이 즉시 깨진다.
- 공통 청크에 무거운 라이브러리가 들어가지 않게 번들 분석으로 확인한다.
- 목록이 길어지면 가상화. 단, 실제로 길어진 뒤에.
- 데이터 재조회 정책(포커스 복귀·주기적 갱신)을 의식적으로 정한다. 기본값이 배터리와 API 비용을 먹는다.

## 9. TDD 워크플로 (요약)

| 대상 | 도구 | 비고 |
|---|---|---|
| 순수 로직(`src/lib`) | 테스트 러너 | DOM 없음. 가장 빠르고 가장 많이 |
| 스키마·매핑(`src/api`) | 테스트 러너 | 잘못된 응답이 에러가 되는지 |
| 훅·컴포넌트 | 테스트 러너 + 렌더 유틸 | **사용자가 보는 것**으로 단언 |
| 라우팅·가드 | 테스트 러너(메모리 라우터) | 미인증 진입·복귀 경로 |
| 화면 흐름 | E2E | 핵심 경로 1개 이상 |

- 네트워크는 **요청 수준에서** 고정한다(모듈 목 남발 금지).
- 검증 게이트: `bash scripts/verify.sh`(CI·pre-commit·hook이 모두 이 스크립트를 호출).

## 10. 새 화면 추가 워크플로

1. **라우트 결정** — URL이 곧 구조다. 공유·새로고침·뒤로가기가 살아야 하는 값은 쿼리에 둔다.
2. `app/routes.tsx`에 지연 로드로 등록한다(다른 곳에서 선언하지 않는다).
3. `pages/<route>/`에 화면을 만들고 **네 상태(loading·empty·error·partial)를 처음부터** 만든다.
4. 데이터는 `api/<domain>/`에 함수·스키마로 추가하고 기능 훅에서 호출한다.
5. 공용으로 올릴 UI가 있으면 먼저 Inventory(`.agents/rules/reuse-before-new.md`).
6. **검증**: `bash scripts/verify.sh` 통과 + 화면 명세 갱신 + 키보드·대비 확인.

## 11. Anti-pattern (코드리뷰 즉시 차단)

- 라우트를 `app/routes.tsx` 밖에서 선언(스플리팅 지점 분산).
- 컴포넌트에서 `fetch` 직접 호출·엔드포인트 문자열 하드코딩.
- 서버 응답을 클라이언트 스토어에 복사하고 무효화를 손으로 관리.
- 캐시 키에 사용자 스코프 누락(계정 전환 시 이전 데이터 노출).
- 응답을 `as`로 단정하거나 `any`로 받기.
- 공용 컴포넌트가 도메인 타입·API를 import.
- 환경변수에 비밀 넣기(번들에 그대로 실린다).
- 라우트 가드를 접근 제어로 착각하고 서버 권한 판정을 생략.
- 앱 전체에 에러 경계 하나만 두기.
- 전역 상태를 기본값으로 쓰기(지역 상태로 되는 것을 스토어에 올리기).
- 지연 로드 청크 404(배포 직후) 처리 누락.
- 정적 호스팅 폴백 설정 누락으로 새로고침이 404가 되는 상태 방치.
- 측정 없이 `memo`·`useMemo`·`useCallback`을 습관적으로 붙이기(비교 비용만 늘고 원인은 그대로).
- 목록 `key`에 배열 인덱스 사용(정렬·필터 후 입력 상태와 포커스가 엉뚱한 행에 남는다).
- **SSR·프리렌더를 얹으면서 모듈 최상위 가변 상태를 그대로 두기**(요청 간 공유 → 사용자 데이터 혼선).
- SSR 도입 이유(SEO·첫 페인트·비밀)를 확정하지 않고 프레임워크부터 고르기.

## 12. 다른 변형으로 전환하기

| 목표 | 디렉터리 이동 | 강제 규칙 교체 지점 |
|---|---|---|
| → `feature-sliced` (기능이 많아질 때) | `pages/`는 그대로 `pages` 계층이 되고, `features/`를 슬라이스로 승격해 각각 `index.ts` 공개 API를 만든다. `components`·`hooks`·`lib`·`api`는 `shared/{ui,lib,api}`로 내린다. 여러 기능을 조합한 덩어리는 `widgets`로 올린다. | `no-restricted-imports` 를 계층 방향 규칙으로 교체 + 슬라이스 내부 직접 import 금지 추가 |
| → `nextjs-app` (서버 렌더·서버 비밀이 필요해질 때) | `app/routes.tsx`를 파일 기반 라우팅으로 펼치고, `api/`의 호출 중 **비밀이 필요한 것만** `src/server/`로 옮긴다. 나머지는 그대로 클라이언트에 남는다. | `server-only` 규칙 도입 + 서버/클라이언트 경계 규칙 추가 |

- 전환 전에 `.agents/docs/decisions/`에 ADR을 남긴다(왜 옮기는지·되돌릴 조건).
- 한 번에 한 라우트씩 옮기고 각 단계마다 `scripts/verify.sh`를 통과시킨다.
