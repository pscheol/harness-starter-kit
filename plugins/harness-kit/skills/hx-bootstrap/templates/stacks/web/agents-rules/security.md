# 보안 가드레일 — {{PROJECT_NAME}}

이 규칙 위반은 **코드리뷰 즉시 차단 대상**이다. 일정·성능보다 우선한다.
프로젝트 고유의 권한 모델은 여기가 아니라 `product.md`와 설계 문서에서 정한다.
이 파일은 **어느 웹 프로젝트에서나 지켜야 하는 최소 방어선**만 규정한다.

## 대전제 — 클라이언트는 신뢰 경계 밖이다

브라우저에서 도는 코드는 사용자가 읽고 고칠 수 있다. 그래서 다음이 따라온다.

- **클라이언트의 검증은 UX이지 보안이 아니다.** 권한·한도·가격은 서버가 다시 판정한다.
- 화면에서 버튼을 숨기는 것은 접근 제어가 아니다. 숨겨도 API는 호출된다.
- 번들에 들어간 것은 공개된 것이다. 비밀·내부 엔드포인트·주석에 남긴 힌트 모두.

## XSS (최우선)

- **사용자 입력을 HTML로 주입하지 않는다.** 프레임워크의 기본 이스케이프를 우회하는 API
  (`dangerouslySetInnerHTML`·`v-html`·`innerHTML`)를 기본으로 쓰지 않는다.
- 불가피하면 **검증된 정제 라이브러리로 정제한 값만** 넣고, 왜 필요한지 주석으로 남긴다.
  자체 정규식 필터를 만들지 않는다(우회 사례가 계속 나온다).
- 사용자 입력을 URL로 쓸 때 **스킴을 검사**한다. `javascript:`·`data:`가 `href`·`src`에 들어가면 실행된다.
- `eval`·`new Function`·문자열 `setTimeout`을 쓰지 않는다.
- 마크다운 렌더링은 raw HTML 허용을 끈 상태가 기본이다.
- 서버가 만든 HTML/JSON에 사용자 값을 끼워 넣을 때는 컨텍스트에 맞게 인코딩한다(HTML·속성·JS·URL이 각각 다르다).

## CSP · 보안 헤더

운영 환경에 CSP를 설정한다. 없으면 XSS 한 건이 곧바로 전면 침해가 된다.

- `script-src`에 `'unsafe-inline'`·`'unsafe-eval'`을 넣지 않는다. 인라인 스크립트가 필요하면 **nonce**를 쓴다.
- `object-src 'none'` · `base-uri 'self'` · `frame-ancestors`(클릭재킹 차단)를 함께 건다.
- 그 밖에 최소 세트: `Strict-Transport-Security` · `X-Content-Type-Options: nosniff` ·
  `Referrer-Policy: strict-origin-when-cross-origin` · `Permissions-Policy`(안 쓰는 기능은 끈다).
- 배포 시 헤더가 실제로 붙는지 확인한다. 설정 파일에만 있고 응답에 없는 경우가 흔하다.

## 인증 토큰 보관

- **httpOnly + Secure + SameSite 쿠키가 기본**이다. 스크립트가 못 읽어야 XSS가 곧 계정 탈취로 이어지지 않는다.
- `localStorage`·`sessionStorage`에 토큰을 두는 방식은 XSS 한 건에 전부 노출된다. 채택하려면
  왜 쿠키가 불가능한지를 설계 문서에 근거로 남긴다.
- 쿠키 인증이면 **CSRF 방어**가 필요하다: `SameSite=Lax|Strict` + 상태 변경 요청에 CSRF 토큰(또는 origin 검사).
- 로그아웃은 서버 세션·토큰을 무효화한다. 클라이언트 저장소만 비우는 것은 로그아웃이 아니다.
- 토큰·세션 식별자를 URL 쿼리에 싣지 않는다(리퍼러·로그·히스토리에 남는다).

## 비밀은 클라이언트에 없다

- 공개 접두사 환경변수(`NEXT_PUBLIC_`·`VITE_` 등)는 **빌드 시 번들에 인라인된다.** API 키·서명 키·
  DB 자격증명을 넣지 않는다. 넣었다면 그 키는 유출된 것으로 보고 교체한다.
- 서드파티 자격증명이 필요한 호출은 서버 경로(라우트 핸들러·BFF)를 거친다.
- 소스맵을 운영에 공개하면 내부 로직·주석이 그대로 노출된다. 공개 여부를 의식적으로 정한다.
- 서버에서 클라이언트로 넘기는 데이터는 **직렬화되어 HTML에 실린다.** 사용자에게 보여줄 필드만 골라
  넘긴다. 엔티티를 통째로 넘기면 내부 필드(해시·내부 메모·타 사용자 정보)가 페이지 소스에 남는다.

## 리다이렉트 · 외부 링크 · 프레임

- **오픈 리다이렉트**: 쿼리로 받은 `next`·`returnUrl`로 이동하기 전에 **같은 오리진인지** 검증한다.
  `startsWith("/")`만으로는 부족하다(`//evil.com`은 프로토콜 상대 URL이다).
- `target="_blank"` 링크에는 `rel="noopener noreferrer"`.
- `postMessage`는 **보내는 쪽에서 targetOrigin을 명시**하고, 받는 쪽에서 `event.origin`을 검증한다.
  `"*"`로 보내거나 origin 검사 없이 받으면 임의 페이지가 대화 상대가 된다.
- iframe으로 외부 콘텐츠를 넣을 때는 `sandbox` 속성으로 권한을 최소화한다.

## 서드파티 · 의존성

- 서드파티 스크립트는 **넣기 전에 무엇을 수집하는지** 확인하고 목록으로 관리한다. 태그 매니저는
  누구나 임의 스크립트를 넣을 수 있는 경로임을 인지한다.
- CDN에서 스크립트를 받으면 SRI(`integrity`)를 건다. 중요한 의존성은 자체 호스팅을 검토한다.
- 락파일을 커밋한다. 설치는 락 기준 재현 설치(`--frozen-lockfile`)로 한다.
- 알려진 취약점 스캔을 정기적으로 돌린다. `postinstall` 스크립트를 실행하는 새 의존성은 검토 대상이다.

## 입력 · 출력

- 파일 업로드는 확장자가 아니라 **서버에서** 타입·크기를 검증한다. 클라이언트 검증은 사용성용이다.
- 사용자 콘텐츠를 같은 오리진에서 서빙하지 않는다(업로드된 HTML이 곧 XSS가 된다).
- 에러 화면에 스택 트레이스·내부 경로·쿼리를 노출하지 않는다.
- 로그·모니터링 전송에 개인정보·토큰·요청 본문 전체를 담지 않는다. 필드를 골라 보낸다.
- 자동완성이 민감한 필드(일회용 코드 등)에는 `autocomplete`를 의식적으로 설정한다.

## 라우트 핸들러 · 서버 경로를 만들 때

프론트엔드 리포에 서버 실행 경로(라우트 핸들러·BFF·서버 액션)가 있다면 그 부분은 백엔드다.

- **인증·인가를 그 경로에서 다시 판정한다.** 화면이 이미 확인했다는 전제를 두지 않는다.
- 입력을 스키마로 파싱한다. 클라이언트가 보낸 값은 어떤 형태로도 올 수 있다.
- 사용자 입력으로 외부 URL을 호출하지 않는다(SSRF). 필요하면 allowlist로 좁힌다.
- 파일 경로를 사용자 입력으로 조립하지 않는다(경로 순회).
- 응답에 내부 오류 메시지를 그대로 싣지 않는다.
