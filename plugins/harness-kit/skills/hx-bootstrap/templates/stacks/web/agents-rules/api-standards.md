# API 연동 표준 — {{PROJECT_NAME}}

프론트엔드에서 **API를 소비하는** 규약이다. 이 리포에 서버 경로(라우트 핸들러·BFF)가 있다면
그 경로를 **제공하는** 규약은 마지막 절에 있다.

## 호출은 한 계층에서만 한다

- 컴포넌트에서 직접 `fetch`하지 않는다. **데이터 접근 계층**(API 클라이언트 + 서버 상태 훅)을 경유한다.
  위치는 변형마다 다르므로 [`structure.md`](./structure.md)·`ARCHITECTURE.md`가 원본이다.
- 엔드포인트 문자열을 화면에 흩지 않는다. 경로는 한 파일에 모으고 함수로 노출한다.
- 인증 헤더·기본 헤더·베이스 URL 주입은 **클라이언트 한 곳**에서 한다. 호출마다 헤더를 손으로 붙이면
  언젠가 빠진 곳이 생기고, 그 한 곳이 401을 낸다.
- 서버 상태는 쿼리 라이브러리가 소유한다. 응답을 클라이언트 스토어로 복사하지 않는다([`ui-state.md`](./ui-state.md)).

## 경계에서 파싱한다 (Parse, don't assume)

- 응답은 **스키마로 파싱**해 타입을 좁힌 뒤 안으로 넘긴다. `as`로 단정하거나 `any`로 받지 않는다.
- 타입 선언은 계약이 아니라 주장이다. 런타임 파싱이 없으면 서버가 필드를 바꾼 날 화면이 조용히 깨진다.
- 파싱 실패는 **에러로 다룬다.** 필드가 없다고 `undefined`로 흘려보내면 실패 지점이 화면 깊숙한 곳으로 밀린다.
- 응답 DTO를 화면까지 그대로 끌고 가지 않는다. 화면이 쓰는 모델로 한 번 변환한다(서버 필드명 변경이
  컴포넌트를 건드리지 않게 된다).
- 날짜·금액은 파싱 시점에 타입을 정한다. 문자열 그대로 비교·계산하지 않는다.

## 에러 처리

- HTTP status를 **화면이 다룰 수 있는 종류**로 한 곳에서 매핑한다.

| 상황 | 화면 처리 |
|---|---|
| 401 인증 만료 | 재인증 흐름으로 보낸다(현재 위치를 기억) |
| 403 권한 없음 | 권한 없음 화면. 재시도 버튼을 주지 않는다 |
| 404 없음 | 빈 상태가 아니라 "없음" 화면 |
| 409/422 검증·충돌 | 필드 단위 메시지로 폼에 되돌린다 |
| 429 한도 | 재시도 시점을 안내한다 |
| 5xx·네트워크 | 재시도 가능한 에러 화면 |

- **에러 메시지를 서버 응답 그대로 사용자에게 노출하지 않는다.** 코드로 매핑한 문구를 쓰고,
  원문은 로그·모니터링으로 보낸다.
- 백엔드가 공통 envelope(`code`·`message`·`request_id`)를 쓴다면 `code`로 분기하고 `request_id`를
  에러 화면·로그에 남긴다. 문의 대응 비용이 크게 줄어든다.
- 에러를 삼키지 않는다. `catch`에서 아무것도 하지 않는 코드는 리뷰에서 막는다.

## 취소 · 레이스

- 사용자가 화면을 떠나거나 입력을 바꾸면 이전 요청은 **취소한다**(`AbortSignal`).
- 취소하지 않으면 늦게 온 이전 응답이 최신 결과를 덮어쓴다. 검색·필터 화면에서 특히 자주 난다.
- 검색어 입력처럼 연속 발생하는 요청은 디바운스 + 취소를 함께 쓴다.
- 취소로 인한 실패(`AbortError`)를 에러 화면으로 표시하지 않는다. 정상 흐름이다.

## 타임아웃 · 재시도

- 모든 요청에 타임아웃을 둔다. 브라우저 기본은 사실상 무한 대기다.
- 재시도는 **멱등한 요청만**(GET·조회). 결제·생성 같은 비멱등 요청은 멱등 키 없이 재시도하지 않는다.
- 재시도는 지수 백오프 + 지터. 4xx는 재시도하지 않는다(요청이 잘못된 것이라 반복해도 같다).
- 자동 재시도 횟수를 늘려 장애를 감추지 않는다. 사용자에게 보이는 실패가 더 낫다.

## 캐시 · 무효화

- 캐시 키에 **요청을 결정하는 값 전부**를 넣는다(경로·파라미터·정렬·페이지 + **사용자 스코프**).
  사용자 스코프가 빠지면 계정 전환 시 남의 데이터가 보인다.
- 변경(mutation) 후 영향을 받는 쿼리를 무효화한다. 무엇을 무효화하는지 코드에서 읽혀야 한다.
- `staleTime`·`gcTime` 같은 값에는 왜 그 숫자인지 한 줄을 남긴다([`code-comments.md`](./code-comments.md)).
- 목록은 커서 기반 페이지네이션을 기본으로 하고 `limit` 상한을 지킨다. 전체 조회를 만들지 않는다.

## 파일 업로드 · 스트리밍

- 업로드는 진행률·취소·실패 재시도를 제공한다. 큰 파일은 사전 서명 URL 방식을 검토한다.
- 스트리밍 응답(SSE·청크)은 연결 종료·재연결 정책을 정한다. 무한 재연결 루프를 만들지 않는다.

## 이 리포가 API를 제공한다면 (라우트 핸들러 · BFF)

- **서버 전용 코드임을 컴파일 단계에서 보장한다**(서버 전용 마커 import·디렉터리 분리). 클라이언트 번들에
  섞이면 비밀이 노출된다([`security.md`](./security.md)).
- 인증·인가를 그 경로에서 다시 판정한다. 화면이 확인했다는 전제를 두지 않는다.
- 입력(본문·쿼리·경로)을 스키마로 파싱하고, 본문 크기 상한을 둔다.
- 응답은 **하나의 형태**로 고정한다. 성공/실패는 HTTP status가 가르고, 오류 본문에는 기계 판독 가능한
  `code`와 사용자 노출용 `message`를 함께 담는다.
- 내부 오류 메시지·스택을 응답에 싣지 않는다. 로그에만 남기고 상관용 식별자를 응답에 넣는다.

## 연동 DoD (Story)

- [ ] 응답을 스키마로 파싱하고, 파싱 실패가 에러로 처리된다.
- [ ] 401·403·404·검증 실패·5xx 각각의 화면 처리가 정의돼 있다.
- [ ] 요청에 타임아웃과 취소가 걸려 있다. 비멱등 요청을 자동 재시도하지 않는다.
- [ ] 캐시 키에 사용자 스코프가 포함돼 있다. 변경 후 무효화 대상이 명시돼 있다.
- [ ] 성공 + 최소 1개 실패 케이스 테스트(네트워크는 목/핸들러로 고정).
- [ ] 엔드포인트 문자열이 한 곳에 모여 있다. 컴포넌트에 `fetch`가 없다.
- [ ] 화면 명세의 API 연동 절이 갱신됐다([`guardrails.md`](./guardrails.md) "docs 동시 갱신").
