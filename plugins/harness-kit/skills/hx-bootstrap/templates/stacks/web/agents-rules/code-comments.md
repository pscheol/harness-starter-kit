# 주석 작성 가이드 (TypeScript · React)

> 기본값은 **주석 없음**이다. 모듈 밖으로 나가는 공개 API에만 한 줄을 달고, 나머지는 코드로 말할 수 없는 것만 적는다.
> 문장을 어떻게 쓸지는 [`writing-style.md`](./writing-style.md)가 정한다. 이 파일은 **어디에 얼마나** 쓸지를 정한다.

이 문서가 주석 표준의 원본이다. steering·진입 파일은 요약과 포인터만 둔다.

## TSDoc 규약 (지켜야 하는 형식)

1. 공개 API 주석은 `/** */`로 선언 바로 위에 쓴다. 내부 한 줄 설명은 `//`.
2. 첫 줄은 **무엇인지** 한 문장. 타입이 이미 말하는 것(인자·반환 타입)은 반복하지 않는다.
3. `@param`·`@returns`를 기계적으로 나열하지 않는다. **타입이 못 담는 의미**(단위·범위·소유권·`null`의 뜻)만 적는다.
4. 폐기 예정은 `@deprecated <대체 방법>`으로 적는다(에디터가 취소선으로 표시한다).
5. `@example`은 사용법이 시그니처만으로 안 잡히는 훅·유틸에만.

export되는 컴포넌트·훅·유틸에는 **한 줄** 설명을 단다. 그 한 줄로 충분하면 거기서 멈춘다.

## 주석을 더 다는 경우 (이 다섯뿐)

1. **Why** — 코드만 봐선 알 수 없는 결정·제약·트레이드오프. "왜 이 방식", "왜 이 값".
2. **함정** — 순진하게 고치면 깨지는 지점. 렌더 순서 의존, 정리 누락, 레이스, 브라우저 버그 우회.
3. **외부 근거** — 디자인 결정·접근성 규격·장애 이력·티켓처럼 코드 밖에 있는 사실.
4. **억제 이유** — `eslint-disable`·`@ts-expect-error`를 붙였다면 왜 안전한지. 이유 없는 억제는 리뷰에서 막는다.
5. **절차** — 본문을 훑어서는 무슨 일을 하는지 안 잡히는 함수(5단계 이내, 각 단계에 "왜").

여기에 안 걸리면 쓰지 않는다. 특히 **props 나열·단순 표현 컴포넌트·매퍼·상수 객체에는 설명 주석을 달지 않는다.**

## 주석을 달지 않는 것

- 시그니처 받아쓰기: `// 사용자 목록을 가져온다` 위의 `fetchUsers()`.
- props를 표로 옮겨 적기. 타입이 이미 한다.
- 규칙 문서로 보내는 참조 주석: `// 자세한 내용은 .agents/rules/security.md 참고`. 규칙은 규칙 파일이 소유한다.
- 구획 나누기 주석(`// ===== 핸들러 =====`), 변경 이력(`// 2026-03-02 수정`). git이 한다.
- JSX 안에서 마크업 구조를 한국어로 반복하는 주석.

```text
✗ // name을 trim해서 반환한다
✓ // 검색 키 일관성 때문에 저장 전에 앞뒤 공백을 흡수한다
```

## effect · 정리

effect는 **무엇을 정리하는지, 왜 이 의존성인지**가 코드에 안 드러난다. 그 부분만 적는다.

```ts
// ✗ 코드를 그대로 옮긴 주석
// 마운트되면 리스너를 등록하고 언마운트되면 해제한다
useEffect(() => { ... }, []);

// ✓ 함정과 근거
// resize 는 드래그 중 초당 수십 번 온다. rAF 로 묶지 않으면 리스트 재계산이 프레임을 넘긴다.
useEffect(() => { ... }, []);
```

의존성 배열에서 값을 일부러 뺐다면 **왜 안전한지**를 적는다. 적지 못하겠으면 빼면 안 되는 값이다.

```ts
// onSelect 는 매 렌더 새로 만들어지지만 첫 선택에만 쓰인다.
// 배열에 넣으면 목록을 열 때마다 재구독이 돌아 스크롤 위치가 초기화된다.
// eslint-disable-next-line react-hooks/exhaustive-deps
useEffect(() => { ... }, [items]);
```

## 컴포넌트 · 훅

```tsx
// ✓ 공개 컴포넌트 — 한 줄과 제약
/** 주문 상태를 색과 라벨로 표시한다. 상태 값은 서버 enum 과 1:1이다. */
export function OrderStatusBadge({ status }: Props) { ... }

// ✓ 훅 — 소유권과 수명
/**
 * {{DOMAIN_EXAMPLE}} 목록을 조회한다.
 *
 * 캐시 키에 사용자 스코프가 들어간다. 빼면 계정 전환 시 이전 사용자 데이터가 남는다.
 */
export function use{{DOMAIN_EXAMPLE}}List(params: ListParams) { ... }
```

표현 전용 컴포넌트(`<Stack>`·`<Text>`)에는 주석을 달지 않는다. 이름과 props가 이미 설명한다.

## 스타일 · 매직 값

CSS의 숫자는 근거가 코드 밖에 있는 경우가 많다. **그 근거만** 적는다.

```css
/* ✗ */
.panel { z-index: 50; } /* z-index 50 */

/* ✓ */
/* 헤더(40)보다 위, 모달 오버레이(100)보다 아래. 층 정의는 토큰 파일. */
.panel { z-index: 50; }

/* ✓ */
/* iOS 사파리 주소창 때문에 100vh 가 실제 화면보다 크다. dvh 미지원 폴백. */
.sheet { height: 100dvh; }
```

색·간격 하드코딩이 불가피하면 **왜 토큰이 아닌지**를 그 자리에 남긴다([`design-system.md`](./design-system.md)).

## 접근성 속성

ARIA 속성은 "왜 필요한지"가 안 보이면 다음 사람이 지운다.

```tsx
// 목록이 비동기로 갱신된다. 스크린리더가 변경을 놓치지 않도록 live region 으로 알린다.
<div aria-live="polite" aria-atomic="false">
```

## 처리 흐름 주석

단계별 흐름(`처리 흐름: 1. … 2. …`)은 **복잡한 함수의 것**이다. 아래 둘 중 하나면 쓴다.

- **절차 복잡도** — 조건 분기·비동기·상태 전이가 얽혀 본문을 훑어서는 절차가 안 잡힌다.
- **순서 의존** — 단계 순서를 바꾸면 버그가 난다. 이때는 각 단계에 **순서의 이유**를 적는다.

5단계 이내로, 각 단계는 "무엇을 — 왜"로 한 줄. 여섯 단계가 필요하면 주석이 아니라 함수를 쪼갠다.

```ts
/**
 * 장바구니를 주문으로 확정한다.
 *
 * 처리 흐름:
 *  1. 재고 확인 — 결제 화면으로 넘기기 전에. 뒤집으면 결제 후 품절이 뜬다.
 *  2. 낙관적 반영 — 스냅샷을 잡아 둔다. 3에서 실패하면 이 스냅샷으로 되돌린다.
 *  3. 확정 요청 — 비멱등이라 자동 재시도하지 않는다.
 *  4. 실패 시 롤백 — 스냅샷 시점 항목만 되돌린다. 그 사이 추가된 항목은 건드리지 않는다.
 */
```

## 리뷰 체크리스트

- 이 주석이 없으면 무엇을 못 알아보는가 → 답이 없으면 삭제.
- props·타입을 한국어로 반복하고 있지 않은가.
- effect에 정리 대상과 의존성 근거가 있는가.
- `eslint-disable`·`@ts-expect-error`·하드코딩된 지연 시간·`z-index`에 이유가 붙어 있는가.
- 매직 숫자(브레이크포인트·애니메이션 지속·재시도 횟수)에 근거가 있는가.
- 코드가 바뀌었는데 주석이 옛 동작을 말하는가 → 고치거나 지운다. 거짓 주석은 없는 것보다 나쁘다.
