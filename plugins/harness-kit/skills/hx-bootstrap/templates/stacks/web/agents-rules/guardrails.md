# 개발 가드레일 — {{PROJECT_NAME}}

모든 작업의 최소 기준이다. 무엇을 만들든 착수 전에 이 파일을 확인한다.

## 추측하지 말 것 (최우선)

- 코드·동작·설정을 추측해서 단정하지 않는다. 확인한 뒤 말한다.
- 파일/컴포넌트/응답 형태를 언급하기 전에 실제로 읽는다. 읽지 않았으면 "확인하지 않았다"고 명시한다.
- 의존성·버전은 `package.json`과 락파일에서 확인한 뒤 사용한다. 설치되지 않은 패키지를 import하는 코드를 쓰지 않는다.
- **API 응답 형태를 상상하지 않는다.** 스펙 문서나 실제 응답을 확인한다. 확인 못 했으면 그 사실을 적고 진행한다.
- 디자인 값(색·간격·타이포)을 지어내지 않는다([`design-system.md`](./design-system.md)).
- 모르거나 불확실하면 "모른다 / 확인 필요"라고 분명히 밝힌다. 검증한 사실과 미확인 가정을 구분해 표현한다.

## 강제 수단은 두 가지뿐이다 (프론트엔드의 구조적 약점)

백엔드에는 컴파일러·모듈 가시성이 레이어를 막아 주지만 **프론트엔드에는 그런 장치가 없다.**
이 프로젝트에서 경계를 실제로 지키는 것은 둘뿐이다.

1. **타입 검사(strict)** — `strict` + `noUncheckedIndexedAccess`. 끄면 경계 타입이 무의미해진다.
2. **ESLint 경계 규칙** — import 방향·슬라이스 공개 API. **규칙에 등록하지 않은 경계는 존재하지 않는 경계다.**

레이어·슬라이스를 늘리면 규칙에도 등록한다. 등록을 빠뜨리면 `ARCHITECTURE.md`는 문서로만 남는다.

## 서버 렌더링(SSR)과 하이드레이션

서버 렌더를 쓰는 변형(`nextjs-app`, 또는 SSR을 얹은 SPA)에서는 **같은 컴포넌트가 두 번 실행된다** —
서버에서 HTML을 만들 때 한 번, 브라우저에서 그 HTML에 이벤트를 붙일 때(하이드레이션) 한 번.
두 실행의 결과가 다르면 React가 마크업을 버리고 다시 그린다. 화면이 깜빡이고, 첫 입력이 사라지고,
콘솔에만 경고가 남는다. **프론트엔드에서 가장 자주 나고 가장 늦게 발견되는 결함이다.**

### 렌더 모드는 라우트마다 의식적으로 정한다

| 모드 | 언제 | 대가 |
|---|---|---|
| 정적 생성(빌드 시) | 모두에게 같은 내용. 마케팅·문서·목록 | 내용이 바뀌면 재빌드 또는 재검증이 필요하다 |
| 서버 렌더(요청마다) | 사용자·요청에 따라 달라진다. 인증 화면·개인화 | 요청마다 서버 비용. 응답 지연이 곧 첫 페인트 |
| 증분 재검증 | 대체로 같지만 가끔 바뀐다. 상품·게시글 | 주기 안에서는 낡은 화면이 나간다 |
| 클라이언트 렌더 | 상호작용이 본체. 대시보드·에디터 | SEO·첫 페인트를 포기한다 |

**기본값에 맡기지 않는다.** 라우트마다 어느 모드인지와 그 근거를 코드에 남긴다. 나중에 "이 페이지가
왜 매 요청마다 렌더되지"를 아무도 답하지 못하는 상태가 실제 비용이 된다.

### 하이드레이션 불일치를 만드는 것들 (전부 금지)

- **렌더 중 시각·난수** — `Date.now()`·`new Date()`·`Math.random()`·`crypto.randomUUID()`.
  서버와 브라우저의 값이 다르다. 시각은 서버에서 계산해 props로 내리고, 표시 포맷은 결정적으로 만든다.
- **렌더 중 브라우저 API** — `window`·`document`·`localStorage`·`navigator`·`matchMedia`.
  서버에는 없다. 마운트 이후(effect)로 미루거나 클라이언트 전용 모듈로 분리한다.
- **사용자 로캘·타임존에 의존하는 포맷** — 서버 로캘과 브라우저 로캘이 다르면 숫자·날짜 문자열이 갈린다.
  로캘을 명시적으로 넘긴다.
- **`typeof window !== 'undefined'` 로 분기해 다른 마크업을 그리기** — 불일치를 만드는 가장 흔한 코드다.
  분기해야 한다면 **양쪽이 같은 초기 마크업**을 그리고, 차이는 마운트 이후에 적용한다.
- **서버·클라이언트에서 다른 초기 상태** — 스토어 초기값을 브라우저 저장소에서 읽으면 어긋난다.
  서버 상태를 직렬화해 내리고 그 값으로 초기화한다.
- **HTML 중첩 규칙 위반** — `<p>` 안의 `<div>`, `<button>` 안의 `<button>` 등. 브라우저가 DOM을 교정해
  서버 HTML과 달라진다.

`suppressHydrationWarning`은 **경고를 지우지 실제 불일치를 고치지 않는다.** 시각 표시처럼 원인이
명확하고 국소적인 경우에만 쓰고, 왜 안전한지 주석을 남긴다.

### 서버에서 도는 코드의 금기

- **모듈 최상위 가변 상태 금지** — `let cache = {}` 는 서버 프로세스에서 **요청 간에 공유된다.**
  한 사용자의 데이터가 다른 사용자 화면에 나간다. 요청 스코프 안에 둔다.
- 서버 렌더 경로에서 브라우저 전용 라이브러리를 정적 import하지 않는다. 동적 import로 내린다.
- 스트리밍(Suspense)은 **느린 부분만** 감싼다. 페이지 전체를 감싸면 스트리밍의 이점이 없다.
- 서버에서 클라이언트로 넘기는 값은 직렬화된다 = **HTML 소스에 그대로 남는다.** 보여줄 필드만 넘긴다.

### 프레임워크 미들웨어는 최종 방어선이 아니다

경로 단위 미들웨어(인증 리다이렉트 등)는 **UX 최적화**다. 접근 제어가 아니다.

- 미들웨어에서 세션을 확인했더라도 **라우트 핸들러·서버 액션·데이터 접근 지점에서 다시 판정한다.**
  미들웨어는 매처(matcher)에서 빠진 경로·정적 자산·직접 호출을 놓친다.
- 미들웨어는 요청마다 돈다. 무거운 작업(DB 조회·외부 호출)을 넣으면 모든 요청이 느려진다.
- 매처 패턴을 넓게 잡아 정적 자산까지 통과시키지 않는다.
- 미들웨어에서 응답 본문을 다시 쓰지 않는다. 리다이렉트·헤더까지만.

## 리렌더와 메모이제이션 — 측정이 먼저다

- **`memo`·`useMemo`·`useCallback`을 습관으로 뿌리지 않는다.** 셋 다 비교 비용과 메모리를 쓴다.
  느리다는 **측정 결과가 있을 때** 붙이고, 무엇이 느렸는지 주석에 남긴다([`frontend-performance.md`](./frontend-performance.md)).
- 리렌더는 그 자체로 문제가 아니다. 문제는 **비싼 리렌더**다 — 큰 목록, 무거운 계산, 레이아웃 변경.
- 상태를 **쓰는 곳 가까이** 둔다. 상위로 올릴수록 그 아래 전체가 함께 리렌더된다. 컴포넌트를 쪼개는 것이
  메모이제이션보다 먼저다.
- 렌더 중에 객체·배열·함수를 새로 만들어 자식 props로 넘기면 `memo`가 무력해진다. 안정된 참조가 필요하면
  그 이유를 명확히 한 뒤에 고정한다.
- Context 값이 매 렌더마다 새 객체면 구독자 전체가 리렌더된다. 값을 나누거나 참조를 안정화한다.
- 목록 `key`는 정렬·필터 후에도 항목을 따라가는 **안정된 ID**여야 한다. 인덱스를 쓰면 순서가 바뀔 때
  입력 상태·포커스가 엉뚱한 행에 남는다. 반대로 **일부러 리마운트**하고 싶을 때 `key`를 바꾸는 것은 정당한 기법이다.

## 하네스 작업 규칙

- 규칙 원본은 `.agents/rules/`, 기록/SDD 원본은 `.agents/docs/`다. 진입 파일(AGENTS.md 등)은 목차일 뿐 상세를 중복 보관하지 않는다.
- 규칙이 바뀌면 `.agents/rules/`의 원본을 **먼저** 고치고 진입 파일·kiro 포인터를 동기화한다(절차: [`agent-harness.md`](./agent-harness.md)).
- 복잡한 작업은 `.agents/docs/<slug>-specs/tasks/active/<feature>.md`에 계획을 남기고 진행한다.
- 기술 부채는 `.agents/docs/tech-debt-tracker.md`에 등록한다.
- 변경은 `scripts/verify.sh`(포맷·lint·typecheck·가드·test·build)로 검증한 뒤 결과를 제시한다.

## exec-plan 완료 게이트 (사용자 검증 필수)

상태 전이 `active/` → `check/` → `completed/`.
- DoD/verify 충족 시 임의로 `completed/`로 옮기지 않는다. 상태를 `check`로 두고 `check/`로 이동해 **사용자 검증을 요청**한다.
- UI 작업은 특히 그렇다. 게이트 통과는 "안 깨졌다"이지 "의도대로 보인다"가 아니다([`verification-ladder.md`](./verification-ladder.md) L4).

## 기능 구현 시 docs 명세 동시 갱신 (필수)

- 화면 추가/변경, 상태 전이 변경, API 연동 변경 시 `.agents/docs/` 명세를 **같은 변경**에 포함한다.
- 화면 명세에는 진입 경로(URL), 필요한 권한, 표시 데이터, **네 가지 상태**(loading·empty·error·partial), 사용자 행동과 결과, 호출하는 API를 적는다.
- 화면 흐름은 flowchart, 서버 왕복이 있는 조작은 sequence diagram으로 남긴다.
- Mermaid diagram은 렌더링 안정성을 우선한다. 노드 label에 `<`, `>`, `<=`, `>=`를 직접 넣지 말고 자연어로 쓴다.
- docs 영향이 없다고 판단되면 exec-plan 또는 변경 요약에 "docs 영향 없음"과 근거를 명시한다.

## 주석은 기본이 '없음'이다

상세·Bad/Good 원본은 [`code-comments.md`](./code-comments.md). 문장을 어떻게 쓸지는 [`writing-style.md`](./writing-style.md).

- **TSDoc 규약**: `/** */`로 선언 바로 위에. 모듈 밖으로 나가는 공개 API(export되는 컴포넌트·훅·유틸)에 **한 줄**을 단다.
- 그 한 줄로 충분하면 거기서 멈춘다. 더 쓰는 경우는 다섯뿐이다 — Why · 함정 · 외부 근거 · 억제 이유 · 복잡한 함수의 절차.
- props 나열, 시그니처 받아쓰기, 구획 주석, 변경 이력은 쓰지 않는다.
- **정리(cleanup)가 필요한 effect**에는 무엇을 왜 정리하는지 적는다. `eslint-disable`·하드코딩된 지연 시간·`z-index` 값에는 이유를 남긴다.
- 코드가 바뀌면 주석도 고치거나 지운다. 한국어로 쓰고, 비밀·토큰·키 원문은 넣지 않는다.

## 레이어 책임 (아키텍처 변형 무관 원칙 — 필수)

아래는 **어떤 변형을 골랐든** 지키는 원칙이다. 구체적인 디렉터리 경로·이름은 변형마다 다르므로
[`structure.md`](./structure.md)와 `ARCHITECTURE.md`가 원본이다.

- **표현과 결정을 분리한다.** 컴포넌트는 "무엇을 그릴지"를 맡고, "무엇이 참인지"는 바깥에서 정한다.
  - 화면에 종속되지 않는 규칙·계산(금액 산정·자격 판정·정규화) → **순수 함수**. DOM·네트워크 의존 0.
  - 데이터 획득·캐시·무효화 → **데이터 접근 계층**(서버 상태). 컴포넌트에서 직접 `fetch` 하지 않는다.
  - 표현 컴포넌트는 props를 받아 그린다. 데이터를 스스로 구해 오는 컴포넌트는 재사용되지 않는다.
- **공유 컴포넌트는 도메인을 모른다.** 공용 `Button`이 주문 상태를 아는 순간 그건 공용이 아니다.
- 의존 방향은 한 방향이다(화면 → 기능 → 엔티티 → 공유). 역방향 import를 만들지 않는다.
- **fetch URL·엔드포인트 문자열을 컴포넌트에 흩지 않는다.** 한 곳에 모은다([`api-standards.md`](./api-standards.md)).
- 파싱·검증은 경계에서. 외부 응답은 스키마로 파싱해 좁힌 뒤 안으로 넘긴다.
- 전역 가변 모듈 상태(모듈 최상위 `let cache = ...`)를 만들지 않는다. 서버 렌더 환경에서는 요청 간에 공유되어 **다른 사용자의 데이터가 섞인다.**
- 위반 예시(하지 말 것): 표현 컴포넌트 안에서 가격 규칙 계산·권한 판정·재시도 정책 작성.

## TypeScript · React 실수 방지 (자주 나는 것)

- **`any`·`as` 단정·`!` 금지**: 모르는 값은 `unknown`으로 받아 좁힌다. `as`는 타입 검사를 끄는 스위치다.
- **effect로 파생 상태를 동기화하지 않는다**: props로 계산되는 값은 렌더 중에 계산한다. effect로 state를 맞추면 한 프레임 늦고 무한 루프의 원천이 된다.
- **비동기 effect의 취소**: 응답이 늦게 온 이전 요청이 최신 결과를 덮어쓴다(레이스). `AbortSignal`이나 무효 플래그로 정리한다.
- **정리 누락**: 이벤트 리스너·타이머·구독·옵저버는 effect의 정리 함수에서 해제한다. 안 하면 언마운트된 컴포넌트가 계속 산다.
- **리스트 `key`에 배열 인덱스 금지**: 순서가 바뀌면 상태가 엉뚱한 항목에 붙는다. 안정된 ID를 쓴다.
- **배열·객체를 제자리에서 바꾸지 않는다**: `sort`·`reverse`·`splice`는 원본을 바꾼다. 복사 후 정렬한다.
- **날짜**: 문자열을 그대로 비교·정렬하지 않는다. 타임존을 명시하고, 표시 형식과 저장 형식을 분리한다.
- **금액**: 부동소수 계산 금지. 최소 단위 정수나 십진 타입으로 다룬다.
- **환경변수**: 공개 접두사가 붙은 변수는 브라우저 번들에 그대로 들어간다. 비밀을 넣지 않는다([`security.md`](./security.md)).
- **`useEffect` 의존성 배열을 손으로 지우지 않는다**: 린터 경고를 억제하려면 이유를 주석으로 남긴다.
