# 품질 기준 / DoD — {{PROJECT_NAME}}

에이전트가 코드를 생성·수정할 때 자체 점검하는 체크리스트. PR 전 충족해야 한다.

## 코드 품질 체크리스트

- [ ] 변경에 대한 테스트 존재(성공 + 최소 1개 실패 케이스). 순수 로직·훅은 **테스트 우선(TDD)**.
- [ ] `any`·`as` 단정·non-null(`!`)이 새로 늘지 않았다. 불가피하면 이유가 주석에 있다.
- [ ] 외부 응답을 **스키마로 파싱**한다. 파싱 실패가 에러로 처리된다([`api-standards.md`](./api-standards.md)).
- [ ] 에러를 삼키지 않는다(빈 `catch` 없음). 사용자에게 보이는 실패 경로가 있다.
- [ ] effect에 정리 함수가 있다(리스너·타이머·구독·요청 취소). 의존성 배열을 임의로 비우지 않았다.
- [ ] 파생 값을 상태로 저장하지 않는다. effect로 상태를 동기화하지 않는다([`ui-state.md`](./ui-state.md)).
- [ ] 리스트 `key`가 안정된 식별자다(배열 인덱스 아님).
- [ ] 레이어 경계 준수 — ESLint import 규칙 통과([`structure.md`](./structure.md)). 새 슬라이스를 만들었으면 **규칙에도 등록**했다.
- [ ] 컴포넌트에 `fetch`·엔드포인트 문자열이 없다. 데이터 접근 계층을 경유한다.
- [ ] 전역 가변 모듈 상태를 만들지 않았다(서버 렌더 환경에서 요청 간 공유된다).
- [ ] 매직 넘버·하드코딩 값 없음(토큰·상수·설정으로 외부화). 색·간격은 **토큰에서** 왔다([`design-system.md`](./design-system.md)).
- [ ] 포맷·lint·타입 검사 통과(`bash scripts/verify.sh`).

## 화면 DoD (Story)

- [ ] **네 가지 상태**가 모두 구현됐다 — loading · empty · error · partial.
- [ ] 에러 화면에 **다음 행동**이 있다(재시도·뒤로·문의). 원인 문자열만 뿌리지 않는다.
- [ ] 키보드만으로 진입·조작·이탈이 가능하다. 포커스 표시가 보인다. 모달에 포커스 함정이 없다.
- [ ] 인터랙티브 요소에 접근 가능한 이름이 있다(아이콘 버튼 포함)([`accessibility.md`](./accessibility.md)).
- [ ] 대비 기준 충족(본문 4.5:1 · 큰 글씨 3:1 · UI 경계 3:1). 색만으로 의미를 전달하지 않는다.
- [ ] 컴포넌트 상태 8종을 검토했다 — default·hover·focus-visible·active·disabled·loading·empty·error.
- [ ] 반응형 확인: 좁은 폭에서 가로 스크롤·잘림이 없다.
- [ ] `prefers-reduced-motion`을 존중한다.
- [ ] 401/403 경로가 화면에서 실제로 동작한다(재인증·권한 없음 화면).
- [ ] 화면 명세(진입 경로·권한·표시 데이터·상태 4종·호출 API)가 갱신됐다.

## 성능 DoD

- [ ] 이미지에 폭·높이가 있다(레이아웃 이동 방지).
- [ ] 초기 번들 예산을 넘기지 않았다. 넘겼다면 PR에 사실과 근거를 적었다([`frontend-performance.md`](./frontend-performance.md)).
- [ ] 무거운 라이브러리를 정적 import하지 않았다.
- [ ] 성능 목적의 변경이면 전/후 측정 숫자가 있다. 없으면 그 변경은 근거가 없다.

## Epic DoD

- [ ] 모든 P0 Story 완료.
- [ ] 내부 demo flow에서 해당 기능 사용 가능.
- [ ] 실패 시 로그·에러 표시로 원인 파악 가능(상관용 식별자 포함).
- [ ] 다음 Epic이 의존하는 계약(API 스키마·공용 컴포넌트 API) 문서화.
- [ ] 핵심 사용자 흐름에 E2E 테스트 1개 이상.

## 커버리지

- 순수 로직·훅 ≥ 90%, 전체 ≥ 80%. 테스트 러너 설정에서 임계를 강제한다(게이트가 러너를 부른다).
- **커버리지 숫자보다 행위 검증이 우선**이다. 렌더만 하고 단언이 없는 테스트로 숫자를 채우지 않는다.
- 구현 세부(클래스명·내부 상태)가 아니라 **사용자가 보는 것**을 기준으로 단언한다. 그래야 리팩터링에서 살아남는다.
- 네트워크는 요청 수준에서 고정한다(요청 가로채기). 컴포넌트에 모듈 목을 덕지덕지 붙이지 않는다.
- 시각적 회귀는 단위 테스트를 대체하지 않고 보완한다.

## 검증 절차

1. `bash scripts/verify.sh` 실행(= 구조 점검 → 포맷 → lint → typecheck → 가드 → test → build)
2. 실패 시 수정 후 재검증 → 3. 결과 제시.
- 도구가 없으면 표준 도구로 셋업하고, 불가하면 그 사유를 명시한다.
- **게이트 통과는 "안 깨졌다"이지 "의도대로 보인다"가 아니다.** UI 확인은 사람의 몫이다([`verification-ladder.md`](./verification-ladder.md) L4).
- exec-plan 완료는 임의로 `completed/`로 옮기지 않는다. `check/`로 옮겨 사용자 검증을 요청한다([`agent-harness.md`](./agent-harness.md)).

> 상세 DoD 원본이 별도 백로그 문서에 있으면 여기 링크만 둔다(같은 내용을 두 곳에 두지 않는다).
