# 주석 작성 가이드 (TypeScript · React · Electron)

> 기본값은 **주석 없음**이다. 모듈 밖으로 나가는 공개 API에만 한 줄을 달고, 나머지는 코드로 말할 수 없는 것만 적는다.
> 문장을 어떻게 쓸지는 [`writing-style.md`](./writing-style.md)가 정한다. 이 파일은 **어디에 얼마나** 쓸지를 정한다.

이 문서가 주석 표준의 원본이다. steering·진입 파일은 요약과 포인터만 둔다.

## TSDoc 규약 (지켜야 하는 형식)

1. 공개 API 주석은 `/** */`로 선언 바로 위에 쓴다. 내부 한 줄 설명은 `//`.
2. 첫 줄은 **무엇인지** 한 문장. 타입이 이미 말하는 것(인자·반환 타입)은 반복하지 않는다.
3. `@param`·`@returns`를 기계적으로 나열하지 않는다. **타입이 못 담는 의미**(단위·범위·소유권·`null`의 뜻)만 적는다.
4. 폐기 예정은 `@deprecated <대체 방법>`으로 적는다.
5. `@example`은 사용법이 시그니처만으로 안 잡히는 훅·유틸에만.

export되는 컴포넌트·훅·유틸·핸들러에는 **한 줄** 설명을 단다. 그 한 줄로 충분하면 거기서 멈춘다.

## 주석을 더 다는 경우 (이 다섯뿐)

1. **Why** — 코드만 봐선 알 수 없는 결정·제약·트레이드오프.
2. **함정** — 순진하게 고치면 깨지는 지점. 프로세스 경계, 정리 누락, 레이스, 플랫폼 차이.
3. **외부 근거** — Electron/OS 동작, 디자인 결정, 장애 이력, 티켓.
4. **억제 이유** — `eslint-disable`·`@ts-expect-error`를 붙였다면 왜 안전한지.
5. **절차** — 본문을 훑어서는 무슨 일을 하는지 안 잡히는 함수(5단계 이내, 각 단계에 "왜").

여기에 안 걸리면 쓰지 않는다. 특히 **props 나열·단순 표현 컴포넌트·매퍼·상수 객체에는 설명 주석을 달지 않는다.**

## IPC 핸들러 (이 스택에서 가장 중요한 주석 자리)

핸들러는 **신뢰 경계**다. 코드만 봐서는 "누가 부를 수 있고 무엇이 바뀌는지"가 안 보인다.

```ts
// ✗ 시그니처 받아쓰기
/** {{DOMAIN_EXAMPLE}} 목록을 반환한다. */
ipcMain.handle('{{DOMAIN_EXAMPLE}}:list', async (event, req) => { ... });

// ✓ 신뢰 수준과 부작용
/**
 * {{DOMAIN_EXAMPLE}} 목록을 반환한다.
 *
 * 렌더러 입력이므로 cursor·limit 를 파싱한 뒤 쓴다. limit 상한을 넘기면 잘라낸다 —
 * 상한 없이 넘기면 전체를 메모리에 올려 main 이 멈춘다.
 */
ipcMain.handle('{{DOMAIN_EXAMPLE}}:list', async (event, req) => { ... });

// ✓ 파괴적 동작
/**
 * 로컬 캐시 디렉터리를 비운다.
 *
 * 되돌릴 수 없다. 사용자 확인은 렌더러가 아니라 여기서 요구한다 —
 * 렌더러 확인만 믿으면 임의 채널 호출로 우회된다.
 */
ipcMain.handle('cache:clear', async () => { ... });
```

`shared/`의 채널 상수·계약 타입에는 **"어느 쪽이 부르고 무엇을 기대하는지"** 를 한 줄로 남긴다.

## 프로세스 경계

파일이 어느 프로세스에서 도는지는 디렉터리로 드러나야 하지만, **경계에 걸친 파일**에는 명시한다.

```ts
// ✓ 공유 모듈의 제약을 못박는다
/**
 * 렌더러와 main 이 함께 import 한다. 런타임 Node API 를 넣지 않는다 —
 * 넣으면 렌더러 번들이 깨진다(빌드에서만 드러난다).
 */
```

플랫폼 분기에는 **왜 그 OS만 다른지**를 적는다. 코드에는 조건만 남고 이유가 사라진다.

```ts
// macOS 는 마지막 창을 닫아도 앱이 살아 있는 것이 관례다. 여기서 quit 하면 Dock 아이콘이
// 남은 채 복원이 안 된다.
if (process.platform !== 'darwin') app.quit();
```

## effect · 정리 · 리스너

정리 대상과 수명은 코드에 안 드러난다. 그 부분만 적는다.

```ts
// ✓ 함정과 근거
// 창이 파괴된 뒤 send 하면 예외가 난다. 워처는 창보다 오래 살므로 여기서 반드시 해제한다.
win.on('closed', () => { watcher.close(); });
```

의존성 배열에서 값을 일부러 뺐다면 **왜 안전한지**를 적는다. 적지 못하겠으면 빼면 안 되는 값이다.

## 컴포넌트 · 훅

```tsx
/** {{DOMAIN_EXAMPLE}} 상태를 색과 라벨로 표시한다. 상태 값은 IPC 계약의 enum 과 1:1이다. */
export function {{DOMAIN_EXAMPLE}}StatusBadge({ status }: Props) { ... }
```

표현 전용 컴포넌트(`<Stack>`·`<Text>`)에는 주석을 달지 않는다. 이름과 props가 이미 설명한다.

## 스타일 · 매직 값

```css
/* ✓ */
/* 프레임리스 창의 드래그 영역. 이 높이보다 작으면 커서가 리사이즈 핸들과 겹친다. */
.titlebar { height: 32px; }
```

색·간격 하드코딩이 불가피하면 **왜 토큰이 아닌지**를 그 자리에 남긴다([`design-system.md`](./design-system.md)).

## 처리 흐름 주석

단계별 흐름은 **복잡한 함수의 것**이다. 분기가 얽혀 절차가 안 잡히거나, 순서를 바꾸면 버그가 나는 경우에만.
5단계 이내로, 각 단계는 "무엇을 — 왜"로 한 줄.

```ts
/**
 * 앱 종료를 처리한다.
 *
 * 처리 흐름:
 *  1. 진행 중 작업 취소 — 저장보다 먼저. 뒤집으면 저장 후 덮어쓰는 쓰기가 남는다.
 *  2. 저장되지 않은 변경 확인 — 있으면 종료를 막고 사용자에게 묻는다.
 *  3. 상태 저장 — 원자적 쓰기. 여기서 실패하면 종료를 중단한다.
 *  4. 워처·워커 종료 — 자식 프로세스가 남으면 앱이 안 죽는다.
 */
```

## 리뷰 체크리스트

- 이 주석이 없으면 무엇을 못 알아보는가 → 답이 없으면 삭제.
- **IPC 핸들러에 신뢰 수준과 부작용이 적혀 있는가.** 파괴적 동작이 표시돼 있는가.
- 공유 모듈에 "Node API 금지" 같은 제약이 명시돼 있는가.
- 플랫폼 분기에 이유가 있는가.
- 리스너·워처·워커의 정리 시점과 수명이 적혀 있는가.
- `eslint-disable`·`@ts-expect-error`·하드코딩된 경로·지연 시간에 이유가 붙어 있는가.
- 코드가 바뀌었는데 주석이 옛 동작을 말하는가 → 고치거나 지운다. 거짓 주석은 없는 것보다 나쁘다.
