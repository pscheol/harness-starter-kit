# 개발 가드레일 — {{PROJECT_NAME}}

모든 작업의 최소 기준이다. 무엇을 만들든 착수 전에 이 파일을 확인한다.

## 추측하지 말 것 (최우선)

- 코드·동작·설정을 추측해서 단정하지 않는다. 확인한 뒤 말한다.
- 파일/컴포넌트/IPC 채널/응답 형태를 언급하기 전에 실제로 읽는다. 읽지 않았으면 "확인하지 않았다"고 명시한다.
- 의존성·버전은 `package.json`과 락파일에서 확인한 뒤 사용한다. 설치되지 않은 패키지를 import하는 코드를 쓰지 않는다.
- **어느 프로세스에서 도는 코드인지 먼저 확인한다.** main·preload·renderer는 쓸 수 있는 API가 다르다.
  이걸 틀리면 런타임에야 드러난다.
- Electron·Node·Chromium 버전에 따라 가능한 API가 다르다. 버전을 확인하고 말한다.
- 디자인 값(색·간격·타이포)을 지어내지 않는다([`design-system.md`](./design-system.md)).
- 모르거나 불확실하면 "모른다 / 확인 필요"라고 분명히 밝힌다. 검증한 사실과 미확인 가정을 구분해 표현한다.

## 프로세스 경계가 이 스택의 전부다

| 프로세스 | 권한 | 책임 |
|---|---|---|
| **main** | Node 전체 · 파일 · 셸 · 네이티브 | 창 관리 · IPC 핸들러 · 파일/DB · 외부 호출 · 업데이트 |
| **preload** | 제한된 다리 | **화이트리스트 API만** 렌더러에 노출 |
| **renderer** | 웹(권한 없음) | 화면. Node API 없음 |

- `contextIsolation: true` · `nodeIntegration: false` · `sandbox: true` — **협상 대상이 아니다.**
  하나라도 풀면 렌더러 XSS 한 건이 곧바로 로컬 코드 실행이 된다. `scripts/verify.sh`가 이 셋을 검사한다.
- **렌더러는 신뢰 경계 밖이다.** 렌더러가 보낸 인자를 main에서 그대로 쓰지 않는다. 스키마로 파싱한다.
- 렌더러에서 필요해 보인다고 main API를 넓히지 않는다. 필요한 **동작 하나**를 채널로 노출한다.
  "파일을 읽어 줘"가 아니라 "이 문서를 열어 줘"다.
- 상세는 [`security.md`](./security.md). IPC 계약 형식은 [`api-standards.md`](./api-standards.md).

## 강제 수단은 셋뿐이다

1. **타입 검사(strict)** — `strict` + `noUncheckedIndexedAccess`.
2. **ESLint 경계 규칙** — 프로세스 간 import 방향. **등록하지 않은 경계는 존재하지 않는 경계다.**
3. **게이트의 프로세스 경계 가드** — `scripts/verify.sh`가 위험 설정을 grep으로 막는다(fast 레벨에도 포함).

번들러가 main·preload·renderer를 각각 빌드하므로 **빌드도 게이트에 포함**한다. Node API를 렌더러
번들에 끌어들이는 import는 빌드에서만 드러난다.

## 하네스 작업 규칙

- 규칙 원본은 `.agents/rules/`, 기록/SDD 원본은 `.agents/docs/`다. 진입 파일(AGENTS.md 등)은 목차일 뿐 상세를 중복 보관하지 않는다.
- 규칙이 바뀌면 `.agents/rules/`의 원본을 **먼저** 고치고 진입 파일·kiro 포인터를 동기화한다(절차: [`agent-harness.md`](./agent-harness.md)).
- 복잡한 작업은 `.agents/docs/<slug>-specs/tasks/active/<feature>.md`에 계획을 남기고 진행한다.
- 기술 부채는 `.agents/docs/tech-debt-tracker.md`에 등록한다.
- 변경은 `scripts/verify.sh`(포맷·경계 가드·lint·typecheck·test·build)로 검증한 뒤 결과를 제시한다.

## exec-plan 완료 게이트 (사용자 검증 필수)

상태 전이 `active/` → `check/` → `completed/`.
- DoD/verify 충족 시 임의로 `completed/`로 옮기지 않는다. 상태를 `check`로 두고 `check/`로 이동해 **사용자 검증을 요청**한다.
- 데스크톱 앱은 특히 그렇다. 게이트는 **개발 모드에서 안 깨졌다**는 뜻이지 패키징된 앱이 동작한다는 뜻이 아니다.
  패키징 후 실행 확인은 사람의 몫이다([`verification-ladder.md`](./verification-ladder.md) L4).

## 기능 구현 시 docs 명세 동시 갱신 (필수)

- 화면 추가/변경, **IPC 채널 추가/변경**, 파일·저장소 접근 변경 시 `.agents/docs/` 명세를 **같은 변경**에 포함한다.
- **IPC 채널을 추가하면 네 곳이 함께 바뀐다**: 채널 상수 목록 · preload 화이트리스트 ·
  main 핸들러(+입력 스키마) · 계약 문서. 하나라도 빠지면 런타임에야 드러난다.
- 화면 명세에는 진입 경로, 필요한 권한, 표시 데이터, **네 가지 상태**(loading·empty·error·partial),
  사용자 행동과 결과, 호출하는 IPC 채널을 적는다.
- Mermaid diagram은 렌더링 안정성을 우선한다. 노드 label에 `<`, `>`, `<=`, `>=`를 직접 넣지 말고 자연어로 쓴다.
- docs 영향이 없다고 판단되면 exec-plan 또는 변경 요약에 "docs 영향 없음"과 근거를 명시한다.

## 주석은 기본이 '없음'이다

상세·Bad/Good 원본은 [`code-comments.md`](./code-comments.md). 문장을 어떻게 쓸지는 [`writing-style.md`](./writing-style.md).

- **TSDoc 규약**: `/** */`로 선언 바로 위에. 모듈 밖으로 나가는 공개 API에 **한 줄**을 단다.
- 그 한 줄로 충분하면 거기서 멈춘다. 더 쓰는 경우는 다섯뿐이다 — Why · 함정 · 외부 근거 · 억제 이유 · 복잡한 함수의 절차.
- **IPC 핸들러에는 신뢰 수준과 부작용**을 적는다: 이 채널이 무엇을 바꾸는가, 누가 부를 수 있는가.
- 정리(cleanup)가 필요한 effect·리스너에는 무엇을 왜 정리하는지 적는다. main의 리스너는 앱 수명 내내 산다.
- `eslint-disable`·하드코딩된 경로·플랫폼 분기에는 이유를 남긴다.
- 코드가 바뀌면 주석도 고치거나 지운다. 한국어로 쓰고, 비밀·토큰·키 원문은 넣지 않는다.

## 레이어 책임 (아키텍처 변형 무관 원칙 — 필수)

아래는 **어떤 변형을 골랐든** 지키는 원칙이다. 구체적인 디렉터리 경로·이름은 변형마다 다르므로
[`structure.md`](./structure.md)와 `ARCHITECTURE.md`가 원본이다.

- **main은 오케스트레이션과 자원 접근**을 맡는다. 화면 로직·표현 규칙을 두지 않는다.
- **preload는 다리일 뿐이다.** 여기에 비즈니스 로직을 넣지 않는다. 채널을 함수로 감싸 노출하고 끝낸다.
- **renderer는 권한이 없다.** 파일·셸·네트워크 자격증명이 필요한 일은 main에 요청한다.
- **공유 코드(`shared/`)에는 타입과 채널 상수만** 둔다. 런타임 Node API를 넣으면 렌더러 번들이 깨진다.
- 도메인 규칙(계산·판정)은 프로세스에 종속되지 않는 순수 함수로 두고 양쪽에서 쓴다.
- 표현 컴포넌트는 props를 받아 그린다. IPC를 직접 부르는 컴포넌트는 재사용되지 않는다.
- 위반 예시(하지 말 것): 렌더러 컴포넌트에서 파일 경로 조립, preload에 권한 판정 로직, main에 화면 문구.

## TypeScript · React · Electron 실수 방지 (자주 나는 것)

- **`any`·`as` 단정·`!` 금지**: 모르는 값은 `unknown`으로 받아 좁힌다. IPC 인자에는 특히 그렇다.
- **어느 프로세스인지 착각**: 렌더러 파일에서 `fs`·`path`·`child_process`를 import하지 않는다.
  번들에 들어가면 빌드가 깨지거나(다행) 런타임에 터진다(불행).
- **IPC 리스너 누수**: 렌더러에서 `on`으로 구독했으면 언마운트 때 해제한다. main의 `handle`은
  **중복 등록하면 예외**가 난다(핫 리로드 때 자주 발생) — 등록은 한 곳에서 한 번만.
- **`send`와 `invoke` 혼동**: 응답이 필요하면 `invoke`/`handle`. `send`로 보내고 별도 채널로 답을 받는
  구조를 만들면 요청·응답 짝이 어긋난다.
- **effect로 파생 상태를 동기화하지 않는다**: props로 계산되는 값은 렌더 중에 계산한다.
- **비동기 취소**: 늦게 온 이전 응답이 최신 결과를 덮어쓴다. 요청 식별자나 취소로 정리한다.
- **리스트 `key`에 배열 인덱스 금지**. 안정된 ID를 쓴다.
- **배열·객체를 제자리에서 바꾸지 않는다**(`sort`·`reverse`·`splice`).
- **경로 문자열을 직접 조립하지 않는다**: 구분자·대소문자 규칙이 OS마다 다르다. 경로 API를 쓴다.
- **플랫폼 분기를 흩지 않는다**: macOS/Windows/Linux 차이(메뉴·트레이·창 닫기 동작)는 한 곳에 모은다.
- **금액은 부동소수 금지**, **날짜는 타임존 명시**.
- **앱 데이터 경로를 하드코딩하지 않는다**: OS별 표준 경로 API를 쓴다.

## 리렌더와 메모이제이션 — 측정이 먼저다

- **`memo`·`useMemo`·`useCallback`을 습관으로 뿌리지 않는다.** 셋 다 비교 비용과 메모리를 쓴다.
  느리다는 **측정 결과가 있을 때** 붙이고, 무엇이 느렸는지 주석에 남긴다([`frontend-performance.md`](./frontend-performance.md)).
- 리렌더 자체는 문제가 아니다. 문제는 **비싼 리렌더**다 — 큰 목록, 무거운 계산, 레이아웃 변경.
- 상태를 **쓰는 곳 가까이** 둔다. 상위로 올릴수록 그 아래 전체가 함께 리렌더된다. 컴포넌트를 쪼개는 것이
  메모이제이션보다 먼저다.
- 렌더 중에 객체·배열·함수를 새로 만들어 자식 props로 넘기면 `memo`가 무력해진다.
- Context 값이 매 렌더마다 새 객체면 구독자 전체가 리렌더된다. 값을 나누거나 참조를 안정화한다.
- **IPC 이벤트가 자주 오는 화면**을 특히 조심한다. main에서 초당 수십 번 밀어 올리는 진행률·로그를
  그대로 state에 넣으면 렌더가 그 빈도로 돈다. main 쪽에서 묶어 보내거나 렌더러에서 시간 단위로 모은다.
- 목록 `key`는 정렬·필터 후에도 항목을 따라가는 **안정된 ID**여야 한다. 반대로 **일부러 리마운트**하고
  싶을 때 `key`를 바꾸는 것은 정당한 기법이다.
