# 품질 기준 / DoD — {{PROJECT_NAME}}

에이전트가 코드를 생성·수정할 때 자체 점검하는 체크리스트. PR 전 충족해야 한다.

## 코드 품질 체크리스트

- [ ] 변경에 대한 테스트 존재(성공 + 최소 1개 실패 케이스). 순수 로직·핸들러는 **테스트 우선(TDD)**.
- [ ] `any`·`as` 단정·non-null(`!`)이 새로 늘지 않았다. 불가피하면 이유가 주석에 있다.
- [ ] **어느 프로세스에서 도는 코드인지** 위치와 import가 일치한다(렌더러에 Node API import 없음).
- [ ] IPC 인자를 **스키마로 파싱**한다. 파싱 실패가 `INVALID_INPUT`으로 반환된다([`api-standards.md`](./api-standards.md)).
- [ ] 에러를 삼키지 않는다(빈 `catch` 없음). 사용자에게 보이는 실패 경로가 있다.
- [ ] IPC 구독·리스너·타이머·워처가 해제된다(렌더러는 언마운트, main은 창 종료).
- [ ] `handle` 등록이 한 곳에서 한 번만 일어난다(중복 등록 예외 없음).
- [ ] 파생 값을 상태로 저장하지 않는다([`ui-state.md`](./ui-state.md)).
- [ ] 레이어·프로세스 경계 준수 — ESLint import 규칙 통과([`structure.md`](./structure.md)). 새 경계는 **규칙에도 등록**했다.
- [ ] 컴포넌트가 `window.<api>`를 직접 부르지 않는다. 데이터 접근 계층을 경유한다.
- [ ] 경로를 문자열로 조립하지 않는다. OS 표준 경로 API를 쓴다.
- [ ] 매직 넘버·하드코딩 값 없음. 색·간격은 **토큰에서** 왔다([`design-system.md`](./design-system.md)).
- [ ] 포맷·경계 가드·lint·타입 검사 통과(`bash scripts/verify.sh`).

## 보안 DoD (이 스택의 최우선)

- [ ] 새로 만든 창이 `contextIsolation: true` · `nodeIntegration: false` · `sandbox: true`로 열린다.
- [ ] preload가 **동작 단위**로 좁게 노출한다. 채널 이름을 인자로 받는 함수를 노출하지 않는다.
- [ ] main 핸들러가 경로·명령·URL을 검증한다(경로 순회·셸 인젝션·임의 스킴 차단).
- [ ] `shell.openExternal` 대상이 스킴 allowlist를 통과한다.
- [ ] 새 창 생성이 기본 거부이고 허용 목록만 외부 브라우저로 열린다.
- [ ] 비밀이 렌더러에 내려가지 않는다. 저장은 OS 키체인.
- [ ] 내부 오류 메시지·스택·파일 경로가 렌더러로 넘어가지 않는다.
- [ ] 로그·크래시 리포트에 비밀·개인정보가 없다.

## 화면 DoD (Story)

- [ ] **네 가지 상태**가 모두 구현됐다 — loading · empty · error · partial.
- [ ] 에러 화면에 **다음 행동**이 있다(재시도·뒤로·문의).
- [ ] 키보드만으로 진입·조작·이탈이 가능하다. 포커스 표시가 보인다. 모달에 포커스 함정이 없다.
- [ ] 인터랙티브 요소에 접근 가능한 이름이 있다([`accessibility.md`](./accessibility.md)).
- [ ] 대비 기준 충족(본문 4.5:1 · 큰 글씨 3:1 · UI 경계 3:1).
- [ ] 컴포넌트 상태 8종을 검토했다 — default·hover·focus-visible·active·disabled·loading·empty·error.
- [ ] 창 크기를 줄였을 때 잘림·가로 스크롤이 없다. 최소 창 크기가 지정돼 있다.
- [ ] `prefers-reduced-motion`을 존중한다.
- [ ] 화면 명세(진입 경로·권한·표시 데이터·상태 4종·호출 IPC 채널)가 갱신됐다.

## 데스크톱 DoD

- [ ] 오래 걸리는 작업이 **main을 막지 않는다**(워커·자식 프로세스). 진행률·취소가 있다.
- [ ] 창을 닫았다 다시 열어도 상태가 일관된다. 두 번째 창에서도 동작한다.
- [ ] 앱 재시작 후에도 유지돼야 하는 값이 실제로 유지된다(저장 위치가 OS 표준 경로).
- [ ] 파일 쓰기가 원자적이다(임시 파일 → 이름 변경).
- [ ] 지원 OS에서 동작을 확인했다(또는 확인하지 못한 OS를 명시했다).
- [ ] 플랫폼 분기가 한 곳에 모여 있다(메뉴·트레이·창 닫기 동작).

## 성능 DoD

- [ ] 콜드 스타트 경로에 새 작업을 추가했다면 그 비용을 측정했다([`frontend-performance.md`](./frontend-performance.md)).
- [ ] IPC를 루프 안에서 호출하지 않는다(배치로).
- [ ] 큰 데이터를 IPC로 통째 넘기지 않는다.
- [ ] 성능 목적의 변경이면 전/후 측정 숫자가 있다.

## Epic DoD

- [ ] 모든 P0 Story 완료.
- [ ] 내부 demo flow에서 해당 기능 사용 가능.
- [ ] 실패 시 로그·에러 표시로 원인 파악 가능.
- [ ] 다음 Epic이 의존하는 계약(IPC 채널·공용 컴포넌트 API) 문서화.
- [ ] **패키징된 앱에서** 핵심 경로가 동작한다(개발 모드 통과는 근거가 약하다).

## 커버리지

- 순수 로직·IPC 핸들러 ≥ 90%, 전체 ≥ 80%. 테스트 러너 설정에서 임계를 강제한다.
- **커버리지 숫자보다 행위 검증이 우선**이다. 렌더만 하고 단언이 없는 테스트로 숫자를 채우지 않는다.
- 구현 세부가 아니라 **사용자가 보는 것**을 기준으로 단언한다.
- main 로직은 Electron API를 얇게 감싼 어댑터 뒤에 두고, 그 어댑터를 대체해 테스트한다.
  Electron 전체를 목으로 흉내 내려 하지 않는다.
- E2E는 실제 앱을 띄워 확인한다(핵심 경로 1개 이상).

## 검증 절차

1. `bash scripts/verify.sh` 실행(= 구조 점검 → 포맷 → **프로세스 경계 가드** → lint → typecheck → 가드 → test → build)
2. 실패 시 수정 후 재검증 → 3. 결과 제시.
- 도구가 없으면 표준 도구로 셋업하고, 불가하면 그 사유를 명시한다.
- **게이트 통과는 "개발 모드에서 안 깨졌다"**이다. 패키징·서명·업데이트 경로 확인은 사람의 몫이다
  ([`verification-ladder.md`](./verification-ladder.md) L4).
- exec-plan 완료는 임의로 `completed/`로 옮기지 않는다. `check/`로 옮겨 사용자 검증을 요청한다([`agent-harness.md`](./agent-harness.md)).

> 상세 DoD 원본이 별도 백로그 문서에 있으면 여기 링크만 둔다(같은 내용을 두 곳에 두지 않는다).
