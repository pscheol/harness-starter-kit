# 설계 원칙 — 객체지향 · 클린 아키텍처 · SOLID (포인터)

원본: `.agents/rules/design-principles.md` — Claude·Codex·Kiro 공통. 클래스·인터페이스를 새로 만들거나 기존 설계를 바꾸기 전에 연다. 레이아웃·모듈 경계는 `ARCHITECTURE.md`·`.agents/rules/structure.md`가 정한다.

요약:
- **의존은 항상 안쪽(정책)을 향한다.** 도메인에 프레임워크 어노테이션·HTTP 타입·벤더 SDK가 들어오면 방향이 뒤집힌 것이다. 경계를 넘을 때 모델을 바꾼다(요청 DTO → 도메인 → 영속).
- **추상은 안쪽이 소유한다**(DIP). 저장소 인터페이스가 영속 패키지에 있으면 이름만 추상이다. 쓰는 쪽으로 옮기고 이름을 도메인 언어로 바꾼다.
- **인터페이스를 관성으로 만들지 않는다.** 구현이 하나뿐이고 테스트 대역도 필요 없으면 클래스만 둔다. (a) 레이어 경계 (b) 구현이 실제로 여럿 (c) 테스트 대체 — 셋 중 하나일 때만 값을 한다.
- **SRP는 "바뀌는 이유가 하나"**다. `Manager`·`Util`·`Facade` 이름과, 한 파일이 서로 다른 이유로 반복 수정되는 이력이 위반 신호다.
- **OCP**: 새 종류를 더할 때 분기 사슬을 찾아다니면 위반이다. 구현이 자기 식별자를 선언하고 조립 지점이 불변 맵으로 확정한다. 이름 문자열 매칭 금지, 미등록은 명시적 실패.
- **LSP**: 하위 구현이 "지원하지 않음"을 던지거나 호출부에 타입 검사가 생기면 그건 하위 타입이 아니다. 재사용 목적의 상속은 합성으로 바꾼다.
- **ISP**: 저장소 인터페이스는 애그리거트 단위로. `upsertByKeys` 같은 저장 메커니즘을 시그니처에 드러내지 않는다.
- **Tell, Don't Ask**: 접근자 여러 개 + 조건문이 호출부에 함께 나타나면 그 판단은 객체의 것이다. 반복되면 Anemic Domain Model. 단, 조회용 DTO는 빈약해도 된다.
- 객체는 **잘못된 상태로 존재할 수 없어야** 한다(생성 시점 불변식 검증). 불변이 기본, 컬렉션은 읽기 전용 뷰, 공유 카운터는 저장소의 원자적 연산으로.
- **과잉 설계가 원칙 위반보다 흔하다.** "이걸 넣으면 무엇이 쉬워지는가"에 한 문장으로 답 못 하면 넣지 않는다. 원칙을 어겨야 한다면 조용히 말고 ADR로.
