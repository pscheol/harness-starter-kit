# 재사용 우선 — 새로 만들기 전에 찾는다

새 파일·컴포넌트·유틸·타입·엔드포인트·설정 키를 만들기 전에 **이미 그 역할을 하는 것이 있는지 찾고,
찾은 결과를 남긴다.** 찾지 않고 만든 것은 리뷰에서 되돌린다.

## 1. 왜 이 규칙이 필요한가

에이전트에게는 **찾는 것보다 만드는 것이 싸다.** 리포 전체를 훑어 기존 날짜 포매터를 찾는 데는
검색 몇 번과 파일 읽기가 들지만, 새로 하나 쓰는 데는 다섯 줄이면 된다. 그래서 아무 장치가 없으면
같은 역할의 코드가 이름만 다른 채로 계속 늘어난다.

늘어난 뒤의 비용은 만들 때의 비용보다 훨씬 크다.

- 버그를 한 곳에서 고쳐도 나머지가 남는다. 어느 것이 쓰이는지 아무도 모른다.
- 두 구현의 동작이 미세하게 다르면 그 차이가 그대로 사용자에게 나간다.
- 다음 에이전트는 "기존 것"이 무엇인지 판단할 근거를 잃는다 — 후보가 셋이면 넷째를 만든다.

## 2. Inventory — 만들기 전에 하는 검색

새로 만들려는 것마다 **세 갈래로** 검색한다. 하나만 하면 놓친다.

| 갈래 | 무엇으로 찾나 | 예 |
|---|---|---|
| 이름 | 역할 이름 + 흔한 동의어 | `format` · `formatter` · `toDisplay` · `render*` · `*Text` |
| 시그니처 | 입력·출력 타입의 조합 | 날짜를 받아 문자열을 반환하는 함수 |
| 위치 | 그 역할이 놓일 만한 디렉터리 | 공용 유틸 · 공유 모듈 · 해당 기능 폴더 |

검색은 파일 이름이 아니라 **내용**으로 한다. 파일 이름은 역할을 배신한다.

```text
✗ 디렉터리 목록만 훑기      — 이름이 다르면 못 찾는다
✓ 내용 검색으로 역할·시그니처·호출부를 함께 본다
```

## 3. 판정 — 셋 중 하나로 끝낸다

| 판정 | 조건 | 해야 할 일 |
|---|---|---|
| 재사용 | 기존 것이 요구를 그대로 만족한다 | 그대로 쓴다. 감싸는 래퍼를 새로 만들지 않는다 |
| 확장 | 기존 것이 대부분 맞고 나머지가 인자·옵션으로 흡수된다 | **기존 것을 고친다.** 호출부 전부를 함께 확인한다 |
| 신규 | 역할이 실제로 다르거나, 확장하면 기존 사용처가 깨진다 | 만든다. **왜 기존 것으로 안 되는지**를 근거로 남긴다 |

"확장하면 복잡해져서"는 신규의 근거가 아니다. 그건 판단이지 사실이 아니다.
근거는 **기존 것으로 안 되는 구체적 지점**이어야 한다 — 다른 입력 계약, 다른 트랜잭션 경계,
다른 실패 정책 같은 것.

## 4. 기록 — 남기지 않으면 하지 않은 것이다

Inventory 결과는 그 변경의 design 문서(`.agents/docs/<slug>-specs/design/<feature>.md`) 결정 절에
남긴다. design 문서가 없는 작은 변경이면 커밋 본문에 한 줄로 남긴다.

```text
Inventory: 공용 날짜 포매터 1개 · 주문 기능 내부 포매터 1개 확인.
신규 사유 — 둘 다 로컬 타임존 고정이라 UTC 표시 요구를 만족하지 못한다.
확장하면 기존 호출부 14곳의 출력이 함께 바뀐다.
```

형식은 짧게. 검색 로그를 붙여넣지 않는다(`writing-style.md`).

## 5. 어디에 적용하나

- 컴포넌트·훅·유틸·헬퍼 함수
- 타입·스키마·DTO — 같은 개념에 이름만 다른 타입이 생기는 것이 가장 흔한 실패다
- API 엔드포인트·이벤트 이름·큐 이름
- 설정 키·환경변수
- `scripts/` — **검증 로직은 특히** 한 곳뿐이어야 한다(`agent-harness.md` 의 "1곳 + N트리거")
- 규칙 문서 자체 — 새 규칙을 만들기 전에 기존 규칙에 절을 더할 수 있는지 본다

적용하지 않아도 되는 것: 테스트 픽스처, 일회성 마이그레이션 스크립트, 버려질 스파이크 코드.

## 6. 자동화로 잡히는 영역

여기 적힌 것은 도구가 잡는다. **리뷰에서 사람이 다시 지적하지 않는다**(`pr-review-policy.md`).

- [ ] 중복 코드 탐지 — 린터·정적 분석의 duplication 규칙
- [ ] 미사용 export 탐지 — dead code 도구
- [ ] 순환 의존 — 구조 검사(`structure.md` 의 강제 수단)

도구가 없는 항목이 이 규칙이 사람과 에이전트에게 맡기는 부분이다.

## 7. 안티-규칙 — 이 규칙을 근거로 하면 안 되는 것

- ❌ "비슷하니까 합치자" — 역할이 다른데 형태만 닮은 것을 합치면 조건 분기만 늘어난다.
- ❌ 기존 코드를 찾았다는 이유로 **요구를 낮추는 것.** 요구가 먼저다.
- ❌ 이 규칙을 근거로 대규모 통합 리팩터링을 시작하는 것. 별도 작업으로 등록한다
      (`.agents/docs/tech-debt-tracker.md`).
- ❌ 재사용 대상이 명백히 잘못 만들어졌는데 그대로 쓰는 것. 고치거나, 못 고치는 이유를 남긴다.
