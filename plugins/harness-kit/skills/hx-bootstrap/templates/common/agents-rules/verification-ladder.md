# 검증 사다리 — "테스트했다"가 무슨 뜻인지 정한다

변경마다 **어느 수준까지 검증했는지**를 같은 언어로 말한다. 수준을 정하지 않으면
"확인했습니다"가 타입 검사만 돌린 것인지 실제로 실행해 본 것인지 알 수 없고,
그 순간 검증 생략이 통과로 읽힌다.

## 1. 다섯 단계

| 레벨 | 이름 | 무엇을 보장하나 | 누가 돌리나 |
|---|---|---|---|
| L0 | 정적 | 포맷·린트·타입·구조 규칙 위반이 없다 | 에이전트 hook(`fast`) · 저장 시 |
| L1 | 단위 | 바뀐 함수·클래스의 입출력이 명세대로다 | 사람/에이전트 · `verify.sh`(`full`) |
| L2 | 통합·계약 | 인접 경계(저장소·외부 API·모듈 간)와 실제로 맞물린다 | `verify.sh`(`full`) · CI |
| L3 | 시스템 | 사용자 시나리오가 처음부터 끝까지 동작한다 | CI · 릴리스 전 |
| L4 | 사람 확인 | 눈으로 봐야 아는 것(레이아웃·문구·감각·운영 영향) | 사람 |

**L0 는 검증이 아니라 전제다.** L0 만 통과한 상태를 "검증했다"고 말하지 않는다.

## 2. 변경 종류 → 최소 레벨

| 변경 | 최소 | 이유 |
|---|---|---|
| 오타·주석·문서 | L0 | 동작이 바뀌지 않는다 |
| 순수 함수·유틸 | L1 | 입출력이 계약의 전부다 |
| 상태를 바꾸는 로직(저장·결제·권한) | L2 | 경계 밖의 부작용이 본체다 |
| 외부 시스템 연동 추가·변경 | L2 | 계약이 맞는지는 단위 테스트로 알 수 없다 |
| 사용자 흐름이 바뀌는 변경 | L3 | 화면·라우팅·권한이 함께 움직인다 |
| 눈에 보이는 변경(레이아웃·카피·모션) | L4 | 통과 기준을 기계가 판정할 수 없다 |
| 마이그레이션·인프라·릴리스 설정 | L2 + L4 | 되돌리기 비용이 크다 |

상한이 아니라 **하한**이다. 위험하다고 느끼면 한 단계 올린다.

## 3. 생략은 허용한다 — 대신 보이게 한다

막으면 사람은 게이트 자체를 우회한다. 그래서 생략은 허용하되 **반드시 기록**한다.
기록 없는 생략은 거짓 보고로 취급한다.

작업을 마칠 때 다음 블록을 보고에 넣는다. 기계가 읽을 수 있게 ASCII 키/값만 쓴다.

```text
[VERIFICATION]
level: L2
ran: 타입 검사 · 단위 42 · 주문 저장소 통합 3
skipped: L3 (E2E 러너 미구성 — tech-debt-tracker 에 등록)
residualRisk: 동시 주문 시 재고 차감 경합은 검증 못 했다
```

- `skipped` 에는 **무엇을**과 **왜**를 함께 쓴다. "시간이 없어서"는 사유가 아니다.
- 반복되는 생략은 부채다 — `.agents/docs/tech-debt-tracker.md` 에 등록한다.

## 4. 게이트와의 관계

`scripts/verify.sh` 한 곳이 강제 지점이고, 레벨은 `HARNESS_VERIFY_LEVEL` 로 나뉜다
(`agent-harness.md` 의 "1곳 + N트리거").

| 게이트 | 도는 레벨 | 왜 |
|---|---|---|
| 에이전트 Stop hook | `fast` = L0 | 턴마다 돈다. 빌드가 겹치면 lock 경합으로 멈춘다 |
| pre-push · CI | `full` = L0~L2 | 여기가 실제 방어선이다 |
| 릴리스 | `full` + L3 | 시나리오는 릴리스 단위로 본다 |

**hook 통과는 full 통과가 아니다.** 커밋·푸시 전에 `bash scripts/verify.sh` 를 직접 돌린다.

## 5. 테스트가 없는 코드를 만났을 때

기존 코드에 테스트가 없다고 해서 이번 변경까지 L0 로 내리지 않는다.
바꾼 범위에 대해서만 최소 레벨을 채우고, 나머지는 부채로 등록한다.

```text
✓ 이번에 바꾼 할인 계산에 단위 테스트 3개 추가(L1). 주변 레거시는 그대로 두고 부채 등록.
✗ 이 파일엔 원래 테스트가 없어서 안 썼다.
```

## 6. 자동화로 잡히는 영역

- [ ] L0 전부 — 포맷·린트·타입·구조 규칙(`verify.sh` 의 앞 단계)
- [ ] 커버리지 임계 — `quality-score.md` 의 기준값
- [ ] 테스트 실행 자체 — CI

## 7. 안티-규칙

- ❌ 레벨을 올리는 것 자체를 목표로 삼는 것. 오타 수정에 E2E 를 요구하지 않는다.
- ❌ 커버리지 숫자를 채우려고 단언 없는 테스트를 쓰는 것. 그건 L1 이 아니다.
- ❌ 사람 확인(L4)을 에이전트가 대신 선언하는 것. "화면이 잘 나옵니다"는 근거가 아니다.
- ❌ 이 규칙을 근거로 리뷰에서 L0 항목(들여쓰기·임포트 정렬)을 지적하는 것(`pr-review-policy.md`).
