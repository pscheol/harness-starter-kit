# 리뷰 정책 — 무엇을 보고, 무엇을 보지 않나

리뷰의 목적은 **자동화가 못 잡는 것을 잡는 것**이다. 도구가 이미 잡는 것을 사람이나
에이전트가 다시 지적하면 그만큼 로직 검토가 줄고, 몇 번 반복되면 리뷰 출력 전체가 무시된다.

## 1. 자동화 위임 — 여기 적힌 것은 리뷰에서 언급하지 않는다

각 규칙 문서의 "자동화로 잡히는 영역" 절이 위임 선언이다. 그 항목은 **리뷰 코멘트 금지**다.

| 영역 | 잡는 도구 | 리뷰에서 |
|---|---|---|
| 들여쓰기·따옴표·줄바꿈·임포트 정렬 | 포매터 | 금지 |
| 미사용 변수·임포트·불가능한 분기 | 린터 | 금지 |
| 타입 오류·널 안전성 | 타입 검사 | 금지 |
| 레이어·모듈 의존 방향 | 구조 검사(`structure.md`) | 금지 |
| 커버리지 임계 | 게이트(`quality-score.md`) | 금지 |

도구가 잡는데도 통과했다면 그건 **도구 설정의 결함**이다. 코멘트가 아니라 설정을 고친다.

## 2. 리뷰가 실제로 보는 것

우선순위 순이다. 위에서 걸리면 아래는 보지 않아도 된다.

1. **정확성** — 요구사항(`requirements`)과 다르게 동작하는가. 경계·실패 경로가 빠졌는가.
2. **안전성** — 권한·입력 검증·비밀값 취급(`security.md`). 되돌릴 수 없는 연산.
3. **계약** — 공개 인터페이스·이벤트·저장 스키마가 호환되는가. 마이그레이션 순서가 맞는가.
4. **경계** — 책임이 제자리에 있는가(`design-principles.md`·`structure.md`).
5. **재사용** — Inventory 를 했는가, 판정 근거가 남았는가(`reuse-before-new.md`).
6. **검증** — 변경 종류에 맞는 최소 레벨을 채웠는가(`verification-ladder.md`).
7. **읽힘** — 이름이 역할을 말하는가. 주석이 Why 를 담는가(`code-comments.md`·`writing-style.md`).

## 3. 지적 형식

지적 하나는 **위치 · 무엇이 · 왜 · 어떻게** 네 조각을 갖는다. 하나라도 빠지면 무시된다.

```text
✗ 이 부분 개선이 필요해 보입니다.

✓ [HIGH] 결제 처리 모듈 :142
  결제 실패 시 재고 예약이 해제되지 않는다. 예외 경로에 보상 처리가 없다.
  근거: reliability.md — 되돌릴 수 없는 연산은 짝이 되는 보상을 함께 둔다.
  제안: 예약 해제를 실패 경로로 옮기거나 보상 트랜잭션으로 분리한다.
```

## 4. 심각도와 머지 기준

| 심각도 | 뜻 | 머지 |
|---|---|---|
| CRITICAL | 보안 결함·데이터 손실·되돌릴 수 없는 오동작 | 막는다 |
| HIGH | 명세와 다른 동작·계약 파손·검증 미달 | 고친 뒤 머지 |
| MEDIUM | 유지보수성 — 지금 안 고쳐도 동작한다 | 합의 후 부채 등록 가능 |
| LOW | 취향·사소한 개선 제안 | 참고. 반려해도 된다 |

- CRITICAL·HIGH 가 없으면 승인한다. LOW 를 근거로 승인을 미루지 않는다.
- MEDIUM 을 미룬다면 `.agents/docs/tech-debt-tracker.md` 에 등록한다. 등록 없는 유예는 망각이다.

## 5. Negative knowledge — 알지만 지금은 안 고치기로 한 것

> 설치 후 채운다. **이 표가 비어 있으면 리뷰어는 매번 같은 것을 지적하고, 그 지적은 매번 무시된다.**

| 항목 | 왜 그대로 두나 | 언제 다시 보나 |
|---|---|---|
| | | |

여기 적힌 것은 **리뷰에서 지적하지 않는다.** 다시 보기로 한 시점이 오면 표에서 지우고 부채로 옮긴다.

## 6. 중점 점검 영역

> 설치 후 채운다. 이 프로젝트에서 실제로 사고가 났던 자리다.

| 영역 | 무엇을 특히 보나 |
|---|---|
| | |

## 7. 에이전트가 리뷰할 때

- 지적은 **최대 7개**까지. 더 많으면 우선순위 위쪽만 남긴다. 스무 개짜리 목록은 읽히지 않는다.
- 파일을 읽지 않고 지적하지 않는다(`guardrails.md` 추측 금지).
- 같은 원인이 여러 파일에 퍼져 있으면 **한 건으로 묶고** 대표 위치만 든다.
- 칭찬·요약·인사를 쓰지 않는다. 발견이 없으면 "없음"이라고 쓴다(`writing-style.md`).

## 8. 안티-규칙

- ❌ 자동화 위임 항목을 다시 지적하는 것(§1).
- ❌ 이번 변경 범위 밖의 코드를 지적하는 것. 별건은 부채로 등록한다.
- ❌ 대안 없이 "이렇게 하면 안 된다"만 쓰는 것.
- ❌ 취향 차이를 HIGH 로 올리는 것. 근거가 규칙 문서에 없으면 LOW 다.
