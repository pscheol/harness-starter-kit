# 플랫폼 불변식 — 문서에서 게이트로 승격시킨다

이 리포에는 "반드시 이래야 한다"가 몇 가지 있다. 그중 **말로만 남은 것은 반드시 깨진다.**
이 규칙은 불변식을 문서 → 경고 → 강제 3단으로 올리는 절차를 정한다.

## 1. 왜 3단인가

규칙을 문서에만 두면 새로 온 사람과 에이전트가 모른다. 반대로 처음부터 강제로 걸면
기존 위반 때문에 무관한 작업이 막히고, 그러면 그 가드는 곧 지워지거나 우회된다.

그래서 순서가 있다.

| 단계 | 형태 | 언제 |
|---|---|---|
| 1. 문서 | 규칙 파일의 한 줄 | 불변식을 막 발견했다. 아직 기계로 표현할 방법을 모른다 |
| 2. 경고 가드 | `scripts/guards/<name>.sh` + `harness-guard-enforce: 0` | 검사 방법을 찾았다. 기존 위반이 남아 있다 |
| 3. 강제 가드 | 같은 파일 + `harness-guard-enforce: 1` | 위반 0건이 됐다. 이제 되돌아가지 않게 못 박는다 |

**2단계를 건너뛰지 않는다.** 경고 단계에서 위반 목록이 곧 정리 작업 목록이 된다.

## 2. 무엇이 불변식인가

가드로 만들 가치가 있는 것은 **어겼을 때 조용히 나쁜 일이 생기는 것**이다.

쓸 만한 것:

- 경계 위반 — 이 레이어가 저 모듈을 알면 안 된다(린터로 안 잡히는 형태).
- 값의 출처 — 설정·비밀·경로를 정해진 곳 밖에서 읽는다.
- 위험 설정 — 보안 옵션을 끄는 코드.
- 금지 API — 이 프로젝트에서 쓰지 않기로 한 함수·패턴.
- 명명·배치 규약 중 **자동으로 확인 가능한 것**.

가드로 만들지 말 것:

- 취향(포매터·린터가 이미 하는 일).
- 판단이 필요한 것("이 추상화가 적절한가").
- 위반이 눈에 바로 보이는 것(리뷰가 더 싸다).
- 자주 정당한 예외가 생기는 것 — 예외가 규칙보다 많으면 그건 규칙이 아니다.

## 3. 가드 만들기

1. `scripts/guards/_template.sh`를 복제한다. **파일명이 가드 이름**이다(`no-direct-env-access.sh`).
2. 헤더에 **무엇을 왜** 검사하는지 한 줄로 적는다. 이유가 없으면 다음 사람이 지운다.
3. `harness-guard-enforce: 0`으로 시작한다.
4. 위반 위치를 `파일:줄` 형식으로 출력하고, **어떻게 고치는지** 한 줄을 덧붙인다.
   고치는 방법이 없는 가드는 잔소리다.
5. 통과할 때는 아무것도 출력하지 않는다.

```bash
bash scripts/run-guards.sh          # 전부 실행(경고는 통과, 강제는 차단)
GUARD_ENFORCE=1 bash scripts/run-guards.sh   # 릴리스 전 점검 — 경고까지 실패로 본다
```

가드는 `scripts/verify.sh`가 **파일 존재만으로 자동 호출**한다. 배선 작업이 없다.

## 4. 승격 · 강등

**승격(0 → 1)**: 위반이 0건이 된 날 올린다. 미루면 다시 늘어난다.
올릴 때 무엇을 정리했는지 커밋 본문에 한 줄 남긴다.

**강등(1 → 0)**: 대규모 리팩터링처럼 일시적으로 위반이 생길 때만. **되돌릴 시점을 함께 적는다.**
시점 없는 강등은 삭제와 같다.

**삭제**: 규칙 자체가 바뀌었을 때만. 가드가 불편하다는 이유로 지우지 않는다.
지운다면 `.agents/docs/decisions/`에 왜 더는 불변식이 아닌지 남긴다.

## 5. 예외 처리

- 예외는 **가드 안에서** 표현한다(경로 제외·주석 마커). 가드를 끄지 않는다.
- 예외에는 이유를 코드 주석으로 남긴다.
- 예외가 세 개를 넘으면 규칙을 다시 본다. 규칙이 현실과 안 맞는 것이다.

## 6. 자동화로 잡히는 영역

여기 적힌 것은 도구가 잡는다. **리뷰에서 다시 지적하지 않는다**(`pr-review-policy.md`).

- [ ] 강제 가드가 검사하는 모든 것 — 게이트가 막는다
- [ ] 경고 가드가 검사하는 것 — 목록이 곧 정리 작업이다
- [ ] 린터·포매터·타입 검사가 잡는 것 — 가드로 중복 구현하지 않는다

## 7. 안티-규칙

- ❌ 새 가드를 곧바로 강제(1)로 만들어 무관한 작업을 막는 것.
- ❌ 위반 위치를 안 찍고 "위반이 있습니다"만 출력하는 가드.
- ❌ 린터가 이미 하는 일을 가드로 다시 구현하는 것.
- ❌ 경고 가드를 몇 달째 경고로 두는 것 — 아무도 안 보는 경고는 없는 것과 같다.
      올리거나 지운다.
- ❌ 가드를 우회하려고 코드를 이상하게 쓰는 것. 그럴 바엔 규칙을 고친다.
