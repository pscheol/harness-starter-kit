# 이슈 트래커 작업 규약 — 티켓이 거짓말하지 않게

설정 원본은 `.agents/issue-tracker.yml`이다. 이 문서는 **무엇을 언제 하는가**를 정하고,
그 파일은 **어떤 ID로 하는가**를 정한다.

## 1. 왜 규약이 필요한가

티켓 상태는 사람들이 "지금 무슨 일이 벌어지고 있는가"를 판단하는 근거다.
에이전트가 여기에 손을 대기 시작하면 두 가지가 망가진다.

- **상태가 실제와 갈린다** — 코드는 리뷰 중인데 티켓은 To Do다. 또는 반대다.
- **여러 작업자가 같은 티켓을 잡는다** — 사람과 에이전트, 또는 에이전트 둘.

이 규약은 그 두 가지만 막는다. 트래커 사용법을 통째로 정하려는 문서가 아니다.

## 2. 한 세션 = 한 활성 티켓

**한 세션에서 동시에 두 티켓을 진행하지 않는다.**

- 작업 시작 시 대상 티켓을 명시하고, 그 세션이 끝날 때까지 바꾸지 않는다.
- 다른 티켓을 만져야 한다면 **지금 티켓을 정리하고**(리뷰 요청 또는 착수 철회) 넘어간다.
- "잠깐 이것도" 가 티켓과 커밋의 대응을 무너뜨린다. 한 커밋이 두 티켓을 건드리면
  나중에 되돌릴 단위가 사라진다.
- 예외: 진행 중 티켓을 막고 있는 사소한 결함은 같은 커밋에 포함하되 **커밋 본문에 명시**한다.

## 3. Pull gate — 착수 전에 최신 상태를 읽는다

착수 직전에 **트래커에서 그 티켓을 다시 읽는다.** 캐시된 정보로 시작하지 않는다.

읽고 확인할 것:

1. **상태** — 이미 진행 중이거나 리뷰 중이면 착수하지 않는다.
2. **담당자** — 다른 사람이 잡고 있으면 착수하지 않는다.
3. **락** — 다른 에이전트의 유효한 락이 있으면 착수하지 않는다(`issue-agent-lock.md`).
4. **요구사항 변경** — 마지막으로 본 이후 설명·코멘트가 바뀌었는지.

하나라도 걸리면 **사용자에게 알리고 멈춘다.** 뚫고 들어가지 않는다.

## 4. 상태 전이 — 표시 이름이 아니라 ID로

- 전이는 `.agents/issue-tracker.yml`의 `transitionIds`로만 한다.
- **표시 이름으로 전이하지 않는다.** 이름은 번역·워크플로 수정으로 바뀌고, 바뀌면 자동화가
  실패하는 게 아니라 **조용히 엉뚱한 상태로 옮긴다.**
- `statusIds`와 `transitionIds`는 다른 값이다. 상태는 "어디에 있는가", 전이는 "어떻게 옮기는가"다.
  전이 ID는 **현재 상태에 따라 달라진다** — 트래커에서 그 이슈의 전이 목록을 조회해 확인한다.
- 설정에 `TBD`가 남아 있으면 **읽기만 하고 전이하지 않는다.** 잘못된 ID로 옮기는 것보다 안 옮기는 게 낫다.

## 5. 에이전트가 넘지 않는 선

| 동작 | 에이전트 | 근거 |
|---|---|---|
| 티켓 읽기·요약 | ✅ | |
| To Do → In Progress | ✅ | 락 획득과 함께 |
| In Progress → In Review | ✅ | **여기까지다** |
| In Review → Done / Close | ❌ | 완료 판단은 사람의 것이다 |
| 담당자 변경 | ❌ | 조직의 일이다 |
| 설명(요구사항) 수정 | ❌ | 원문을 에이전트가 고쳐 쓰지 않는다 |
| 코멘트 추가 | ✅ | 아래 규약대로 |
| 티켓 생성 | `mayCreate: true` **그리고** 사용자가 명시적으로 요청했을 때만 | 자동 생성은 보드를 노이즈로 채운다 |

- 이 표는 `.agents/issue-tracker.yml`의 `agentBoundary`와 같은 내용이다. **둘이 갈리면 설정이 이긴다.**
- 넓히려면 왜 필요한지 `.agents/docs/decisions/`에 남긴다.
- exec-plan 완료 게이트와 같은 원칙이다: 에이전트는 `check`까지, 완료는 사용자가 한다
  (`agent-harness.md`).

## 6. 코멘트 규약

**남기는 것** — 그 티켓을 보는 사람이 알아야 할 것만.

- **착수**: 누가(세션 식별자)·언제·어느 브랜치.
- **리뷰 요청**: PR 링크 · 검증 게이트 결과 한 줄 · 사람이 확인해야 할 것(특히 L4 항목).
- **막힘**: 무엇이 막았는지 · 무엇이 있으면 풀리는지. 추측을 적지 않는다.

**남기지 않는 것**

- 진행 상황 중계("파일 3개를 수정했습니다"). 커밋이 이미 한다.
- 검증 게이트 출력 전문. 결과 한 줄 + 링크면 된다.
- 코드 블록 덤프. 코드는 PR에 있다.
- 내부 경로·비밀·에러 스택.

코멘트는 사람이 읽는 글이다(`writing-style.md`). 작업 일지체를 쓰지 않는다.

## 7. 브랜치·커밋·PR

- 브랜치 이름에 티켓 키를 넣는다(패턴은 `issueKeyPattern`).
- 커밋 제목이나 본문에 티켓 키를 넣는다. 트래커가 커밋을 티켓에 연결한다.
- PR 제목에 티켓 키 + 한 줄 요약. 본문에 티켓 링크.
- **티켓 없는 변경**도 있다(오타 수정·문서). 그때는 규약을 억지로 적용하지 않는다.

## 8. 실패했을 때

- 트래커 API 호출이 실패하면 **작업을 멈추지 않는다.** 코드 작업은 계속하고,
  트래커 반영이 안 됐다는 사실을 사용자에게 알린다.
- 전이가 거부되면(권한 없음·워크플로상 불가) 그대로 보고한다. 다른 전이로 우회하지 않는다.
- 락 획득에 실패하면 착수하지 않는다(`issue-agent-lock.md`).
- **부분 성공을 성공으로 보고하지 않는다.** 상태는 바뀌었는데 코멘트가 실패했다면 그렇게 적는다.

## 9. 티켓 생성 (`mayCreate: true` 일 때만)

기본은 꺼져 있다. 켰더라도 **사용자가 만들라고 했을 때만** 만든다. 작업 중에 "이것도 티켓이 필요하겠네"
라고 판단해 스스로 만들지 않는다.

- 만들기 전에 **필수 필드를 사용자에게 확인받는다** — 프로젝트·이슈 타입·제목·설명. 지어내지 않는다.
- 중복을 먼저 확인한다. 같은 내용의 티켓이 이미 있으면 만들지 말고 그것을 알린다.
- 만든 뒤 **자동으로 착수하지 않는다.** 생성과 착수는 다른 결정이다. 키를 보고하고 멈춘다.
- 담당자·스프린트·우선순위는 비워 둔다. 조직의 판단이다.
- 여러 개를 한 번에 만들지 않는다. 분해가 필요하면 그 분해안을 먼저 사용자에게 보인다.

## 10. SDD 와 이어 붙이기

티켓과 SDD 문서는 **같은 작업의 두 기록**이다. 어긋나면 둘 다 신뢰를 잃는다.

| 티켓 상태 | 이 리포에서 대응하는 상태 |
|---|---|
| To Do | 스펙 없음, 또는 requirements 초안(`draft`) |
| In Progress | requirements~tasks 진행 중, tasks 가 `tasks/active/` |
| In Review | 구현 완료 + 게이트 통과, tasks 가 `tasks/check/` |
| Done | 사용자 승인 후 tasks 가 `tasks/completed/` — **에이전트는 여기까지 가지 않는다** |

- **착수 전이가 먼저다.** SDD 부터 시작하면 "코드는 진행 중인데 티켓은 To Do"가 된다.
- **티켓 본문을 requirements 로 복사하지 않는다.** 티켓은 배경·요청이고 requirements 는 "무엇을·왜"다.
  티켓에서 뽑는 것: 배경·사용자·성공 조건·제약. 뽑지 않는 것: 구현 지시·담당자·일정.
- 티켓에 없어 추측해야 하는 것은 `[NEEDS CLARIFICATION]` 으로 남긴다. 티켓에 없다고 지어내지 않는다.
- **requirements 상단에 티켓 키를 남긴다.** 나중에 이 기능이 왜 있는지 되짚는 유일한 실마리다.
- 리뷰 요청(⑥)에서 **티켓 전이와 tasks 이동을 함께** 한다. 하나만 하면 그 순간부터 보드가 거짓말한다.
- 이 흐름을 한 번에 도는 명령이 `/hx-ticket` 이다. 트래커만 만지려면 `/hx-issue`.

## 11. 안티-규칙

- ❌ 표시 이름으로 상태를 전이하는 것.
- ❌ 설정이 `TBD`인 채로 자동 전이를 켜는 것.
- ❌ 티켓을 Done으로 옮기는 것.
- ❌ 한 세션에서 여러 티켓을 동시에 진행하는 것.
- ❌ 락을 확인하지 않고 착수하는 것, 남의 락을 임의로 깨는 것.
- ❌ 진행 상황을 코멘트로 중계해 티켓을 로그로 만드는 것.
- ❌ 트래커 반영 실패를 조용히 넘기는 것.
