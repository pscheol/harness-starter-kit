규약 원본 `.agents/rules/issue-tracker-workflow.md` 와 `.agents/rules/sdd-workflow.md` 를 로드해 그대로 수행한다.
설정 원본은 `.agents/issue-tracker.yml`.

**이 명령은 두 흐름을 잇는다.** 트래커의 티켓 상태와 SDD 단계 문서가 **서로 어긋나지 않게** 하는 것이 목적이다.
트래커만 만지고 싶으면 `/hx-issue`, SDD 단계만 밟고 싶으면 `/hx-specify` 계열을 직접 쓴다.

## 시작 전 확인 (건너뛰지 않는다)

1. `.agents/issue-tracker.yml` 을 읽는다. `access.method` 가 `TBD` 면 **트래커에 접근할 수단이 없다** —
   그 사실을 알리고 `hx-jira-setup` 스킬로 안내한다. 추측으로 API를 부르지 않는다.
2. `statusIds`·`transitionIds` 에 `TBD` 가 있으면 **읽기 전용 모드**로 진행한다(전이·코멘트 없이 SDD만).
3. 이미 활성 티켓이 있으면 멈춘다. **한 세션 = 한 활성 티켓.**

## 흐름

| 단계 | 트래커 | SDD | 게이트 |
|---|---|---|---|
| ① 가져오기 | 티켓 조회 + pull gate(상태·담당자·락·요구사항 변경) | — | 하나라도 걸리면 **멈추고 알린다** |
| ② 착수 | 락 획득 → In Progress 전이 → 착수 코멘트 | 제품 slug·기능 이름 확정 | 락 실패 시 착수하지 않는다 |
| ③ 스펙 | — | `/hx-specify` — 티켓 본문을 **요구사항의 입력**으로 쓴다 | 사용자 승인 |
| ④ 설계·분해 | — | `/hx-plan` → `/hx-tasks` | 각 단계 승인 |
| ⑤ 구현 | — | `/hx-implement` (`scripts/verify.sh` 통과) | 완료 게이트는 `check/` 까지 |
| ⑥ 리뷰 요청 | In Review 전이 → PR 링크 코멘트 → **락 해제** | tasks 는 `check/` 에 둔다 | Done 으로 옮기지 않는다 |

- **`--from-ticket` 인자를 주면 ①~③ 까지만** 하고 멈춘다(스펙 초안까지만 보고 싶을 때).
- **`--resume` 이면** 진행 중인 티켓을 이어받는다(락 소유자가 자신인지 확인 후).

## 티켓 본문 → 요구사항 변환 규칙

- 티켓 설명을 **그대로 복사하지 않는다.** requirements 는 "무엇을·왜"이고 티켓은 대개 그 둘이 섞여 있다.
- 티켓에서 뽑아 쓰는 것: 배경·사용자·성공 조건·제약. 뽑지 않는 것: 구현 지시·담당자·일정.
- 티켓에 없어서 추측해야 하는 것은 **`[NEEDS CLARIFICATION]`** 으로 남기고 `/hx-clarify` 로 넘긴다.
  티켓에 없다는 이유로 지어내지 않는다.
- requirements 상단에 **티켓 키를 추적 근거로 남긴다.** 나중에 왜 이 기능이 있는지 되짚는 유일한 실마리다.
- 티켓 설명을 에이전트가 고쳐 쓰지 않는다(`agentBoundary.mayEditDescription`).

## 상태가 어긋나는 지점 (여기서 사고가 난다)

- **SDD 는 진행됐는데 티켓은 To Do** — ② 를 건너뛰고 ③ 부터 시작하면 이렇게 된다. 착수 전이를 먼저 한다.
- **티켓은 In Review 인데 tasks 는 `active/`** — ⑥ 에서 tasks 를 `check/` 로 옮기지 않았다. 둘을 같이 옮긴다.
- **티켓은 Done 인데 코드는 미완** — 에이전트는 Done 으로 옮기지 않는다. 사람이 옮겼다면 그 사실을 보고한다.
- 트래커 호출이 실패하면 **코드 작업은 계속하되 반영이 안 됐다는 사실을 알린다.** 부분 성공을 성공으로 적지 않는다.

## 핵심

1. **한 세션 = 한 활성 티켓.** 다른 티켓을 만져야 하면 지금 것을 정리하고 넘어간다.
2. **전이는 `transitionIds` 로만.** 표시 이름으로 옮기지 않는다.
3. **에이전트는 In Review 까지.** Done·Close·담당자 변경·설명 수정은 하지 않는다.
4. 락은 쓴 뒤 **다시 읽어 자기 것인지 확인**한다.
5. 각 SDD 단계는 **사용자 승인**을 받는다. 티켓이 있다고 게이트를 건너뛰지 않는다.
6. 실패는 그대로 보고한다.

> Jira 를 안 쓰는 프로젝트에서는 이 명령이 설치되지 않는다(`--modules=jira-workflow` 를 켠 리포에만 있다).
> 그때는 `/hx-specify` 부터 시작하는 평소 SDD 흐름을 쓴다.
