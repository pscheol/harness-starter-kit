## 0. 먼저 확인 (건너뛰지 않는다)

1. **접근 수단** — `access.method` 가 `TBD` 이거나 `none` 이면 **트래커를 부르지 않는다.**
   "연동 수단이 없다"고 알리고 `hx-jira-setup` 스킬로 안내한다. 도구를 짐작해 호출하지 않는다.
2. **ID 채움 여부** — `statusIds`·`transitionIds` 에 `TBD` 가 있으면 **읽기만** 하고 상태를 바꾸지 않는다.
3. `method: rest` 면 토큰은 `restTokenEnv` 에 적힌 **환경변수에서** 읽는다. 설정 파일에 값이 있으면 그것이 결함이다.

## 서브커맨드

| 형태 | 하는 일 |
|---|---|
| `<키>` (또는 생략) | 티켓을 읽어 요약. **상태를 바꾸지 않는다** |
| `start <키>` | pull gate → 락 획득 → In Progress 전이 → 착수 코멘트 → 브랜치 이름 제안 |
| `review <키>` | 검증 게이트 결과 확인 → In Review 전이 → PR 링크 코멘트 → 락 해제 |
| `drop <키>` | 착수 철회 — To Do 되돌림 + 락 해제 |
| `unlock <키>` | stale 락 보고. **사용자 승인 후에만** 해제하고 코멘트를 남긴다 |
| `create` | **`agentBoundary.mayCreate: true` 이고 사용자가 명시적으로 요청했을 때만.** 아래 절차 |

### `create` 절차

1. `mayCreate` 가 `false` 면 그 사실을 알리고 멈춘다. 설정을 임의로 바꾸지 않는다.
2. **필수 필드를 사용자에게 확인받는다** — 프로젝트·이슈 타입·제목·설명. 지어내지 않는다.
3. **중복을 먼저 검색한다.** 같은 내용의 티켓이 있으면 만들지 말고 그것을 보여 준다.
4. 담당자·스프린트·우선순위는 비워 둔다(조직의 판단이다).
5. 만든 뒤 **자동으로 착수하지 않는다.** 키를 보고하고 멈춘다 — 생성과 착수는 다른 결정이다.
6. 여러 개를 한 번에 만들지 않는다. 분해가 필요하면 분해안을 먼저 보인다.

## 핵심

1. **Pull gate** — 착수 직전에 티켓을 다시 읽는다(상태·담당자·락·요구사항 변경). 하나라도 걸리면 멈추고 알린다.
2. **전이는 `transitionIds` 로만.** 표시 이름으로 옮기지 않는다 — 조용히 엉뚱한 상태가 된다.
3. **에이전트는 In Review 까지.** Done·Close·담당자 변경·설명 수정은 하지 않는다.
4. **한 세션 = 한 활성 티켓.** 다른 티켓을 만져야 하면 지금 것을 정리하고 넘어간다.
5. 락은 쓴 뒤 **다시 읽어 자기 것인지 확인**한다. 실패하면 착수하지 않는다.
6. 실패는 그대로 보고한다. **부분 성공을 성공으로 적지 않는다**(상태는 바뀌고 코멘트는 실패한 경우 등).

> 이 명령은 **트래커만** 다룬다. 티켓을 받아 SDD 스펙을 쓰고 구현해 리뷰까지 올리는 **전 여정**은 `/hx-ticket`.

대상(서브커맨드 + 이슈 키, 생략 시 현재 브랜치에서 키를 찾아 조회): 이 명령 뒤에 이어서 적은 내용
