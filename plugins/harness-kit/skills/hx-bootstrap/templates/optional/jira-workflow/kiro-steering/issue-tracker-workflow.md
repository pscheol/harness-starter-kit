# 이슈 트래커 작업 (포인터)

원본: `.agents/rules/issue-tracker-workflow.md` — 티켓을 잡거나 상태를 옮기기 전에 연다. 설정은 `.agents/issue-tracker.yml`.

요약:

- **한 세션 = 한 활성 티켓.** 다른 티켓을 만져야 하면 지금 것을 정리하고 넘어간다.
- **Pull gate**: 착수 직전에 티켓을 다시 읽는다 — 상태·담당자·락·요구사항 변경. 하나라도 걸리면 멈추고 알린다.
- **전이는 `transitionIds` 로만.** 표시 이름으로 옮기면 조용히 엉뚱한 상태가 된다.
  `statusIds` 와 `transitionIds` 는 다른 값이고, 전이 ID 는 현재 상태에 따라 달라진다.
- 설정에 `TBD` 가 남아 있으면 **읽기만** 하고 전이하지 않는다.
- **에이전트는 In Review 까지.** Done·Close·담당자 변경·설명 수정은 하지 않는다.
- 코멘트는 착수·리뷰 요청·막힘 셋만. 진행 중계·게이트 출력 전문·코드 덤프는 남기지 않는다.
- 브랜치·커밋·PR 에 티켓 키를 넣는다. 티켓 없는 변경에 규약을 억지로 적용하지 않는다.
- 트래커 호출이 실패해도 코드 작업은 계속하되 **반영 안 됐다는 사실을 알린다.** 부분 성공을 성공으로 보고하지 않는다.
