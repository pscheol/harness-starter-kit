# 이슈 작업 락 (포인터)

원본: `.agents/rules/issue-agent-lock.md` — 티켓에 착수하기 전에 연다. 설정은 `.agents/issue-tracker.yml` 의 `lock` 절.

요약:

- 담당자 필드는 **누가 책임지는가**, 락은 **지금 누가 손대고 있는가**다. 다른 것이므로 대신 쓰지 않는다.
- 획득 순서: 티켓 재조회 → 락 없으면 쓰기 → **쓴 뒤 다시 읽어 자기 것인지 확인**.
  트래커에는 원자적 CAS 가 없어서 다시 읽는 것이 유일한 방어다.
- 긴 작업은 TTL 전에 갱신한다. 갱신하지 않으면 남이 stale 로 보고 가져간다.
- 해제는 **반드시** — 리뷰 요청 전이 · 착수 철회 · 세션 종료. 락을 걸어 둔 채 끝내지 않는다.
- **stale 락을 자동으로 깨지 않는다.** 누가·언제 걸었는지 보고하고 사용자 승인 후에만, 코멘트를 남기고 깬다.
- 락은 쓰기를 막는다. 읽기·분석·질문 답변은 락 없이 해도 된다.
- 락 쓰기가 실패하면 **착수하지 않는다.** 락 없이 진행하는 것이 가장 위험하다.
- 소유자 표기는 사람이 읽고 연락할 수 있는 형태로. 불투명한 값만 남기면 아무도 풀지 못한다.
